# dashboard-sub-kpi Specification

## Purpose
Core KPI 7종을 보조하는 Sub KPI(미언급 프롬프트 수 / 복수 언급 답변 수 / Top 3 노출 비율 /
긍정·부정 키워드 언급 수 / 부정 답변 비율 / 브랜드 사이트 방문 수 / 엔진 간 일관성)의 정의·
산출·지면 배정 규약. 핵심 원칙은 두 가지다 — (1) Sub 를 위해 새 화면을 만들지 않고 이미 그
지표 계열을 다루는 기존 화면의 기존 슬롯에 얹는다, (2) 입력이 없는 지표는 숫자를 지어내지 않고
"측정 대기"로 남긴다.

## Requirements

### Requirement: Sub KPI 는 지표 성격에 맞는 지면에 노출되어야 한다
시스템은 Sub KPI 를 별도 화면을 신설하지 않고 **이미 그 지표 계열을 다루는 기존 화면**에
노출해야 한다(SHALL). 지면 배정은 다음과 같아야 한다(SHALL):

- **답변분석 > 언급** — 미언급 프롬프트 수, 복수 언급 답변 수, Top 3 노출 비율(요약 타일 행),
  긍정 키워드 언급 수, 부정 키워드 언급 수, 부정 답변 비율(감정 분포 패널 하단 행)
- **AI 퍼널 > 전환** — 브랜드 사이트 방문 수(GA4 기반이라 미러 지표와 데이터원이 다름)
- **Core KPI 카드** — 엔진 간 일관성만. 각 Core 의 파생값이므로 그 Core 카드 값 오른쪽에
  배지로 노출한다

Sub KPI 를 위한 새 라우트·탭·독립 섹션을 만들어서는 안 된다(SHALL NOT).

초기 규약(2026-06-18)은 모든 Sub 를 Core 카드 내부 행으로 두었으나, 카드가 값의 근거인
분자/분모 2줄을 상시 노출하게 되면서(2026-07-01) 그 자리가 사라졌다. 2026-07-29 재배치로
드릴다운이 값어치인 지표는 언급 화면으로, Core 파생값인 일관성만 카드에 남겼다.

#### Scenario: 언급 화면에 요약 타일로 노출됨
- **WHEN** 답변분석 > 언급 화면을 렌더하면
- **THEN** 상단 요약 타일 행에 미언급 프롬프트 수·복수 언급 답변 수·Top 3 노출 비율이 함께 표시된다

#### Scenario: 감정 파생 Sub 는 감정 패널에 붙는다
- **WHEN** 감정 분포 패널을 렌더하면
- **THEN** 같은 sentiment 신호에서 나온 긍정·부정 키워드 언급 수와 부정 답변 비율이 그 패널 안에 표시된다

#### Scenario: Sub 는 독립 화면을 만들지 않음
- **WHEN** Sub KPI 를 노출하면
- **THEN** 기존 화면의 기존 슬롯에만 나타나고 새 라우트나 탭을 만들지 않는다

### Requirement: Sub KPI 는 표준·웹사이트·프로젝트 표면에서 동일하게 동작해야 한다
Sub KPI 는 세 표면(표준 / 웹사이트 / 개별 프로젝트)에서 같은 정의·같은 산식으로 노출되어야
한다(SHALL). 표면 간 차이는 모집단(해당 표면의 `answerWhere`)뿐이어야 하며, 각 표면은 그
화면의 본 집계와 **동일한 필터**로 Sub 집계를 호출해야 한다(SHALL).

#### Scenario: 세 표면이 같은 정의를 쓴다
- **WHEN** 표준·웹사이트·프로젝트의 언급 화면을 각각 렌더하면
- **THEN** 세 화면 모두 같은 Sub KPI 항목이 같은 산식으로 표시되고, 값만 각 표면의 모집단을 반영한다

### Requirement: 백필 의존 Sub 는 측정 대기로 표시되어야 한다
값을 산출할 입력(예: scope sentiment backfill)이 아직 없는 Sub 는 숫자를 지어내지 않고 "측정
대기" 상태로 표시해야 한다(SHALL NOT 임의값). 감정 파생 Sub 3종(긍정·부정 키워드 언급 수,
부정 답변 비율)은 sentiment 데이터를 가진 추적 답변이 0이면 측정 대기여야 한다(SHALL).

#### Scenario: sentiment 미도착 시 감정 파생 Sub 는 측정 대기
- **WHEN** sentiment 데이터를 가진 추적-브랜드 답변이 없으면
- **THEN** 감정 분포 패널의 Sub 3종은 0 이 아니라 "측정 대기" 칩을 표시한다

### Requirement: 엔진 간 일관성은 Core 의 엔진별 min ÷ max 로 산출되어야 한다
엔진 간 일관성은 해당 Core 지표의 엔진(`target`)별 값 중 **최소 ÷ 최대 × 100**으로 산출해야
한다(SHALL). 유효 엔진(분모>0)이 2개 미만이면 비교 불가이므로 표시하지 않아야 한다(SHALL NOT
100% 오인 표기). 값이 없는(측정 대기) Core 카드에도 붙이지 않아야 한다(SHALL NOT). 엔진 구분은
신뢰 가능한 `scope_answers.target` 을 사용해야 하며(SHALL), 정제되지 않은 `model_slug` 를
사용해서는 안 된다(SHALL NOT).

일관성의 입력이 되는 엔진별 Core 값은 **그 Core 카드와 같은 정의**로 계산되어야 한다(SHALL).
특히 ④ 우선 노출도의 엔진별 평균순위는 순위 미진입 답변을 제외해야 하며, 미진입을 임의 순위
(예: 100위)로 채워서는 안 된다(SHALL NOT) — 그렇게 하면 평균이 순위가 아니라 노출률의 역수가
되어 일관성이 ① 노출률 일관성을 복제한다(2026-07-29 실측: 61.1% → 95.9%).

#### Scenario: 단일 엔진 슬라이스에서는 일관성 생략
- **WHEN** 필터된 모집단에 유효 엔진이 1개뿐이면
- **THEN** 일관성 배지는 표시되지 않는다(100% 로 표기하지 않는다)

#### Scenario: 두 엔진 이상이면 카드 값 옆에 배지로 표시
- **WHEN** 한 Core 가 2개 이상 엔진에서 값을 가지면
- **THEN** 그 Core 카드의 값 오른쪽에 (엔진 최소값 ÷ 최대값 × 100) 이 배지로 표시된다

#### Scenario: 순위 일관성은 Core ④ 와 같은 모집단을 쓴다
- **WHEN** ④ 우선 노출도의 엔진 간 일관성을 산출하면
- **THEN** 엔진별 평균순위는 순위가 매겨진 답변만으로 계산된다(카드 값과 동일 정의)

### Requirement: Sub KPI 는 정의와 산식을 화면에서 확인할 수 있어야 한다
라벨만으로 산식이 자명하지 않은 Sub KPI 는 정의와 산식을 hover 로 확인할 수 있어야 한다(SHALL).
특히 Top 3 노출 비율은 정수 순위 임계가 아니라 **답변 내 등장 위치의 평균이 3.0 이하**라는 점을
정의문이 직접 밝혀야 한다(SHALL) — 라벨이 "3위 이내"로 오독되기 때문이다.

#### Scenario: Top 3 정의가 평균 기준임을 밝힌다
- **WHEN** Top 3 노출 비율의 정의를 열면
- **THEN** "등장 위치의 평균이 3.0 이하"라는 판정 기준과 분모(당사 브랜드가 등장한 답변)가 함께 표시된다

### Requirement: Sub KPI 읽기는 BFF 경계와 server-derived 필터를 따라야 한다
Sub KPI 데이터도 강제 진입점(`server.ts`)을 거쳐야 한다(SHALL): 세션 인증 → 감사 → (역할→
프로젝트 게이팅) → 집계. 값 필터는 그 화면의 본 집계와 동일한 server-derived 필터
(`answerWhere`)를 재사용해야 한다(SHALL). 클라이언트가 보낸 스코프 파라미터를 신뢰해서는 안
된다(SHALL NOT).

#### Scenario: Sub 도 동일 필터 모집단을 본다
- **WHEN** 동일 차원 필터가 본 집계와 Sub 에 적용되면
- **THEN** 두 집계는 같은 `answerWhere` 규칙으로 동일 모집단을 사용한다

### Requirement: 중복되는 Sub 는 기존 화면/Core 로 흡수하고 신설하지 않는다
기존 화면이나 Core 가 이미 같은 데이터를 제공하는 Sub 는 독립 KPI 로 신설하지 않아야
한다(SHALL NOT). 출처별 구성비는 인용분석(도메인/유형/상세페이지)과 Core ⑤(자사 인용 점유율)에
이미 존재하므로 그쪽 breakdown 으로 흡수해야 한다(SHALL). 프롬프트 주제별 구성비는 측정 결과가
아니라 프롬프트 카탈로그 구성이므로 카탈로그/표준프롬프트 요약으로 다뤄야 한다(SHALL).

#### Scenario: 출처별 구성비는 인용분석으로 흡수
- **WHEN** 출처별 구성비를 노출할 필요가 생기면
- **THEN** 새 KPI 가 아니라 Core ⑤ 또는 인용분석 페이지의 % 구성비 표현으로 제공한다
