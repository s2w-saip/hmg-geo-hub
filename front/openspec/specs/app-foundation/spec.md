## Requirements
### Requirement: 프로젝트 스캐폴드와 도구 설정
프로젝트는 App Router 기반 Next.js 15 + React 19 + TypeScript + Tailwind 4 애플리케이션이어야 한다(SHALL).
합의된 시각화 의존성(cytoscape, cytoscape-fcose, d3, d3-sankey, lucide-react)이 설치되어야 한다.

#### Scenario: 개발 서버가 실행됨
- **WHEN** 개발자가 설치 후 dev 명령을 실행하면
- **THEN** 타입/컴파일 오류 없이 앱이 빌드되고 서빙된다
- **AND** Tailwind 유틸리티 클래스가 스타일로 렌더된다

#### Scenario: 프로덕션 빌드가 성공함
- **WHEN** 프로덕션 빌드 명령이 실행되면
- **THEN** TypeScript 오류 없이 빌드가 완료된다

### Requirement: v1 정보구조 라우트
애플리케이션은 인증 뒤에 v1 IA를 라우트로 노출해야 한다(SHALL): 통합 대시보드, 고객 관심
대시보드, AI 답변 대시보드, 개별 프로젝트 생성, 관리자 콘솔. 추가로 접근 가능한 메인 메뉴가
없는 사용자가 도달할 빈 상태 보조 라우트(`/no-access`)를 제공한다. 모든 라우트는 로케일 접두
경로 안에서 동작하며, 라우트별 접근 가능 역할은 access-control 정책에 의해 결정된다.

#### Scenario: 인증된 사용자가 디폴트 도착 라우트에 도달함
- **WHEN** 인증된 사용자가 로그인을 완료하면
- **THEN** 사용자의 역할이 접근 가능한 라우트 중 첫 번째 라우트가 로케일 접두 경로 안에서 렌더된다

#### Scenario: 5개 메인 라우트가 모두 존재함
- **WHEN** 인증된 사용자가 통합 대시보드 / 고객 관심 / AI 답변 / 개별 프로젝트 / 관리자 콘솔
  라우트로 각각 이동하면
- **THEN** 각 라우트가 로케일 접두 경로 안에서 자체 페이지로 렌더된다(접근 정책으로 차단되지 않는 한)

#### Scenario: 미인증 접근은 리다이렉트됨
- **WHEN** 미인증 방문자가 보호 라우트(통합 대시보드 등)를 요청하면
- **THEN** 로그인 라우트로 리다이렉트된다

#### Scenario: 접근 불가 라우트 요청은 빈 상태 라우트로 리다이렉트
- **WHEN** 인증된 사용자가 자신의 역할에 허용되지 않은 메인 라우트로 이동을 시도하면
- **THEN** `/no-access` 빈 상태 라우트로 리다이렉트된다

### Requirement: 미정 영역의 빈 상태 껍데기
데이터 출처가 미정인 화면은 조작된 UI 대신 빈 상태(empty-state) 자리표시자를 렌더해야 한다(SHALL).
대상은 고객 관심 데이터(구글 키워드, 커뮤니티 VoC)이며, 경쟁사 cross-insight(share-of-voice)는
v1에 나타나지 않아야 한다.

#### Scenario: 미정 데이터 영역이 빈 상태를 보여줌
- **WHEN** 사용자가 고객 관심 데이터 화면을 열면
- **THEN** "데이터 출처 미정"을 알리는 빈 상태 자리표시자가 표시된다
- **AND** 경쟁사 cross-insight 뷰는 존재하지 않는다

### Requirement: 인증 화면과 인증 뒤 레이아웃이 시각 토큰을 따름

로그인 페이지와 인증 뒤 `DashLayout`은 색·타이포·반경·라인 두께·그림자·모션을 시각 토큰을 통해서만 적용해야 한다(SHALL). 하드코딩된 neutral 색이나 시스템 폰트 직접 지정은 토큰 정의 외에서 허용되지 않는다. 인증 뒤 레이아웃은 **상단 헤더(좌측 워드마크 + 우상단 보조: 역할 배지·로케일·로그아웃) + 좌측 사이드바(그룹 라벨로 묶인 RBAC 가시 네비게이션) + 메인 영역**의 3구획 구조를 사용한다. lg 미만 너비에서는 사이드바가 슬라이드인 드로어로 동작한다. 로그인 페이지는 좌측 브랜드 보이스(워드마크 + 헤드라인) + 우측 폼 카드의 두 칼럼(lg 이상) / 스택(모바일) 레이아웃을 유지한다.

#### Scenario: 데스크톱 인증 뒤 레이아웃이 사이드바를 표시

- **WHEN** lg 이상 너비에서 인증된 사용자가 어떤 보호 라우트로 이동하면
- **THEN** 좌측에 사이드바, 상단에 헤더, 우측 메인의 3구획 레이아웃이 렌더되고 사이드바·헤더·메인 모두 시각 토큰에서 도출된 색·타이포·라인을 적용한다

#### Scenario: 모바일 인증 뒤 레이아웃이 슬라이드인 드로어

- **WHEN** lg 미만 너비에서 사용자가 헤더의 메뉴 토글을 누르면
- **THEN** 좌측에서 사이드바가 드로어로 슬라이드인 되고 데스크톱과 동일한 네비게이션 항목이 표시된다

#### Scenario: 헤더가 브랜드 톤을 표현함

- **WHEN** 인증된 사용자가 어떤 보호 라우트로 이동하든
- **THEN** 헤더의 워드마크는 브랜드 토큰 색으로, 상단 라인은 시멘틱 border 토큰으로 렌더된다

#### Scenario: 로그인 페이지가 브랜드 톤을 표현함

- **WHEN** 미인증 사용자가 로그인 페이지에 도달하면
- **THEN** 헤드라인은 `font-head`, 본문은 `font-text` 폰트 토큰을 따르고, 기본 버튼은 시멘틱 primary 토큰, 입력 포커스는 시멘틱 ring 토큰을 적용한다

#### Scenario: 사이드바 항목이 그룹 라벨로 분류됨

- **WHEN** 인증 뒤 사이드바를 렌더하면
- **THEN** 항목은 `General`(통합·고객관심·AI답변·프로젝트)과 `Admin`(관리자 콘솔) 등의 그룹 라벨 아래에 분류돼 표시되고, 각 항목은 i18n 사전(`messages/{ko,en}.json`)의 `nav.*` 키에서 라벨을 가져온다
