# period-comparison-delta

## ADDED Requirements

### Requirement: 기간 비교 창은 최신 노출 회차 앵커일을 끝점으로 삼는다

기간 프리셋(7·14·30·365일)과 그 프리셋에서 파생되는 Δ 는 표면별 **최신 노출 회차
앵커일** `E` 를 끝점으로 써야 한다(SHALL). `E` 는 `summary_cycles` 에서
`cycleViewableSql()`(= `view_anchor_at IS NOT NULL AND view_anchor_at <= now()`)
`AND active_generation_id IS NOT NULL` (웹사이트는 `AND fleet_visible`) 을 만족하는 행의
`max(cycle_anchor_at)` 의 **UTC 일**이어야 한다(SHALL).

창은 다음 수식을 따른다(SHALL):

```
현재 창 cur  = [ E − (N−1) , E ]
직전 창 prev = [ E − (2N−1) , E − N ]
```

두 창은 길이가 같고(각 N일) 겹치지 않으며 맞닿아야 한다(SHALL).
`minDay`(수집 시작일) 클램프는 **현재 창에만** 적용한다(SHALL): 직전 창에 적용하면
길이가 달라진다.

`E` 를 해소할 수 없으면(원장 미적용·DB 오류·그 표면에 노출 회차 0) 프리셋은 **오늘 기준
트레일링으로 폴백**해야 한다(SHALL: 종전 동작).

#### Scenario: 끝점이 오늘이 아니라 최신 노출 회차일이다
- **GIVEN** 글로벌 표면의 최신 노출 회차 앵커가 `2026-09-13` 이고 오늘이 `2026-09-18` 일 때
- **WHEN** "주간(7일)" 프리셋을 고르면
- **THEN** 창은 `2026-09-07 ~ 2026-09-13` 이고, `2026-09-12 ~ 2026-09-18` 이 **아니다**

#### Scenario: 미러 술어로 끝점을 잡지 않는다
- **GIVEN** 웹사이트 표면에서 원장 술어의 최신 앵커가 `2026-09-11`,
  미러 시간 규칙(`COALESCE(view_anchor_at, cycle_anchor_at + 1 day) <= now()`)의 최신 앵커가
  `2026-09-14` 일 때
- **THEN** `E = 2026-09-11` 이다 (두 술어가 3일 갈리는 것이 라이브 실측이고, 큰 쪽을 쓰면
  현재 창 끝에 화면에 값이 없는 꼬리가 생긴다)

#### Scenario: 노출 회차가 없는 표면은 폴백한다
- **GIVEN** `summary_cycles` surface='project' 에 노출 가능한 회차가 0건일 때
- **WHEN** 프로젝트 화면에서 프리셋을 고르면
- **THEN** 창은 오늘 기준 트레일링이고 기간 비교 Δ 는 `unsupported` 로 억제된다

### Requirement: 카드 값의 창과 Δ 현재 창은 같은 날짜쌍에서 파생된다

같은 화면에서 표시되는 지표 값의 집계 창과, 그 옆 Δ 의 "현재 창" 은 **같은
`(dateFrom, dateTo)`** 에서 나와야 한다(SHALL). 값의 창만 오늘 기준이고 Δ 의 창만 앵커
기준인 상태는 금지한다(SHALL NOT).

#### Scenario: 값과 Δ 가 서로를 설명한다
- **GIVEN** 글로벌·무필터, `E = 2026-09-13`, 7일 프리셋
- **WHEN** AI 노출률 카드와 그 Δ 를 함께 렌더하면
- **THEN** 카드 값은 `74.57%`(= 56,033/75,138, 회차 09-08·09-13 합산)이고
  Δ 는 `74.5735 − 64.7751 = +9.80 %p` 다: 카드에 찍힌 수가 Δ 계산의 피연산자와 같다
- **AND** 오늘 기준 트레일링 창의 값 `76.27%`(28,656/37,570, 회차 09-13 단독)는
  이 화면 어디에도 나타나지 않는다

### Requirement: Δ 는 분자합·분모합으로 계산하고 지표 유형별 단위를 쓴다

| 유형 | 산식 | 단위 |
| --- | --- | --- |
| 비율 | `(Σ분자_cur / Σ분모_cur) − (Σ분자_prev / Σ분모_prev)` | `%p` |
| 건수형 | `(Σ건수 / Σmonitored)` 끼리의 증감률. `prev == 0` 이면 `null` | `%` |
| 순위형 | `(Σrank_sum/Σranked_answers)` 의 절대 차 | `rank` |

회차별 비율을 평균내는 산식은 금지한다(SHALL NOT). 건수형 지표를 **회차 수**로 나누는
산식도 금지한다(SHALL NOT: 회차 크기가 불균등하다: 웹사이트 한 앵커일의 참여 프로젝트가
1~95개로 실측된다).

건수형 지표 목록: 답변당 언급 수 · 답변당 인용 수 · 웹사이트 자사 URL 수 · 타겟 URL 수.

**범위 제외**: ⑤ AI 인용 점유율은 이번 범위에서 제외한다: 집계층 `own_citations`(5.30%)와
화면 정본 도메인 표(10.39%)가 다르다.

#### Scenario: 비율의 평균이 아니다 (골든 반례)
- **GIVEN** 14일 창의 직전 창 `2026-08-17 ~ 2026-08-30` 의 회차 셋 (글로벌·무필터 실측):
  `08-18` 6,856/9,012 = 76.0764 % · `08-19` 760/874 = 86.9565 % · `08-25` 6,618/9,650 = 68.5803 %
- **WHEN** 창 값을 계산하면
- **THEN** `(6,856+760+6,618) / (9,012+874+9,650) = 14,234/19,536 = 72.8604 %` 다
- **AND** 회차별 비율의 산술평균은 `77.2044 %` 로 **4.34 %p 다르다**: 그 뮤테이션은
  테스트에서 죽어야 한다

#### Scenario: 건수형은 답변 1건당으로 정규화한다
- **WHEN** 직전 창의 회차 수가 현재 창의 1/2.6 이고 회차 크기도 불균등할 때
- **THEN** 건수형 Δ 는 회차 수·회차 크기 변동에 불변이다 (분모가 `monitored` 이므로)

### Requirement: 억제 사유는 5종이고 우선순위가 고정돼 있다

```
unsupported > no_prev_window > no_data > missing_share > start_window
```

억제되면 칩은 **U+2015 (`―`)** 를 그리고(SHALL), 캡션은 사유별 완결 문장 하나를
ko/en 으로 표시해야 한다(SHALL). **U+2014 em dash 를 쓰지 않는다**(SHALL NOT).

#### Scenario: 억제 글리프는 U+2015 다
- **WHEN** 억제 상태의 Δ 칩을 렌더하면
- **THEN** 출력 문자열에 U+2015 가 있고 U+2014 는 **0건**이다

#### Scenario: 우선순위: unsupported 가 이긴다
- **GIVEN** `depth3` 필터가 걸려 집계층을 못 타고, 동시에 직전 창의 누락 비중이 45% 일 때
- **THEN** 사유는 `unsupported` 다 (누락 비중은 애초에 판정할 입력이 없다)

---

### Requirement: 누락 30% 억제는 30일·1년 창에만 적용한다

```
missingShare = Σexpected_units(창 안 미발행 회차) / Σexpected_units(창 안 전체 회차)
억제 ⇔ missingShare >= 0.30   (경계 포함)
```

분자·분모는 **회차 원장 기준**이며 차원 필터의 영향을 받지 않아야 한다(SHALL).
7일·14일 창에는 이 임계를 적용하지 않는다(SHALL NOT): 그 창들은 한쪽 창의 **발행 회차
0**(= `no_prev_window` / `no_data`)일 때만 억제한다.

#### Scenario: 30일 창: 억제 (골든)
- **GIVEN** 글로벌·무필터, `E = 2026-09-13`, 30일 프리셋
- **WHEN** 직전 창 `2026-07-16 ~ 2026-08-14` 의 누락 비중을 계산하면
- **THEN** `14,404 / 35,264 = 40.846 %` 이고 `>= 30 %` 이므로 `missing_share` 로 억제된다
- **AND** 억제를 끄면 Δ 는 `71.5367 − 79.2608 = −7.72 %p` 다 (회귀 대조값)

#### Scenario: 14일 창: 같은 누락이어도 억제하지 않는다
- **GIVEN** 14일 창의 직전 창에 미발행 회차가 있어 누락 비중이 30% 를 넘어도
- **THEN** `missing_share` 로 억제하지 않는다. 발행 회차가 **0** 일 때만 억제한다

#### Scenario: 정확히 30% 는 억제다
- **WHEN** 30일 창의 누락 비중이 정확히 `0.30` 이면
- **THEN** 억제한다 (경계 포함). `0.2999` 는 표시한다

---

### Requirement: 1년 프리셋은 직전 1년 데이터가 없으면 전용 문구로 억제한다

#### Scenario: 연간 비교 불가
- **GIVEN** 글로벌 첫 회차 앵커가 `2026-06-07`, 웹사이트가 `2026-07-02` 일 때
- **WHEN** 1년 프리셋을 고르면
- **THEN** 칩은 `―` 이고 캡션은 "비교할 직전 1년 데이터가 없습니다" 다
  (`periodCompare.reason.noPrevYear`)
- **AND** 데이터가 쌓여 직전 1년 창에 발행 회차가 생기면 **코드 변경 없이** 값이 표시된다

### Requirement: `start_window` 는 창 길이에 비례한 유예를 쓴다

```
F = 그 필터 범위의 첫 발행 회차 앵커일
grace(N) = ceil(N / 4)
start_window ⇔ F > prev.lo + grace(N)
```

#### Scenario: 창 시작 직후 인입은 온전한 창이다
- **GIVEN** 30일 창의 직전 창이 `2026-07-16` 에 시작하고 첫 발행 회차가 `2026-07-22` 일 때
- **THEN** `grace(30) = 8`, `07-22 <= 07-24` 이므로 `start_window` 가 **아니다**

#### Scenario: 창 중반 인입은 시작 구간이다
- **GIVEN** 같은 창에서 첫 발행 회차가 `2026-07-30` 일 때
- **THEN** `07-30 > 07-24` 이므로 `start_window` 로 억제한다

### Requirement: 숨긴 회차는 계열별로 다르게 센다

`hidden_reason IS NOT NULL AND hidden_scope = 'citations'` 인 회차는 **언급 계열의
분자·분모에는 남기고**, 인용 계열에서는 제외해야 한다(SHALL):
`excludeHiddenCycleRuns(…, family)` 규약과 같다. 누락 비중의 분모에도 남긴다(발행된 회차다).

#### Scenario: 숨김 회차 계열 규약 (골든)
- **GIVEN** 글로벌 14일 창, `E = 2026-09-13`, 직전 창 `2026-08-17 ~ 2026-08-30`,
  그 안의 `2026-08-25` 회차가 `hidden_scope='citations'` 일 때
- **WHEN** AI 노출률(언급 계열)의 직전 창 값을 계산하면
- **THEN** `14,234 / 19,536 = 72.8604 %` 다 (08-25 포함)
- **AND** 08-25 를 제외하면 `7,616 / 9,886 = 77.0382 %` 가 되어 Δ 가 `−1.55` → `−5.73 %p` 로
  **4.18 %p 틀어진다**: 이 대조가 회귀 테스트다
- **AND** 답변당 인용 수(인용 계열)에서는 08-25 를 제외해 현재 창 `5.3553` ·
  직전 창 `14.8635` 를 쓴다

### Requirement: 두 창은 한 문장으로 읽는다

Δ 를 위해 집계를 두 번 돌리지 않아야 한다(SHALL NOT). 회차 축 사실표의 회차 집합을
N일에서 **2N일로 넓혀** 한 번 읽고, 두 창으로 가르는 것은 애플리케이션 계층에서 한다(SHALL).

집계층으로 표현할 수 없는 필터 조합(`depth2` · `depth3` · admin 임의 다중 브랜드:
`planTrendRead` 가 `ok:false` 를 내는 경우)에서는 Δ 를 `unsupported` 로 억제해야 한다(SHALL).
미러에서 두 창을 각각 집계하는 경로를 만들지 않는다(SHALL NOT).

#### Scenario: 창을 넓혀도 문장 수가 그대로다
- **WHEN** 30일 프리셋의 Δ 를 계산하면
- **THEN** 발행되는 SQL 문장 수가 30일 창만 읽을 때와 같다 (회차 집합 술어의 범위만 2배)

#### Scenario: 예산 (EXPLAIN ANALYZE 실측)
- **WHEN** 60일(= 두 개의 30일 창) 회차 축 읽기를 프로덕션 규모에서 실행하면
- **THEN** 글로벌(root, 무필터) `Execution Time <= 150 ms`(실측 94.256 ms · shared hit 6,022),
  웹사이트 함대(95 프로젝트) `<= 50 ms`(실측 11.009 ms · shared hit 2,838)
- **AND** 측정은 **최소 두 워크스페이스**에서 한다 (한 곳만 재면 작은 쪽 타임아웃을 놓친다)

### Requirement: 기간 미선택 기본 화면은 값이 바뀌지 않는다

기간 필터가 비어 있으면 Δ 의 산식을 바꾸지 않아야 한다(SHALL: "직전 회차 대비" 유지).
이 상태에서 이 변경 전후의 모든 Δ 값과 카드 값은 동일해야 한다(SHALL).

#### Scenario: 무필터 회귀
- **WHEN** 기간을 지정하지 않고 12개 Δ 지면을 렌더하면
- **THEN** 이 변경 도입 전과 값이 **한 자리도 다르지 않다** (사전 스냅샷 대조)

### Requirement: 캐시는 끝점 변화를 따라간다

기간 비교 셀의 TTL 은 600초 이하여야 하고(SHALL), 캐시 키에 **해소된 `E`** 를 포함해야
한다(SHALL). 무효화 태그는 기존 `SUMMARY_TAG` 를 단다.

#### Scenario: 회차 공개 시점에 키가 갈린다
- **GIVEN** 새 회차의 `view_anchor_at` 이 방금 지나 `E` 가 `09-13` → `09-20` 으로 바뀌었을 때
- **WHEN** 같은 필터로 다시 요청하면
- **THEN** 캐시 키가 달라 새 창으로 계산된다 (2시간 TTL 을 기다리지 않는다)

### Requirement: 롤아웃은 단일 스위치이며 기본 off 다

설정 `period_compare`(기본 off)가 ① 프리셋 끝점 ② 창 대 창 Δ 산식 **둘 다**를 켜야
한다(SHALL). 둘을 독립적으로 켤 수 있게 만들지 않는다(SHALL NOT): 값의 창과 Δ 의 창이
갈리기 때문이다.

#### Scenario: off 에서 왕복·페이로드 증가 0
- **WHEN** `period_compare` 가 off 인 상태로 대시보드를 렌더하면
- **THEN** DB 왕복 수와 페이로드가 이 변경 도입 전과 같다

### Requirement: 달력 월 프리셋은 확정 MoM 정책을 따른다 (v2, Q2=b)

"이번 달"·"지난달" 프리셋을 제공해야 한다(SHALL). 월 소속은
`cycle_anchor_at AT TIME ZONE 'Asia/Seoul'` 의 연·월이다(SHALL).

| 프리셋 | 범위 | 비교 대상 |
| --- | --- | --- |
| 이번 달 | KST 이번 달 1일 ~ `E` | 지난달 **전체** |
| 지난달 | KST 지난달 1일 ~ 말일 | 전전월 **전체** |

이 두 프리셋에는 창 비교의 `start_window`(`grace(N)`) 대신 MoM 의 `start_month`
(전전월 데이터 유무 2단 판정 + 신규 인입 첫째 주 7일)를 적용해야 한다(SHALL).
두 규칙은 배타적이며 한 프리셋에 둘 다 걸리지 않아야 한다(SHALL NOT).

기존 "월간(최근 30일)" 프리셋은 유지하고 **창 비교**를 적용한다(SHALL). 그 창의
누락 30% 규칙도 유지한다(SHALL).

달력 월과 창 비교는 **같은 읽기 함수**(`readComparePeriods`)를 써야 한다(SHALL):
달력 월은 `windows` 목록의 원소 셋(`before`·`prev`·`cur`)이다. 월 전용 집계 SQL 을
따로 두지 않는다(SHALL NOT).

#### Scenario: 월초에 이번 달 회차가 아직 없다
- **GIVEN** `E` 가 아직 지난달에 머물러 이번 달 발행 회차가 0일 때
- **WHEN** "이번 달" 프리셋을 고르면
- **THEN** `no_data`(현재 구간) 억제 + 해당 캡션이 나온다. 프리셋 자체는 숨기지 않는다

#### Scenario: 이식 동치 증명
- **WHEN** `feat/mom-delta` 의 `summary-mom-aggregates.int.test.ts` 가 고정한
  2026-07 / 08 / 09 골든을 `readComparePeriods` 위에서 재계산하면
- **THEN** 같은 값이 나온다 (월 전용 집계를 버려도 값이 보존된다는 증명)

---

### Requirement: 새 산식은 적용일 이후 구간에만 적용한다 (v2, Q6=b)

```
적용 ⇔ cur.hi >= PERIOD_COMPARE_EPOCH
```

`PERIOD_COMPARE_EPOCH` 는 상수 **1곳**(`lib/kpi/period-compare.ts`)이며,
`summary_settings.period_compare_epoch` 가 있으면 그것이 이긴다(SHALL).
판정 분기는 게이트웨이 진입부 **1곳**에만 두어야 한다(SHALL): 적용 대상이 아니면
`null` 을 돌려주고 화면은 종전 Δ 경로를 그대로 쓴다. 분기를 지면 코드에 넣지
않는다(SHALL NOT).

#### Scenario: 기발행 리포트가 재현된다
- **WHEN** 적용일 이전 구간(`cur.hi < EPOCH`)을 캘린더로 직접 지정해 조회하면
- **THEN** 종전 Δ 가 그대로 나오고, 억제 칩("―")은 나타나지 않는다

#### Scenario: 분기가 1곳이다
- **WHEN** 리포에서 `PERIOD_COMPARE_EPOCH` 참조를 전수 grep 하면
- **THEN** 상수 정의 1곳 + 게이트웨이 판정 1곳 + 테스트를 제외하고 **0건**이다
