## Context

대시보드 시계열의 선결 과제는 "측정주기가 일정하지 않다". 미러 `scope_answers.measured_at`
실측(2026-06-18)으로 버킷 폭을 데이터 기반으로 결정했다.

## 측정 cadence 실측 (근거)

| 단위 | 결과 |
|---|---|
| 주별 버킷 | 3개 — 06-01주(측정 1일, 부분배치) · 06-08주(측정 5일) · 06-15주(측정 3일) |
| 일별 버킷 | 9개 — 06-07(1배치) → 06-08~09 **공백** → 06-10~17 |
| 셀당 커버리지 | 평균 4.17일 / 9일 (max 8, min 1) |
| (prompt, 하루) | 대부분 10+회 과측정 |

→ raw 이벤트 축 ❌(간격 불규칙), run 회차 축 ❌(fragment), **캘린더 버킷 ✅**.

## Decisions

### D1. 버킷 폭 = 일 저장 / 주 표시
- 저장·집계 grain 은 일(인트라데이 과측정 흡수). 표시 기본은 주 — 06-08~09 공백과 체제 변화,
  셀 patchiness 를 흡수하고 GA4 일단위와 정렬 가능.
- 사용자가 주↔일 전환(`?bucket=week|day`). 일 단위는 충분히 조밀한 슬라이스의 drill-down 용.
- **대안 기각**: 시간/run 버킷(노이즈), 회차 인덱스 축(캘린더 비교 불가), 롤링 윈도우(후행·설명난해).

### D2. 보간 절대 금지 + coverage 노출
- 측정 없는 버킷은 행 자체를 만들지 않는다 → 차트 `connectNulls={false}` 로 선이 끊긴다.
- 각 버킷에 측정일수·답변수·마지막측정을 실어 "N일 측정" 배지로 노출. ~46% 커버리지가
  매끄러운 선으로 위장되는 것이 진짜 위험이라는 판단.

### D3. KPI 산식은 스냅샷과 단일 출처
- 버킷별 raw 집계만 repo 에서 만들고, 최종 KPI 산식(visibility/SOV/citationShare 의 pct 등)은
  스냅샷과 동일하게 view-model(`live.ts`)에서 적용. 카드 값과 추이 라인이 같은 산식.

### D4. 단위 혼재 → 분리축
- 퍼센트 KPI 4종(노출/점유율/우호도/인용점유율)은 좌축(%), 평균순위는 우축(rank).
- 순위는 자연 스케일(작을수록 아래). "낮을수록 좋음"의 방향성은 KPI 카드 변화량 색(goodness)으로 전달 —
  축 reverse 는 그 자체로 혼란이라 채택하지 않음.

### D5. 변화량 = 직전 측정 버킷 대비
- delta = (값 있는) 마지막 버킷 − 직전 버킷. null 버킷은 건너뜀, 값 2개 미만이면 delta=null(칩 숨김).
- 반올림 후 ±0.05 미만은 flat(미세 노이즈로 방향 칩이 흔들리지 않게).
- 측정 기준(주/일)과 동일 버킷을 쓰므로 사용자가 기준을 바꾸면 카드 델타도 그 기준으로 재계산.
- **알려진 한계**: 가장 최근 버킷이 진행 중(부분 측정)일 수 있어 델타가 과/소대될 수 있음 →
  coverage 배지로 보완. 부분 버킷 제외 옵션은 후속 open question.

### D6. BFF 경계 유지
- 시계열도 `fetchStandardTrend`(enforce→audit→`assertProjectInScope`→캐시)만 진입점.
  동일 `answerWhere(filters)` 재사용으로 server-derived filter(#2) 일관.
