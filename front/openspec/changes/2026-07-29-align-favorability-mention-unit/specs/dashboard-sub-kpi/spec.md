# dashboard-sub-kpi Specification (delta)

## MODIFIED Requirements

### Requirement: Sub KPI 는 지표 성격에 맞는 지면에 노출되어야 한다
시스템은 Sub KPI 를 별도 화면을 신설하지 않고 **이미 그 지표 계열을 다루는 기존 화면**에
노출해야 한다(SHALL). 지면 배정은 다음과 같아야 한다(SHALL):

- **답변분석 > 언급** — 미언급 프롬프트 수, 복수 언급 답변 수, Top 3 노출 비율(요약 타일 행),
  긍정 키워드 언급 수, 부정 키워드 언급 수, **부정 언급 비율**(감정 분포 패널 하단 행)
- **AI 퍼널 > 전환** — 브랜드 사이트 방문 수(GA4 기반이라 미러 지표와 데이터원이 다름)
- **Core KPI 카드** — 엔진 간 일관성만. 각 Core 의 파생값이므로 그 Core 카드 값 오른쪽에
  배지로 노출한다

Sub KPI 를 위한 새 라우트·탭·독립 섹션을 만들어서는 안 된다(SHALL NOT).

초기 규약(2026-06-18)은 모든 Sub 를 Core 카드 내부 행으로 두었으나, 카드가 값의 근거인
분자/분모 2줄을 상시 노출하게 되면서(2026-07-01) 그 자리가 사라졌다. 2026-07-29 재배치로
드릴다운이 값어치인 지표는 언급 화면으로, Core 파생값인 일관성만 카드에 남겼다. 구 라벨
"부정 답변 비율"은 우호도의 언급 단위 정렬(2026-07-29 D1)과 함께 "부정 언급 비율"로
개명됐다 — 산식이 언급 단위인데 라벨이 답변 단위를 주장하면 안 되기 때문이다.

#### Scenario: 언급 화면에 요약 타일로 노출됨
- **WHEN** 답변분석 > 언급 화면을 렌더하면
- **THEN** 상단 요약 타일 행에 미언급 프롬프트 수·복수 언급 답변 수·Top 3 노출 비율이 함께 표시된다

#### Scenario: 감정 파생 Sub 는 감정 패널에 붙는다
- **WHEN** 감정 분포 패널을 렌더하면
- **THEN** 같은 sentiment 신호에서 나온 긍정·부정 키워드 언급 수와 부정 언급 비율이 그 패널 안에 표시된다

#### Scenario: Sub 는 독립 화면을 만들지 않음
- **WHEN** Sub KPI 를 노출하면
- **THEN** 기존 화면의 기존 슬롯에만 나타나고 새 라우트나 탭을 만들지 않는다

### Requirement: 백필 의존 Sub 는 측정 대기로 표시되어야 한다
값을 산출할 입력(예: scope sentiment 채점)이 아직 없는 Sub 는 숫자를 지어내지 않고 "측정
대기" 상태로 표시해야 한다(SHALL NOT 임의값). 감정 파생 Sub 3종(긍정·부정 키워드 언급 수,
부정 언급 비율)은 **언급 단위**로 산출해야 하며(SHALL — kpi-favorability 의 산식·모집단과
동일: 분모 = tracked 멘션 sentiment 신호 합 P+NE+NG+MX, 부정 언급 비율의 분자 = NG), 그 신호
합이 0이면 측정 대기여야 한다(SHALL). 긍정·부정 키워드 언급 수는 종전과 같이 신호 합
(Σpositive, Σnegative)이며 — 이는 언급 단위 우호도의 분자·부정 분자와 동일 값이다.
답변 단위 우세(dominant) 분류를 부정 언급 비율에 사용해서는 안 된다(SHALL NOT).

#### Scenario: sentiment 미도착 시 감정 파생 Sub 는 측정 대기
- **WHEN** sentiment 신호를 가진 tracked 멘션이 없으면
- **THEN** 감정 분포 패널의 Sub 3종은 0 이 아니라 "측정 대기" 칩을 표시한다

#### Scenario: 부정 언급 비율은 우호도의 반대편 세그먼트
- **WHEN** 동일 모집단에서 부정 언급 비율과 우호도를 계산하면
- **THEN** 두 지표는 같은 분모(신호 합)를 쓰고, 분자만 각각 NG 와 P 다

### Requirement: 엔진 간 일관성은 Core 의 엔진별 min ÷ max 로 산출되어야 한다
엔진 간 일관성은 해당 Core 지표의 엔진(`target`)별 값 중 **최소 ÷ 최대 × 100**으로 산출해야
한다(SHALL). 유효 엔진(분모>0)이 2개 미만이면 비교 불가이므로 표시하지 않아야 한다(SHALL NOT
100% 오인 표기). 값이 없는(측정 대기) Core 카드에도 붙이지 않아야 한다(SHALL NOT). 엔진 구분은
신뢰 가능한 `scope_answers.target` 을 사용해야 하며(SHALL), 정제되지 않은 `model_slug` 를
사용해서는 안 된다(SHALL NOT).

일관성의 입력이 되는 엔진별 Core 값은 **그 Core 카드와 같은 정의**로 계산되어야 한다(SHALL).
특히 ④ 우선 노출도의 엔진별 평균순위는 순위 미진입 답변을 제외해야 하며, 미진입을 임의 순위
(예: 100위)로 채워서는 안 된다(SHALL NOT) — 그렇게 하면 평균이 순위가 아니라 노출률의 역수가
되어 일관성이 ① 노출률 일관성을 복제한다(2026-07-29 실측: 61.1% → 95.9%). 마찬가지로 ③
우호도의 엔진별 값은 그 엔진 모집단의 **언급 단위 긍정률**(kpi-favorability 의 Core ③ 동일
정의)이어야 하며(SHALL), 답변 단위 우세 분류를 사용해서는 안 된다(SHALL NOT).

#### Scenario: 단일 엔진 슬라이스에서는 일관성 생략
- **WHEN** 필터된 모집단에 유효 엔진이 1개뿐이면
- **THEN** 일관성 배지는 표시되지 않는다(100% 로 표기하지 않는다)

#### Scenario: 두 엔진 이상이면 카드 값 옆에 배지로 표시
- **WHEN** 한 Core 가 2개 이상 엔진에서 값을 가지면
- **THEN** 그 Core 카드의 값 오른쪽에 (엔진 최소값 ÷ 최대값 × 100) 이 배지로 표시된다

#### Scenario: 순위 일관성은 Core ④ 와 같은 모집단을 쓴다
- **WHEN** ④ 우선 노출도의 엔진 간 일관성을 산출하면
- **THEN** 엔진별 평균순위는 순위가 매겨진 답변만으로 계산된다(카드 값과 동일 정의)

#### Scenario: 우호도 일관성은 Core ③ 과 같은 단위를 쓴다
- **WHEN** ③ 우호도의 엔진 간 일관성을 산출하면
- **THEN** 엔진별 값은 언급 단위 긍정률(카드 값과 동일 정의)로 계산된다
