## ADDED Requirements

### Requirement: 세션 기반 인증
애플리케이션은 자체 로그인으로 사용자를 인증하고 서버단 세션을 유지해야 한다(SHALL). scope
workspace key는 최종 사용자 인증에 사용되지 않는다.

#### Scenario: 로그인이 세션을 생성함
- **WHEN** 사용자가 유효한 자격 증명으로 로그인하면
- **THEN** 서버단 세션이 생성되고 사용자가 인증된 라우트에 도달할 수 있다

#### Scenario: 세션 없으면 보호 접근 차단
- **WHEN** 유효한 세션 없는 요청이 보호 라우트나 scope API handler에 도달하면
- **THEN** 접근이 거부된다

### Requirement: 데이터 범위 계층을 가진 역할 모델
시스템은 각 사용자에게 역할(HQ / 권역 / 국가 / 관리자)을 부여해야 하며(SHALL), 이 역할은
브랜드 > 권역 > 국가 > 차종 계층을 따르는 허용 데이터 범위로 매핑되고, 관리자에게는 추가로
관리자 콘솔이 부여된다.

#### Scenario: 역할이 허용 범위로 매핑됨
- **WHEN** 국가 역할 사용자가 로드되면
- **THEN** 허용 범위가 해당 국가(및 하위)로 제한된다

### Requirement: 서버단 범위 강제 필터
hmg-geo 서버는 모든 scope 호출에서 인증 사용자의 역할로 도출한 권역/국가 필터를 서버단에 강제 주입해야 한다(SHALL).
클라가 보낸 location 파라미터는 무시하며, 각 scope 호출에 대해 사용자별 attribution을 기록해야 한다.

#### Scenario: 클라가 보낸 location이 무시됨
- **WHEN** 국가 사용자가 허용 범위 밖의 location 파라미터를 담아 요청하면
- **THEN** 서버는 클라 값을 버리고 역할에서 도출한 필터를 적용한다
- **AND** 응답에는 사용자의 허용 범위 내 데이터만 포함된다

#### Scenario: 사용자별 감사 attribution
- **WHEN** BFF를 통해 scope 호출이 일어나면
- **THEN** 서버는 어떤 인증 사용자가 시작했는지 로그에 남긴다
