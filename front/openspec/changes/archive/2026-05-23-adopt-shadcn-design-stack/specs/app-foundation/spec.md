## ADDED Requirements

### Requirement: 인증 화면과 인증 뒤 레이아웃이 시각 토큰을 따름

로그인 페이지와 인증 뒤 `DashLayout`은 색·타이포·반경·라인 두께·그림자·모션을 시각 토큰을 통해서만 적용해야 한다(SHALL). 하드코딩된 neutral 색이나 시스템 폰트 직접 지정은 토큰 정의 외에서 허용되지 않는다. 인증 뒤 레이아웃은 **상단 헤더(좌측 워드마크 + 우상단 보조: 역할 배지·로케일·로그아웃) + 좌측 사이드바(그룹 라벨로 묶인 RBAC 가시 네비게이션) + 메인 영역**의 3구획 구조를 사용한다. lg 미만 너비에서는 사이드바가 슬라이드인 드로어로 동작한다. 로그인 페이지는 좌측 브랜드 보이스(워드마크 + 헤드라인) + 우측 폼 카드의 두 칼럼(lg 이상) / 스택(모바일) 레이아웃을 유지한다.

#### Scenario: 데스크톱 인증 뒤 레이아웃이 사이드바를 표시

- **WHEN** lg 이상 너비에서 인증된 사용자가 어떤 보호 라우트로 이동하면
- **THEN** 좌측에 사이드바, 상단에 헤더, 우측 메인의 3구획 레이아웃이 렌더되고 사이드바·헤더·메인 모두 시각 토큰에서 도출된 색·타이포·라인을 적용한다

#### Scenario: 모바일 인증 뒤 레이아웃이 슬라이드인 드로어

- **WHEN** lg 미만 너비에서 사용자가 헤더의 메뉴 토글을 누르면
- **THEN** 좌측에서 사이드바가 드로어로 슬라이드인 되고 데스크톱과 동일한 네비게이션 항목이 표시된다

#### Scenario: 헤더가 브랜드 톤을 표현함

- **WHEN** 인증된 사용자가 어떤 보호 라우트로 이동하든
- **THEN** 헤더의 워드마크는 브랜드 토큰 색으로, 상단 라인은 시멘틱 border 토큰으로 렌더된다

#### Scenario: 로그인 페이지가 브랜드 톤을 표현함

- **WHEN** 미인증 사용자가 로그인 페이지에 도달하면
- **THEN** 헤드라인은 `font-head`, 본문은 `font-text` 폰트 토큰을 따르고, 기본 버튼은 시멘틱 primary 토큰, 입력 포커스는 시멘틱 ring 토큰을 적용한다

#### Scenario: 사이드바 항목이 그룹 라벨로 분류됨

- **WHEN** 인증 뒤 사이드바를 렌더하면
- **THEN** 항목은 `General`(통합·고객관심·AI답변·프로젝트)과 `Admin`(관리자 콘솔) 등의 그룹 라벨 아래에 분류돼 표시되고, 각 항목은 i18n 사전(`messages/{ko,en}.json`)의 `nav.*` 키에서 라벨을 가져온다

## REMOVED Requirements

### Requirement: 인증 화면과 인증 뒤 헤더가 시각 토큰을 따름

**Reason**: 좌측 사이드바 패턴으로 레이아웃이 전환되며, 가로 nav를 포함하던 헤더-중심 요구사항이 더 이상 유효하지 않다. 헤더는 워드마크 + 우상단 보조만 담는 가벼운 구조가 되고, 네비게이션 책임은 사이드바로 이동했다.

**Migration**: 위 `ADDED Requirements`의 "인증 화면과 인증 뒤 레이아웃이 시각 토큰을 따름" 요구사항이 새 3구획 레이아웃(상단 헤더 + 좌측 사이드바 + 메인) 안에서 헤더 시멘틱(워드마크·우상단 보조)과 사이드바 시멘틱(그룹 nav)을 함께 정의하므로, 기존 헤더 요구사항의 시나리오(브랜드 톤 표현, 로그인 폼 톤 등)는 새 요구사항의 시나리오로 모두 흡수된다.
