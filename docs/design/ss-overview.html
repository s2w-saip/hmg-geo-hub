이 문서의 쓰임 — Overview 에서 조건 3(변화의 이유)과 4(근거까지)를 판정하는 기준표입니다. 2장 · 3장의 위치 목록이 검증 스크립트의 입력이 되고, 4장 · 5장이 목업과 구현의 명세입니다. 조건 5(다음 행동)는 ‘이번 회차 요약’이 있는 화면의 조건이라 Overview 에는 해당하지 않습니다(다음 화면 Mention 에서 처음 다룹니다).

1. 정한 것(합격 기준 문서 1장 5–9)

  • 데이터는 기존 경로(legacy: Next.js 가 미러 · 요약 사실표를 직접 읽음). 새 백엔드는 범위 밖.
  • 증감 기준 = 직전 회차. 분해는 회차 대 회차만, 기간 비교 칩은 분해하지 않는다. 화면 숫자는 그대로 둔다.
  • 이전 회차는 ‘변화의 이유’ 서랍 위 회차별 증감 이력 띠로 본다. 회차를 누르면 그 회차와 그 직전 회차 사이의 분해로 바뀌고, 근거 목록도 그 회차를 따른다.
  • 격차(당사 − 경쟁사)는 당사 | 경쟁사 답변 목록을 열면 통과. ‘비교 브랜드 N개 중 M위’ 같은 순위 문구는 조건 4 대상 아님.
  • 페이지 안 스크롤 이동 없음 — 모든 분해 · 목록은 서랍으로 연다.

2. 증감 위치 목록(조건 3)

합격선: 아래 ‘대상’ 위치에서 1클릭으로 엔진 · 국가 · 프롬프트별 기여가 열리고, 기여의 합이 그 위치의 증감과 같다(±0.1pp, 순위는 ±0.1번째).

3. 숫자 위치 목록(조건 4)

합격선: 아래 ‘대상’ 위치마다 2클릭 안에 그 숫자를 만든 답변 원문 목록이 열린다. 클릭 수는 숫자를 누르는 것부터 셉니다.

4. 서랍 명세

두 서랍은 같은 오른쪽 시트(RnDrawer, 폭 720px로 넓힘) 하나 안의 두 화면입니다. ‘변화의 이유 → 근거’는 서랍을 새로 쌓지 않고 같은 시트에서 넘어가며, 머리 왼쪽 ‘‹ 변화의 이유’로 돌아옵니다. Esc · 바깥 누름 = 닫기, 초점은 연 숫자로 돌아갑니다.

4-1. 변화의 이유

  1. 머리 — 제목 ‘변화의 이유’, 부제 ‘{지표} · {브랜드} · 직전 회차 대비’.
  2. 회차별 증감 이력 띠 — 최근 회차들의 ‘직전 대비 증감’을 날짜와 함께 작은 막대(0 기준 위 · 아래)로 나열. 최대 12칸(추이 자리 13개 = 증감 12개), 오래된 것 → 최신. 기본 선택 = 최신 칸 = 화면의 증감. 칸을 누르면 아래 전체가 그 회차로 바뀐다. 직전 회차가 없는 첫 칸은 ‘비교 없음’.
  3. 고른 회차 요약 — ‘{직전 날짜} → {고른 날짜}’, 큰 증감, ‘{직전 값} → {이번 값}’, 분모 ‘{지표 분모 이름} {직전} → {이번}’, 오른쪽 ‘이 회차 근거’.
  4. 축 탭 — 엔진 · 국가 · 프롬프트. 국가 담당 계정은 국가 탭이 없다(자기 국가 안에서 엔진 · 프롬프트). 권역 계정의 국가 탭은 권역 안 국가만.
  5. 기여 표 — 열: 항목 | 기여(0 기준 막대 + 값) | 직전 → 이번(그 조각의 지표 값) | 비중(분모 중 그 조각의 몫, 직전 → 이번) | 근거. 정렬 = 기여 크기(절댓값) 큰 순. 행에 마우스를 올리면 ‘값 변화 몫 · 비중 변화 몫 · 분모 수’.
    • 국가 · 프롬프트는 상위 10행 + ‘그 외 N개’ 한 행(합 유지). ‘모두 보기’는 서랍 안에서 펼친다.
    • 프롬프트 탭은 두 행을 따로 둔다: ‘새로 측정된 프롬프트 N개’(이번 회차에만), ‘측정에서 빠진 프롬프트 N개’(직전 회차에만).
    • 맨 아래 ‘합계’ 행 = 화면의 증감. 행마다 0.01 단위(소수 둘째 자리)로 보이되 최대 잔여 반올림으로 합을 화면 숫자에 맞춘다. 0.01 인 이유: 프롬프트 수백 개 · 국가 수십 개로 흩어지면 한 조각의 기여가 0.0x 라 0.1 단위로는 모두 0.0 이 된다(목업 검토).
    • 색은 방향(좋아짐 / 나빠짐)만 — 우선 노출도는 낮을수록 좋으므로 반대. 단위는 pp, 우선 노출도는 ‘번째’.
  6. 읽는 법 안내(ⓘ) — ‘기여 = 값 변화 몫 + 비중 변화 몫. 값이 떨어진 항목은 보통 −, 평균보다 높은 항목의 비중이 커지면 +.’ 산식은 4-3.
  7. 상태 — 로딩(뼈대), 지연(‘반영 중’), 오류(다시 시도), 회차 기준 데이터 없음(요약 사실표를 읽지 못해 미러로 떨어진 경우 — 이유 문장), 직전 회차 없음, 그 회차의 세부 데이터 없음(보존 기간 밖), 기간 비교 칩에서 연 경우의 안내.

4-2. 근거(답변 목록)

  1. 머리 — 제목 ‘근거’, 부제 ‘{지표} · {브랜드} · {회차 날짜} 회차’ + 조각 칩(엔진 · 국가 · 프롬프트 중 고른 것).
  2. 회차 토글 — 변화의 이유에서 왔을 때만: ‘이번 회차 {날짜} | 직전 회차 {날짜}’.
  3. 표본 줄 — 지표의 분자 / 분모와 값(예: ‘답변 2,735개 중 당사 언급 1,664개 · 60.8%’). 화면 값과 같은 숫자다(조건 1 의 표본 수도 여기서 충족).
  4. 나눔 탭 — 분자에 든 답변 | 나머지. 지표별 정의는 아래 표.
  5. 행 — 프롬프트 본문(1줄), ‘엔진 · 국가 · 언어 · 측정일’, 당사 표시(언급 수 · 순위 · 감정 · 인용 도메인 중 그 지표에 맞는 것), 원문 발췌 2줄(브랜드 강조). 행을 누르면 같은 서랍 안에서 원문 전체(인용 목록 포함)를 연다.
  6. 분량 — 50행씩 ‘더 보기’, 총 개수 표시. 정렬 = 프롬프트 · 엔진 · 국가 순.
  7. 격차에서 연 경우 — 탭 ‘당사 | {경쟁사}’ 두 개(나눔 탭은 각 탭 안에).

4-3. 기여 산식

조각 i 의 분모 비중 wi = di ÷ D, 값 ri = ni ÷ di, 전체 두 회차 평균 r̄ = (V0 + V1) ÷ 2 일 때

기여i = w̄i · (ri1 − ri0) + (r̄i − r̄) · (wi1 − wi0)  = 값 변화 몫 + 비중 변화 몫  (w̄i, r̄i = 그 조각의 두 회차 평균)

  • 합 = V1 − V0 정확히(Σ(w1 − w0) = 0 이라 평균을 빼도 합이 같다). 새로 측정된 조각 = (ri1 − r̄) · wi1, 빠진 조각 = −(ri0 − r̄) · wi0 — 평균과 같은 값으로 들어오면 0.
  • 왜 이 식인가: ‘이번 몫 − 직전 몫’(w1r1 − w0r0)도 합은 같지만, 값이 떨어진 조각이 비중만 늘어 + 로 보인다(목업 검토: ChatGPT 67.7% → 67.1% 가 +0.1pp). 평균을 뺀 식에서는 같은 조각이 −0.3pp 다.
  • 순위(우선 노출도)도 같은 식(값 = 순위 합 ÷ 순위 있는 답변). 단위는 ‘번째’, 좋아짐 = 음수.
  • 표시: 행마다 0.01 단위, 최대 잔여 반올림으로 합을 화면 증감에 맞춘다. 화면 증감이 반올림 값끼리의 차(round1(round1(v1) − round1(v0)))라 정확한 차와 0.1 다를 수 있어도 같은 방식으로 맞춘다.

5. 데이터 원천(legacy)

  • 회차 자리 — 카드 추이와 같은 회차 묶음 함수(lib/summary/read/cycle-set.ts)를 그대로 쓴다. 증감 이력 띠의 값 = 카드 추이 자리 값의 차라서 화면 증감과 같은 숫자다.
  • 엔진 · 국가 분해 — 요약 추이층 summary_trend_own(당사) · summary_trend_brands(경쟁사)의 키에 이미 engine · country 가 있다(fold.ts AGG_DIMS). 카드 값과 같은 행을 엔진 또는 국가로 묶기만 하므로 기여의 합이 구성상 카드 증감과 같다. 엔진별 ①–④ 는 이미 추이 배열에 실려 온다(summary-global-trend-read.ts engines).
  • 프롬프트 분해 — 추이층에는 프롬프트 열이 없다. 세부층(summary_answers · summary_brand_mentions · summary_domain_citations)의 두 회차를 접기(fold) 규칙 그대로 prompt_id 로 접는다. 본문은 summary_prompt_dim.text. 접기와 글자 그대로 같은 식을 써야 하는 곳: ② 분모(경쟁 통과 언급 comp_mentions), ④ 표시명 접기 순위, ⑤ 공식(HMG) 판정(변형 · 스코프별), 경쟁사 순위(comp_rank_sum). 시험: 프롬프트 합 = 추이층 자리 값(두 회차 모두).
  • 근거 목록 — 세부층의 job(회차 고정) → 미러 scope_answers 원문. 거름 = 엔진 · 국가 · 프롬프트 · 브랜드, 인용은 group_key. 기존 서랍 라우트(기간 내 누적으로 고정)는 쓰지 않는다.
  • 계정 범위 — 세션 scope 로 readStandardFilters 를 만들고 같은 필터 객체를 쓴다. 새 리더는 lib/scope/server.ts 의 withStandardRoot 안에 둔다.
  • 캐시 — mirrorCache + 요약 태그(무효화는 기존 sync-mirror 와 같다).
  • 회차 기준 데이터 없음 — 요약 사실표 읽기가 꺼져 카드가 미러로 떨어지면 증감이 ‘직전 측정일’ 기준이 되므로 분해하지 않고 서랍에 그 사실을 적는다. 경쟁사 추이가 주 단위 미러 버킷일 때(경쟁사 화면 키 꺼짐)도 같다. 이때 근거(값을 누름)는 카드 값과 같은 미러 스냅샷 빌더로 연다(직전 회차 토글 없음).

7. 남은 확인

  • 요약 세부층의 실제 보존 기간 — 설계는 13주이나 지우는 코드가 없다. 이력 띠 12칸이 세부층 범위를 넘으면 그 칸은 ‘세부 데이터 없음’.
