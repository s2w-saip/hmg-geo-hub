# 고객 관심(intent) 모듈 설계 (IN-1 키워드 + IN-2 소셜 스크레이핑)

기준: 설계 공용 계약 v2(`DESIGN-CONTRACT.md`), 확정 DDL `db/DB-v2.sql`. 현행 근거: 통합 프리뷰 7639b9e.

## 1. 개요

고객 관심 화면 두 탭을 하나의 FastAPI 모듈 `/v1/intent` 로 제공한다.

| 단위 | 화면 | 원천 | 성격 |
| --- | --- | --- | --- |
| IN-1 | 프로젝트 intent/google-keyword, 표준 customer-interest/google-keywords | DataForSEO 응답 투영 `rd.kw_*`, `app.project_tracked_keyword`, `app.kw_prompt_draft` | 외부 데이터 조회 + 유료 수집 요청 + LLM 초안 |
| IN-2 | 프로젝트 intent/social-scraping | 컨텍스트 맵 정적 스냅샷 `ext.ctx_*`, `app.ctx_generated_prompt` | 코퍼스 열람 + LLM 프롬프트 생성 |

두 단위 모두 측정 지표 M01~M12, 규칙 R01~R13 을 소비하지 않는다. 공통 필터 모델의 축은 전부 지원하지 않으며, 들어오면 `meta.ignored_filters` 에 기록한다.

모듈 차원의 핵심 결정:

1. **유료 수집은 비동기 큐**: api_rw 는 app 과 judgment_change INSERT 만 가능하다(DB-v2.sql:839-843). 그래서 DataForSEO 재조회는 `app.judgment_change` kind `dfs_fetch`(제안 P1)로 요청하고 적재기가 `ext.dfs_call`·`rd.kw_*` 를 쓴다. API 는 202 를 주고 클라이언트가 폴링한다. DB-ACR-외부-데이터.md:70 의 "첫 조회는 수집 중 상태로 응답" 과 같다.
2. **키워드 읽기는 term+country 기반**: `rd.kw_*` 는 프로젝트에 묶이지 않은 공용 외부 데이터다. 그래서 프로젝트 화면과 표준 화면(project 없음)이 같은 엔드포인트를 쓴다.
3. **후보 풀 쓰기 단일화**: `POST /v1/intent/candidates` 하나를 두 단위가 공유한다.
4. **GET 은 부수효과 없음**: IN-1 의 `fresh` 파라미터는 없앴다.

## 2. 엔드포인트 명세

모든 project 종속 엔드포인트는 `project_id` 를 query 로 받는다. 응답은 `{data, meta}` 형태다(§3 IntentMeta).

### IN-1 키워드

| 메서드 | 경로 | 권한 | 설명 |
| --- | --- | --- | --- |
| GET | /v1/intent/keywords?project_id= | 멤버 | 추적 키워드 목록과 키워드별 최신 월 검색량 |
| POST | /v1/intent/keywords?project_id= | 운영 | body {term, country?}. 중복이면 409 |
| DELETE | /v1/intent/keywords?project_id=&ids= | 운영 | 1~100건 삭제. WHERE project_id 스코프로 남의 행 차단(현행 _actions.ts:445-455 방식) |
| GET | /v1/intent/insight?term=&country=&project_id?&limit=8 | 멤버 또는 표준 열람자 | 12개월 추이, 최신 SERP(최신 gen 초안 포함), serp_call_id, freshness |
| GET | /v1/intent/related?term=&country=&project_id? | 같음 | 최신 연관어(is_seed 제외, 최대 30), freshness |
| GET | /v1/intent/lookup?terms=&country=&project_id? | 같음 | 여러 term 조회(빈 상태 검색 플로우) |
| GET | /v1/intent/standard-keywords?source_type=&brand=&limit=&cursor= | 표준 열람자(hq·region·country·admin + 메뉴 standard) | 표준 화면 키워드 탭 원천(BG-41, 읽기 전용). app.standard_keyword enabled 행, 브랜드 스코프(공통 NULL 은 모두, 그 밖은 계정 브랜드 안). notes·created_by 비노출. 가시 행을 app.term_norm(term) 으로 합쳐 한 항목으로 준다(같은 term 의 공통·브랜드 행이 탭 둘이 되지 않게, bg-intent 검증 D4). 정렬 대표 행 created_at DESC·keyword_id, 한 페이지 기본·최대 500 항목, 초과분은 키셋 커서(meta.page.next_cursor)로 이어 받는다. meta.page.total = 필터 전체 항목 수. 쓰기는 /v1/admin/interest/keywords 그대로 |
| POST | /v1/intent/fetches | 운영 | body {project_id?, kind: insight/related/search, terms[], country, force?}. 신선하면 200 {status:'fresh'}, 아니면 judgment_change INSERT 후 202 {change_id}. 같은 요청이 미완료면 기존 change_id 반환 |
| GET | /v1/intent/fetches/{change_id} | 요청자 또는 운영 | pending, running, applied, failed(+error) |
| POST | /v1/intent/serp-drafts | 운영 | body {project_id?, serp_call_id, ranks?}. ranks 를 생략하면 초안 없는 전 행을 LLM 1회로 처리, 지정하면 재생성(gen+1) |
| POST | /v1/intent/candidates?project_id= | 운영 | 공용. body {source, items[{text, source_keyword?}]}. 응답 {added_count, skipped_count, candidate_ids} |

freshness 는 `observed_at` 과 상수 FRESHNESS(insight 24h, related·search 7d, lib/keyword/cache.ts:41-44)로 계산하며 fresh, stale, missing 중 하나다. missing 이면 data 가 빈 값이다. FE 는 운영자라면 수집 버튼을, 아니면 "준비 중"(A12)을 보여준다.

응답 예:

- insight: `{term, country, location_code, language_code, trend:[{month, search_volume, competition_index, cpc}]≤12, serp_call_id, serp:[{rank, url, domain, title, snippet, suggested_prompt|null, draft_model}]≤limit}`. `meta.as_of` = max(observed_at), `meta.freshness`.
- related: `{found_count, items:[{term, search_volume, intent}]}`.
- lookup: `[{term, status, search_volume, intent, related:[…]}]`.
- keywords: `[{keyword_id, term, country, created_at, latest_month, latest_volume}]`.
- standard-keywords: `{source_type, items:[{keyword_id, keyword_ids[], term, source_type, brand_codes[(null=공통)], created_at, updated_at}]}`. 한 항목 = term_norm 묶음(keyword_id·term·created_at = 대표 행: created_at 최신, 동률 keyword_id 최소. updated_at = 묶음 최댓값). 화면 탭은 id = keyword_id, label = term 으로 쓰면 둘 다 응답 안에서 유일하다. `meta.page = {next_cursor, limit, total}`, 브랜드 좁히기에서 빠진 값은 `meta.dropped_filters.brand`.

| DELETE | /v1/intent/social/prompts?project_id=&ids= | 운영 | 소프트 삭제(removed_at). seed_key 는 제외 집합으로 계속 유지 |

엔티티 행: `{id, name, theme_id?, theme_name?, category?, mention_count, sentiment:{positive, negative, neutral, total, positive_pct, negative_pct, neutral_pct}, linked_count}`. sentiment 의 분모는 세 감성 개수의 합이다. 합이 0 이면 neutral_pct 를 100 으로 둔다(현행 sentimentPerspective, scope-context-map.ts:87-100). 구 필드명 perspective(buyer/seller)는 폐기한다.

## 3. 공통 구성요소

- **라우터**: `app/modules/intent/` 아래 keywords.py, social.py, candidates.py 를 두고, deps·schemas·repo_kw·repo_ctx·repo_app·presets·llm·xlsx 를 공유한다.
- **IntentMeta**: 공통 meta 필드(surface, mode, as_of, cycles, generation, ignored_filters, dropped_filters, suppressed)를 그대로 둔다. surface, mode, cycles, generation 은 null 이다. 여기에 page{total,page,size}, snapshot_id, freshness 를 확장한다. surface 열거형에 'intent' 는 추가하지 않는다.
- **DB 세션**: 읽기는 `ro_conn`(api_ro), 쓰기는 `rw_tx`(api_rw, `set_config('app.actor_id', uid, true)`)를 쓴다. api_rw 는 rd·ext 를 읽을 수 없다. 그래서 쓰기 핸들러는 항상 **읽기(api_ro) → 외부 호출(트랜잭션 없음) → 쓰기(api_rw 짧은 트랜잭션)** 3단으로 짠다.
- **term_norm**: NFC, trim, lower 순서로 만든다. 현행 insight.ts:54-55 와 같고 NFC 만 추가했다. 적재기와 한 벌을 공유한다.
- **국가 프리셋**: lib/keyword/location-presets.ts 배열을 파이썬 상수로 옮긴다. 모르는 country 는 400 으로 거부한다.
- **정렬·검색 안전**: sort·dir 은 화이트리스트 매핑으로만 SQL 조각을 고르고, ILIKE 입력은 이스케이프한다.
- **컨텍스트 맵 산업 선택**: 서버 설정 CONTEXT_MAP_INDUSTRY_ENTITY_ID 로 정한다(현행 단일 자동차 코퍼스, _actions.ts:141-147). 활성 스냅샷이 없으면 "준비 중" 을 준다.

## 5. 권한

- 컨텍스트 맵 읽기: 인증 사용자면 된다. 코퍼스는 브랜드와 프로젝트 축이 없는 전역 데이터다(현행 app/api/context-map/route.ts 주석과 같은 판단). 코퍼스가 프로젝트별로 나뉘면 다시 본다.
- 키워드 읽기: project_id 가 있으면 active 멤버, admin, global 운영자만 읽는다. 없으면 STANDARD_VIEWERS(hq, region, country, admin)이면서 country 가 사용자 국가 스코프 안이어야 한다. 스코프 밖이면 403.
- 쓰기와 유료 호출(키워드 추가·삭제, fetches, serp-drafts, candidates, 소셜 프롬프트 생성·삭제): canOperateProject 를 이식해 적용한다. admin 은 통과, none 은 거부, global 은 통과, assigned 는 active 멤버일 때만 통과한다. project_id 가 없으면 admin 또는 global 만 허용한다. 현행은 insight·related·search 라우트가 requireUser 만 검사하므로 이 부분은 권한이 강해지는 변경이다.
- 모든 쓰기 SQL 은 WHERE project_id 로 클라이언트가 보낸 id 의 소속을 다시 확인한다.
- 검증 D3·D5 로 정한 규칙(2026-09-28, intent R11, core 6라운드 반영):
  1. project_id 없는 키워드 경로(insight·related·lookup·fetches·serp-drafts)는 메뉴 그룹 standard 게이트, project_id 가 있는 경로는 project 게이트.
  2. project_id 경로의 국가는 프로젝트 국가 ∪ 그 프로젝트 추적 키워드 국가로 묶인다. 그 밖의 국가면 project_id 없는 규칙(표준 화면 권한)을 적용한다.
  3. serp-drafts 의 프로젝트 권한은 SERP 의 (키워드, location, language)가 그 프로젝트 추적 키워드와 맞을 때만 인정한다.
  4. fetches 의 "같은 요청(수집 종류·location·language·term 집합)이 미완료면 기존 change_id 를 돌려준다"는 요청자가 상태 조회로 볼 수 있는 행에 한한다
     (core.write.enqueue_change_result dedupe=coalesce_active + reusable 판정). 볼 수 없으면 새 요청을 넣는다.

## 6. 성능

| 엔드포인트 | 10배에서 요청당 행 | 한정 조건 | 위험 |
| --- | --- | --- | --- |
| keywords 목록 | 프로젝트 추적 키워드 수(수백 이하) + 키워드당 1행 | project_id 유니크 선두, PK 4열 | low |
| insight | 추이 ≤12, SERP ≤10, 초안 LATERAL 1 | kw_key·loc·lang 최신 call(kw_serp_latest) | low |
| related·lookup | ≤30 × terms | kw_suggestion_latest | low |
| context-map 목록 | 페이지 ≤200 + COUNT(스냅샷당 수천~수만) | ctx_entity_type_mentions, P2 | low |
| entities 상세 | 근거 8, 도메인·연결 수십 | PK·ctx_evidence_entity·P2 | low |
| stats | ctx_domain 스냅샷 전체 DISTINCT host | snapshot_id | low |
| export | 전량 약 10만(10배 가정) | snapshot_id | medium: 서버 커서 + 스트리밍 |
| 생성류 | 시드 풀 ≤850 + 프로젝트 생성물 수백 | 인덱스 | medium: LLM 지연 |

파티션 가지치기와 D8 예외는 해당이 없다. 사전 집계, 캐시, 요약 표는 두지 않는다(stats·COUNT·similar_to 는 조회할 때 계산). 측정 사실 표를 읽지 않아 G-25 등 알려진 고위험과는 무관하다.

## 7. 대조 방법(신구 패리티)

- IN-2 읽기: 스냅샷이 정적이므로 값이 정확히 같아야 한다. 현행 `/api/context-map?tab=contexts|conditions|combinations`(정렬·방향 조합별 page 0~2), `tab=detail`(상위 20 엔티티), stats, export 행 수와 셀 값을 새 엔드포인트와 비교한다. 차이로 인정하는 것은 필드명(perspective 에서 sentiment 로)과 버킷 경계뿐이다.
- IN-2 생성: LLM 출력은 비결정적이라 값은 대조하지 않는다. 시드 풀 구성(Top-N id 집합, 현행 getSeedPool), 제외 집합 동작(같은 시드 재생성 0건), skipped_existing 수를 대조한다.
- IN-1: 현행 캐시(keyword_cache)는 폐기 대상이라 값 대조 원천이 없다. 같은 DataForSEO 응답 원본 픽스처를 적재기에 넣은 뒤 새 insight·related 출력이 현행 buildMonthlyTrend·SERP 8행 절단·related seed 제외 규칙의 출력과 같은지 계약 테스트로 확인한다. term_norm 은 API 와 적재기 양쪽에 같은 골든 세트(한글 NFD 입력 포함)를 넣어 검사한다.
- 권한: 역할 × operator × 멤버십 행렬(operator-policy.test.ts:45-65 사례)을 엔드포인트마다 적용한다. 다른 프로젝트 id 로 DELETE 했을 때 0건이 나오는지 확인한다.

## 8. 열린 질문

1. P1(judgment_change 'dfs_fetch')을 승인할지, 그리고 적재기 픽업 주기(목표 5초 이내)와 방식(LISTEN/NOTIFY 또는 폴링).
