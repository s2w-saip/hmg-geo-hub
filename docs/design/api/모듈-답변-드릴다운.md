# answers 모듈 설계 (답변 드릴다운)

> 기준: 설계 공용 계약 v2 (`DESIGN-CONTRACT.md`), 확정 DDL `db/DB-v2.sql`. 단위: AN-1(목록), AN-2(상세). 현행 근거: 통합 프리뷰 7639b9e.

## 1. 개요

답변 드릴다운은 카드·표·차트의 숫자를 눌렀을 때 그 숫자를 이루는 **개별 답변**을 보여 주는 기능이다. 현행은 모집단 목록을 각 드릴다운 API(brand-mention-prompts, brand-citations, signal-prompts)가 프롬프트 단위로 묶어 주고, 원문은 `/api/scope/answer?jobId=` 가 한 건씩 준다(app/api/scope/answer/route.ts:24).

새 구조는 두 엔드포인트로 나눈다.

| 단위 | 엔드포인트 | 역할 |
| --- | --- | --- |
| AN-1 | `GET /v1/answers` | 조건에 맞는 완료 답변의 키셋 목록. 모달의 답변 배열(현행 `MentionAnswerLive[]`)과 신호 프롬프트 답변을 공급 |
| AN-2 | `GET /v1/answers/{job_id}` | 답변 1건의 헤더·원문·언급·감성 스팬·스탠스·인용 |

프롬프트 단위 집계 목록(프롬프트별 언급 수·점유율)은 mentions·citations 모듈의 `/prompts` 가 맡고, 사용자가 프롬프트를 고르면 AN-1(`prompt_id`)로 넘어온다.

## 2. 확정 결정 (단위 사이 모순 해소)

1. **공개 id = job_id(uuid).** 현행 모달·QA 가 job_id 로 라우팅하고(`raw-data-qa/answers/[jobId]`, `app.qa_answer_review` PK) answer_key 는 순차 정수라 열거 가능하다. answer_key 는 커서 안에만 쓴다.
2. **surface 는 문자열 enum**(`global`·`website`·`project`). DB 정수 1·2·3 은 내부 전용(DB-v2.sql:12).
3. **기간 축 = round_date**(계약 §3, G-04). anchor_date 는 표시만.
4. **R03** = `c.servable AND c.view_date <= rd.today_kst()`, view_date NULL 은 비노출.
5. **R04 계열 게이트**(현행 scope-aggregates.ts:3790-3793 계승):

   | 대상 | 허용 hidden_scope |
   | --- | --- |
   | 답변 행 자체 | 0, 2, 3 (1 all 제외) |
   | 언급 필드·언급 술어(mention_brand, signal) | 0, 2 |
   | 인용 필드·인용 술어(domain, source[]) | 0 |

6. **권한은 표면별**(아래 §6). AN-2 초안의 일괄 geo_key 게이트는 폐기.
7. **브랜드 스코프 = `bgrp = ANY(마스크 목록)`**, 스코프 브랜드 ∪ HMG 공통.
8. **상세 언급 브랜드 원천 = rd.answer_brand**(카드와 같은 규칙 버전). 모델 행만 원본 뷰.
9. **감성 스팬·스탠스 근거 대조는 서버 계산**(현행 포팅).
10. **source_category[] 폐지 → 공통 source[]**, 카탈로그 축은 global 에서 지원.

## 3. 엔드포인트 명세

### 3.1 AN-1 `GET /v1/answers`

**필터**

| 구분 | 축 |
| --- | --- |
| 지원(공통) | surface(필수), own_brand(서버), brand[], country[], lang[](website), engine[](비면 dflt), from/to, funnel[]·brand_presence[]·list_type[]·depth1~3[](global 만), source[] |
| 무시 | 표면에 맞지 않는 카탈로그 축, lang[](global·project 는 filters 모듈 판정 따름) |
| 추가 | `project_id`(surface=project 필수), `prompt_id`, `mention_brand`(rd.dim_brand_name.name), `signal`(positive·neutral·mixed·negative·mention·recommendation·comparison·definition·final_choice), `domain`, `q`(2~200자), `include_gap`(기본 false), `collapse`(none·cell, cell 은 prompt_id 필수), `cursor`, `limit`(기본 50, 최대 200) |

**모드**: from/to 가 없으면 snapshot(프로젝트별 최신 노출 회차 1개, kpi 모듈 `snapshot_cycles` 재사용. 인용 술어가 있으면 인용 계열 회차, 아니면 언급 계열 회차), 있으면 cumulative.

**응답**

```json
{
  "data": { "rows": [ {
    "id": "job_id(uuid)",
    "round_date": "date", "anchor_date": "date", "measured_at": "timestamptz|null",
    "prompt": { "prompt_id": "uuid", "text": "string|null" },
    "engine": "code", "country": "code|null", "lang": "code|null",
    "is_rep": true, "is_acr": false, "acr_iter_rank": 1, "gap": false,
    "mentions": { "total": 3, "own": { "count": 1, "rank": 2 } },
    "citations": { "has_cit": true, "tgt_cited": false, "own_url_cited": true },
    "matched_brand": { "name": "Kia", "mention_count": 2, "rank": 1,
                       "sentiment": {"pos":1,"neu":1,"neg":0,"mix":0},
                       "types": {"mention":1,"recommendation":1,"comparison":0,"definition":0,"final_choice":0} },
    "matched_domain": { "domain": "example.com", "citations": 2 },
    "runs": null
  } ] },
  "meta": { "surface": "global", "mode": "snapshot", "as_of": "date", "cycles": ["cycle_id"],
            "generation": 0, "ignored_filters": [], "dropped_filters": {}, "suppressed": {},
            "page": { "next_cursor": "string|null", "window_from": "date", "window_to": "date" } }
}
```

- `mentions` 는 언급 계열 숨김이면 null, `citations` 는 인용 계열 숨김이면 null 이고 `meta.suppressed` 에 사유를 적는다. 사유 코드는
  core `envelope.SUPPRESS_*` 어휘다: 창 회차가 그 계열에서 전부 숨김 = `hidden`, 계열 술어(mention_brand·signal·domain·source[])가 걸린 채
  창의 **일부** 회차만 그 계열 숨김 = `partial_hidden`(남은 회차 행만 나온다는 고지, core `window_suppression(partial=True)`).
- 이 페이지가 훑은 round_date 창은 `meta.page.window_from·window_to`(core `envelope.Page`, 기간 모드 92일 조각)다. data 에는 싣지 않는다.
- `mentions.own` 은 ment_h/k/g·own_rk_h/k/g 를 own_bits 로 골라 Python 에서 계산한다(HMG = 합, 순위는 0 제외 최솟값, 계약 §3 M04 규칙).
- `matched_brand`·`matched_domain` 은 해당 파라미터가 있을 때만, 페이지 answer_key(최대 201개)로 2차 소형 조회해 채운다. competitive true/false 두 행은 합산, rank 는 competitive 행 rk(0 이면 null).
- `runs` 는 collapse=cell 일 때만.

**쿼리 골격**(정적 SQL, 선택 술어는 코드에서 조립)

```sql
SELECT a.answer_key, a.round_date, a.anchor_date, a.prompt_key, a.engine_key, a.geo_key, a.lang_key,
       a.is_rep, a.is_acr, a.acr_iter_rank, a.gap, a.ment_total, a.ment_h, a.ment_k, a.ment_g,
       a.own_rk_h, a.own_rk_k, a.own_rk_g, a.has_cit, a.tgt_cited, a.own_url_cited, a.cyc_key,
       j.job_id, j.measured_at
  FROM rd.answer a
  JOIN rd.job j ON j.answer_key = a.answer_key
 WHERE a.surface = :surface
   AND a.round_date BETWEEN :win_from AND :win_to            -- 창(스냅샷 = 회차 round_date)
   AND a.cyc_key = ANY(:cyc_keys)                            -- 노출·계열 게이트 + project_key 스코프
   AND a.bgrp = ANY(:bgrp_values)
   [AND a.geo_key = ANY(:geo_keys)]  [AND a.lang_key = ANY(:lang_keys)]
   [AND a.engine_key = ANY(:engine_keys) | AND a.dflt]
   [AND a.prompt_key = ANY(:prompt_keys)]                    -- prompt_id·카탈로그 축·q 결과
   AND a.std_in                                              -- include_gap 이면 a.cit_in
   [AND (a.round_date, a.answer_key) < (:c_rd, :c_ak)]
   [AND EXISTS (SELECT 1 FROM rd.answer_brand ab
                 WHERE ab.surface = a.surface AND ab.round_date = a.round_date AND ab.answer_key = a.answer_key
                   AND ab.brand_key = :mention_brand_key AND ab.std_in)]
   [AND EXISTS (SELECT 1 FROM rd.answer_brand ab WHERE ... AND ab.own_bit = ANY(:own_bits) AND ab.std_in AND ab.<s_*|t_*> > 0)]
   [AND EXISTS (SELECT 1 FROM rd.citation c
                 WHERE c.surface = a.surface AND c.round_date = a.round_date AND c.answer_key = a.answer_key
                   AND c.cit_in AND c.source_key = ANY(:source_keys))]   -- domain·source[] → source_key 집합
 ORDER BY a.round_date DESC, a.answer_key DESC
 LIMIT :limit + 1;
```

- 인용 술어가 있으면 `:cyc_keys` 는 인용 계열 게이트(hidden_scope = 0)로, 언급 술어가 있으면 언급 계열로 계산한다. 둘 다 있으면 교집합.
- collapse=cell: 같은 조건에서 `DISTINCT ON (a.engine_key, a.geo_key) ... ORDER BY a.engine_key, a.geo_key, j.measured_at DESC` + `count(*) OVER (PARTITION BY a.engine_key, a.geo_key)`. prompt_id 로 좁혀 행 수가 작을 때만 허용한다.
- 선택 술어가 있고 기간이 92일을 넘으면 창을 92일씩 잘라 걸어가며, 창 안에서 limit 을 못 채우면 부분 페이지와 창 경계 커서를 돌려준다.

### 3.2 AN-2 `GET /v1/answers/{job_id}`

**필터**: surface(선택, 실제 표면과 다르면 404), brand[](global·website, 관점 브랜드 입력, 스코프 교집합. project 는 ignored). 나머지 공통 축은 `meta.ignored_filters`.

**처리 순서**

1. 헤더(스코프·노출 게이트 포함, 없으면 404):

```sql
SELECT j.answer_key, j.job_id, j.surface, j.project_key, j.cyc_key, j.round_date, j.measured_at,
       j.engine_key, j.geo_key, j.lang_key, j.bgrp, j.prompt_key,
       c.cycle_id, c.anchor_date, c.hidden_scope, c.generation
  FROM rd.job j JOIN rd.cycle c ON c.cyc_key = j.cyc_key
 WHERE j.job_id = :job_id AND j.served
   AND c.servable AND c.view_date <= rd.today_kst() AND c.hidden_scope = ANY('{0,2,3}')
   AND j.project_key = ANY(:project_keys)
   [AND j.bgrp = ANY(:bgrp_values) AND j.geo_key = ANY(:geo_keys)]   -- global 만
```

2. 번들(한 문장, 스칼라 서브쿼리 json_agg): 프롬프트·카탈로그(dim_prompt ⋈ catalog_entry ⋈ dim_taxon), rd.answer 메타, v_answer_body, rd.answer_brand ⋈ dim_brand_name(브랜드), v_answer_mention_raw(모델, entity_type <> 'Brand'), v_answer_occurrence, v_answer_stance_raw ⋈ dim_entity ⋈ rd.answer_stance(own_bit), rd.citation ⋈ dim_url ⋈ dim_source ⋈ app.citation_category. 사실 표는 헤더의 (surface, round_date, answer_key) 등치, 뷰는 answer_key 등치 + 스코프 열 재단언.
3. 서버 계산: own_bits(표면별: project = app.project.brand_code, global·website = brand[] ∩ 스코프(요청 관점), 없으면 스코프 전체(admin·scope_all = 3사). 목록 AN-1 과 같은 규칙: 현행 scope-aggregates.ts:7954 getMirrorAnswerBody trackedEntityIdsFor(contextBrand ?? brand), 2026-09-28 core 6라운드 정정), `build_sentiment_spans`(당사 발생만), `verify_stance_evidence`, 스탠스 정렬(turn, 당사 우선, 표시명).

**응답**

```json
{
  "data": {
    "id": "job_id",
    "header": { "surface": "global", "cycle_id": "uuid", "round_date": "date", "anchor_date": "date",
                "measured_at": "ts|null", "engine": "code", "country": "code", "lang": "code",
                "prompt": { "prompt_id": "uuid", "text": "string|null", "funnel": "code|null", "kind": "single|acr" },
                "catalog": { "brand": "code|null", "presence": "code|null", "list_type": "code|null",
                             "depth1": null, "depth2": null, "depth3": null },
                "analysis_state": 0, "gap": false, "is_acr": false, "acr_iter_rank": 1, "model_slug": "string|null" },
    "body": { "available": true, "answer_text": "string" },
    "mentions": { "brands": [ { "name": "Kia", "mention_count": 3, "rank": 1, "own_bit": 2, "own": true } ],
                  "models": [ { "name": "EV9", "mention_count": 1, "parent_brand": "Kia" } ] },
    "sentiment": { "spans": [], "skipped": 0 },
    "stances": [ { "turn_index": 0, "entity_id": "uuid", "brand": "Kia", "own": true, "stance": "positive",
                   "confidence": 0.9, "evidence_text": "string|null", "evidence_match": "verified|mismatch|unavailable",
                   "reason": "string|null" } ],
    "citations": [ { "ord": 1, "url": "string|null", "title": "string|null", "domain": "string|null",
                     "category": "string", "owned": false, "target_hit": false } ]
  },
  "meta": { "surface": "global", "mode": "snapshot", "as_of": "date", "cycles": ["cycle_id"],
            "generation": 0, "ignored_filters": [], "dropped_filters": {},
            "suppressed": { "mentions": "hidden|analysis_gap", "citations": "hidden" } }
}
```

- `body.available=false` 면 이하 섹션은 빈 값(현행 `{ available:false }` 계약 계승).
- 언급 계열 숨김(3)이면 mentions·sentiment·stances 를, 인용 계열 숨김(2·3)이면 citations 를 비우고 suppressed 에 표시한다. gap 답변은 언급 섹션이 비고 `analysis_gap`.

## 4. 공통 구성요소

- **라우터**: `app/modules/answers/router.py`, 핸들러는 파라미터 검증·스코프 호출·repo 호출·meta 조립만.
- **공통 의존성(타 모듈)**: `get_principal`, `resolve_scope`, `get_ro_conn`(api_ro, statement_cache_size=0), `build_meta`, kpi 의 `snapshot_cycles`.
- **gates.py**: R03 SQL 조각, `family_visible(hidden_scope, family)` 과 계열별 허용 코드 배열. 다른 모듈도 쓸 수 있게 공용 후보로 올린다.
- **repo.py**: `exposed_cycles`, `load_job_header`(QA 모듈 변형 공유), `list_answers`, `matched_brand_rows`, `matched_domain_counts`, `detail_bundle`.
- **render.py**: `verify_stance_evidence`(원본 lib/answer-sentiment/stance-evidence.ts:31), `build_sentiment_spans`(lib/answer-sentiment/spans.ts:88), `is_own`. 오프셋은 코드포인트 기준이라 Python str 인덱스와 그대로 맞는다.
- **커서**: base64url JSON `{v, rd, ak, w}`. 서명 없음(스코프는 매 요청 재계산).
- **캐시 없음**: 결과·차원 사전 모두 요청마다 조회(D8).

## 6. 권한

| 표면 | 게이트 |
| --- | --- |
| global | project_key = root, `bgrp = ANY(스코프 브랜드 ∪ HMG 마스크)`, `geo_key = ANY(허용 국가)` |
| website | `project_key = ANY(스코프 사이트)`(site_brand_bit·site_geo_key 로 계산, 가상 코드 HYUNDAI-N 은 브랜드 비트). 답변 geo_key 로 거르지 않는다 |
| project | `project_key = ANY(활성 멤버 프로젝트)`, scope_all 이면 전체. 계정 region 락 미적용(현행 route.ts:36-40 계승) |

- api_ro(읽기 전용, 5초, DB-v2.sql:830-836)만 쓴다. ing 직접 접근 없음, 원문은 rd 뷰로만.
- 목록: 권한 밖 값은 `meta.dropped_filters`, 공집합이면 빈 rows. 상세: 존재하지 않음·스코프 밖·미노출·숨김 all·비served 모두 404. 세션 무효 401, 스코프 계산 실패 403(fail-closed).
- brand[] 는 관점(own) 입력일 뿐 접근 범위를 넓히지 않는다(스코프 교집합, global·website).
- 운영자 게이트 없음(비용 액션 아님). 접근 감사 로그는 AU-1 결정을 따른다.

## 7. 성능 (폭 10배 기준, 실측 전 추정)

| 경로 | 읽는 행 | 가지치기·인덱스 | 위험 |
| --- | --- | --- | --- |
| AN-2 상세 | 헤더 1 + 답변 1 + 언급·발생·스탠스 수십~수백 + 인용 5~20 | rd.job UNIQUE(job_id), 사실 표 PK 등치, ing PK 프리픽스 | low |
| AN-1 스냅샷 | 회차 leaf 1개(약 10만~15만 행 추정) 중 PK 역순 + 필요 시 EXISTS 탐침 | LIST(surface) + RANGE(round_date) 1 leaf, PK(surface, round_date, answer_key) 역순, cyc_key = ANY | medium |
| AN-1 기간 1년 + 선택 술어 | 최대 450만~700만 답변(DB-성능-물리-설계.md §8) | 92일 창 상한, ab_brand_idx·cit_source_idx 구동, SET STATISTICS 1000 | high |

## 8. 대조 방법

- **AN-2 ↔ 현행 `/api/scope/answer`**: 같은 job_id 표본(표면 3종 × 엔진 × 턴 1·2 × gap 유무)으로 answerText, citations(순서·URL), brandMentions(이름·수·tracked), modelMentions, sentiment.spans·skipped, stances(evidenceMatch 포함)를 필드 단위 비교. 예상 차이: 인용 카테고리 체계 변경, 표시명 병합 위치 변경 → mig.known_diff 등록.
- **AN-1 ↔ 현행 드릴다운**: brand-mention-prompts·brand-citations·signal-prompts 결과의 (프롬프트, 답변 job_id) 집합을 collapse=cell 결과와 비교. 예상 차이: 반복 측정 전체 나열(collapse=none), ACR 반복 접기(A15), gap 제외(A16).
- **카드 정합**: 같은 필터로 kpi 카드의 분모(답변 수)와 AN-1 전체 행 수(페이지 끝까지)가 같은지 확인(스냅샷·기간 각 1회).
- **권한 회귀**: 웹사이트 가상 지역 계정, 브랜드 전용 계정의 타 브랜드 job_id, 프로젝트 비멤버, 미노출 회차 job_id 가 모두 기대대로(200 또는 404) 나오는지.
- 신구 대조 하네스(`notes/hmg-refactor-proto/harness`)에 드릴다운 조합을 추가한다.

## 9. 열린 질문

1. hidden_scope=3(mentions)의 현행 대응 분기가 없다. 언급 계열만 숨기는 해석으로 확정해도 되는가(운영 의도 확인).
2. `meta.page`(next_cursor, 창 경계)를 공통 meta 확장으로 둘지 통합자 합의가 필요하다.
3. rd.dim_url.domain 과 rd.dim_source.domain 의 정규화(www·서브도메인·소셜 경로)가 같은가. 다르면 domain 술어 결과가 현행 fetchWebsiteBrandCitations(lib/scope/server.ts:5220)와 갈린다.
4. 프로젝트 가상 회차에 view_date 가 기입되는가(NULL 이면 프로젝트 답변 전부 404).
5. rd.dim_brand_name.name 이 현행 canonicalBrandDisplayName(lib/scope/brand-display-aliases.ts:83) 결과와 같은 표기로 적재되는가(적재 모듈).
6. 92일 창 상한 값과, 창 경계에서 부분 페이지를 돌려주는 UX 가 모달에서 수용 가능한가.
7. 고객 상세에 앵커 고정·드롭 사유(v_answer_registry)를 보일지(현행 고객 화면엔 없음, QA 전용 유지 권장).
8. collapse=cell 기본값: 현행 모달처럼 prompt_id 지정 시 cell 을 기본으로 할지, 반복 전체 나열을 새 기본으로 고지할지(A4 고지 대상 여부).
