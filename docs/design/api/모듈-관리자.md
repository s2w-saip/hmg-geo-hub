# 관리자(admin) 모듈 설계

작성: 모듈 설계 리드 (2026-09-27) · 기준: DESIGN-CONTRACT v2, DB-v2.sql(정본), DECISIONS G-18·G-23

## 1. 개요

관리자 모듈은 `/v1/admin` 아래에서 표준 카탈로그(AD-1, 고객 관심 키워드·소스 AD-1b), 엔티티 레지스트리(AD-2), 인용 출처 오버라이드(AD-3), 회차 운영(AD-4), 계정·권한(AD-5)을 제공한다. 모든 엔드포인트는 활성 admin 전용이다.

핵심 원칙은 세 가지다.

1. **쓰기 패턴 하나**: app 원본 쓰기 + 명시적 감사 + (판정 입력이면) `app.judgment_change` 요청을 한 트랜잭션에서 커밋한다. `rd`·`ing` 반영은 적재기가 비동기로 한다(A17, B4). Scope 반영은 `app.scope_outbox` 로만 한다(계약 §5).
2. **관리 창 규칙 하나**: 사실 표를 읽는 관리 화면(AD-2 목록, AD-3 후보)은 기간이 필수다. 기본값은 최신 노출 회차이고, 회차 1개를 넘으면 `admin_long`(30s)을 쓰며, 최대 366일이다(G-18 a).
3. **D8 준수**: 요약 표·캐시·카운터를 만들지 않는다. 필요한 것은 차원 속성 투영 2개(제안)와 인덱스 1개(제안)뿐이다.

## 2. 엔드포인트 명세

### 2.2 AD-1b 고객 관심 키워드·표준 소스 (`/v1/admin/interest`)

keywords·sources 각각 GET·POST·PATCH·DELETE. 물리 삭제이고 감사 표는 없다(현행 동일). 판정 입력이 아니라 judgment_change 도 쓰지 않는다. 읽기 소비자는 intent 모듈이다.

### 2.3 AD-2 엔티티 레지스트리 (`/v1/admin/entities`)

- GET: surface 필수, from/to(기본 최신 노출 회차), q, role(own|excluded|competitor), sort(brand_answers_desc|name_asc), 키셋.
  - 행 = `rd.dim_entity`(entity_type='Brand') ∪ 레지스트리에만 있는 엔티티(현행 entity-registry.ts:115-127 동작 보존).
  - 수치 = 귀속 표시 브랜드 단위 `brand_answers`, `brand_mentions`(G-23 a). 엔티티별 수는 제공하지 않는다.
- PUT /{entity_id}: body {role, brand_code(own 필수), name?}. own·excluded 는 upsert, competitor 는 행 삭제. 이어서 `judgment_change('entity', payload{op, old, new})`. 응답은 WriteAccepted와 재구축 가능 경고다.

```sql
WITH w AS (
  SELECT brand_key, count(DISTINCT answer_key)::int AS answers, sum(mention_count)::int AS mentions
  FROM rd.answer_brand
  WHERE surface = :s AND round_date BETWEEN :from AND :to
  GROUP BY brand_key)
SELECT e.entity_id, e.entity_type, coalesce(r.name, e.rep_name) AS name, bn.name AS brand_name,
       coalesce(r.role, 'competitor') AS role, r.brand_code,
       coalesce(w.answers, 0) AS brand_answers, coalesce(w.mentions, 0) AS brand_mentions
FROM rd.dim_entity e
LEFT JOIN rd.dim_brand_name bn USING (brand_key)
LEFT JOIN w USING (brand_key)
LEFT JOIN app.entity_registry r ON r.entity_id = e.entity_id
WHERE e.entity_type = 'Brand' [AND role·q 조건] [AND 키셋]
ORDER BY brand_answers DESC, e.entity_id LIMIT :limit + 1;
```

### 2.4 AD-3 인용 출처 오버라이드 (`/v1/admin/citation-overrides`)

- GET /: 오버라이드 목록((updated_at, domain) DESC 키셋).
- GET /candidates: surface 필수, from/to(기본 최신 노출 회차), limit(기본 500, 최대 5,000), category[](선택). `rd.citation`(cit_in) ⋈ `rd.dim_source` 를 domain 단위로 센다. 오버라이드 도메인은 0건이어도 FULL OUTER JOIN 으로 포함한다(category_src=1).
- GET /categories: `app.citation_category` 전체.
- PUT /{domain}: body {category_key, note(500자 이하)}. upsert 후 `judgment_change('citation_override', subject_texts=[domain], payload{old, new})`.
- DELETE /{domain}: 삭제 후 judgment_change(new=null). 없으면 404.

### 2.5 AD-4 회차 운영 (`/v1/admin/cycles`, `/v1/admin/jobs`)

현행에는 화면이 없고 운영자 스크립트(scripts/summary/hide-cycle.ts, hide-cycle-warning.ts, 0054 드롭 SQL)만 있다. 이를 요청 API 로 옮긴다.

| 메서드 | 경로 | 요청 kind·payload |
| --- | --- | --- |
| GET | /cycles?surface&from&to&project | 읽기: rd.cycle(cycle_pick_idx) + 대기 중 요청 |
| GET | /cycles/{cyc_key} | 읽기: 상세 + 진행률(rd.job 분포, rd.answer gap 수) |
| POST | /cycles/{cyc_key}/hide | cycle_admin {cycle_id, op:hide, hidden_scope, reason} |
| POST | /cycles/{cyc_key}/unhide | cycle_admin {cycle_id, op:unhide} |
| POST | /cycles/{cyc_key}/close | cycle_admin {cycle_id, op:close, reason} |
| PUT | /cycles/{cyc_key}/view-date | cycle_admin {cycle_id, op:set_view_date, view_date} |
| GET | /jobs/{job_id}/registry | 읽기: rd.v_answer_registry 등치 조회 |
| POST | /jobs/{job_id}/anchor-pin | anchor_pin {job_id, anchor, reason} |
| POST | /jobs/{job_id}/drop | answer_drop {job_id, reason}, confirm 필수 |

- 모든 쓰기는 `dry_run=true` 를 지원한다. dry_run 이면 hideCycleWarnings 이식 결과(같은 주 잔여 비숨김 회차 수, 더 최신 비숨김 회차 수로 계산)와 대상 상태만 돌려준다. 선택 필드 `expected_generation` 이 rd.cycle.generation 과 다르면 409.
- hidden_scope 는 DDL 어휘(all|citations|mentions)를 받는다. mentions 는 현행 스크립트에 없는 신규 범위다.

### 2.6 AD-5 계정·권한 (`/v1/admin/users`)

- 목록·단건·생성·수정·삭제·이력, 그리고 reset-password(신규 기능이라 승인 전 비활성).
- PATCH 가드 순서: vendor 인데 operator≠none 이면 422 → admin 강등이 자기 자신이거나 남은 admin 이 0명이면 409 → menu_groups 가 역할 허용 그룹의 부분집합이 아니면 422 → If-Match row_version 불일치면 409 → CHECK 위반은 제약명과 함께 422.
- admin 생성·승격 시 scope_all=true 를 강제한다(ua_scope_nonempty 통과).
- 생성: Supabase createUser → DB 트랜잭션(user_account + permission_audit_log) → 실패 시 auth 보상 삭제. 삭제: auth 선삭제 → DB 삭제 + 감사.

### 2.7 공통: 변경 요청 큐 (`/v1/admin/changes`)

GET 목록(kind[]·status[]·requested_by·subject, change_id DESC 키셋)과 GET /{change_id}. 모든 비동기 쓰기의 반영 확인 경로이자 관리자 판정 변경 원장이다.

## 3. 공통 구성요소

- **require_admin**: JWKS 검증 후 user_account 에서 role='admin' AND status='active' 를 확인한다.
- **rw_tx**: api_rw, `set_config('app.actor_id', uid, true)`, `SET LOCAL statement_timeout='30s'`.
- **ro_conn / admin_window**: api_ro(5s) 또는 admin_long(30s)을 고르고 기간 기본값을 채운다.
- **enqueue_change**: judgment_change INSERT. 같은 subject 에 대기 중 요청이 있으면 409.
- **audited_catalog_write / audited_user_write**: DB-v2 에 트리거가 없어 앱이 감사·요청·outbox 를 명시적으로 쓴다.
- **봉투**: `{data, meta:{next_cursor, ignored_filters, dropped_filters, surface?, as_of?, generation?, default_window?}}`. 비동기 쓰기는 `WriteAccepted{change_id, propagation}`.
- **오류**: `{error:{code, message, details}}`. 코드는 403·404·409·422·502.
- **rd 검증 규약**: api_rw 는 rd 를 못 읽는다. 쓰기 전 검증은 api_ro 로 먼저 읽고, 최종 검증은 적재기가 한다.

## 4. 읽기 스키마

**app**: prompt, prompt_audit_log, project, brand, standard_keyword, standard_source, scope_outbox, judgment_change, entity_registry, citation_category, citation_domain_override, user_account, permission_audit_log, rhq_region, website_site.

**rd**: dim_prompt, dim_project, dim_entity, dim_brand_name, answer_brand, citation, dim_source, cycle, surface_generation, job, answer, v_answer_registry.

`ing` 은 읽지 않는다(A17).

제안(D8 판정 포함):

- **P1** `rd.dim_project.regions`: 시장 어휘. 차원 투영이라 허용.
- **P2** `rd.cycle.hidden_reason`: 갭 슬롯 판단. 원장 투영이라 허용.
- **P3** INDEX `app.permission_audit_log(target_user_id, created_at DESC)`: 인덱스라 허용.
- **P4** `rd.v_cycle_ledger` 뷰: D8 예외 ③ 비노출 원칙과 충돌하므로 결정이 필요하다. 기본은 보류.
- **P5** outbox 처리 롤 GRANT: 적재 모듈 소관.

기각·보류:

- rd.answer_stance(entity_key) 인덱스: G-23 으로 기각.
- user_account role·status 인덱스: 규모가 작아 기각.
- app.prompt 커버링 인덱스: 실측 후 결정(보류).

## 5. 권한

- 모든 경로에 require_admin 을 적용한다. 권한 교집합(§9)은 적용하지 않는다. 관리자는 전량을 보고 dropped_filters 는 항상 비어 있다.
- 메뉴 그룹 게이트 require_menu_group('admin')(관리 메뉴 없는 admin 403 menu_forbidden, 현행 route-policy /admin 이하 group admin):
  AD-1 카탈로그(prompts·bulk·reference, bg-admin 검증 D3 에서 추가)·AD-3·AD-4·AD-5·GA4·키워드 도구는 건다.
  AD-1b 고객 관심(interest)·AD-2 엔티티(registry) 라우터는 2026-09-28 기준 require_admin 만이다(별도 항목).
- 커넥션 롤:
  - 목록·기본 창은 api_ro.
  - 확장 창은 admin_long.
  - 쓰기는 api_rw 이고, app.actor 미설정이면 DB 가 거부한다.
- 비밀값: Supabase 서비스 롤 키는 런타임 env 로만 주입하고 로그·응답에 남기지 않는다. 임시 비밀번호는 응답에만 한 번 싣는다.

## 7. 대조 방법 (A13 병행 운영)

- **AD-1**: 현행 listStandardCatalog(lib/db/repositories/standards.ts:160)와 prompt_id 집합, 필드 값, stats 6종을 비교한다. 엑셀은 export → import preview 왕복 diff 0 을 확인한다. 쓰기 경로는 같은 편집에 대해 prompt_audit_log changes 동등성과 judgment_change·outbox 행 생성을 단언한다.
- **AD-1b**: 목록 동등성을 확인한다.
- **AD-2**: 엔티티 집합과 역할이 일치해야 한다. 수치는 정의가 바뀌었으므로(엔티티 발생 합에서 표시 브랜드 답변·언급 수로, 기간 필수) mig.known_diff 에 등록하고 A4 1회 고지를 한다.
- **AD-3**: 도메인별 현재 분류(category·source)가 현행 listDomainCuration(citation-overrides.ts:137)과 일치해야 한다. 상위 N 순위 차이는 기간 필수로 생긴 known_diff 로 처리한다.
- **AD-4**: 현행 화면이 없다. 대신 같은 cycle 에 대해 스크립트 실행 결과 상태(hidden_scope·hidden_reason·view_date·status)와 API 요청이 반영된 뒤의 rd.cycle 상태가 같은지 비교하고, hideCycleWarnings 테스트를 이식해 통과시킨다.
- **AD-5**: 계정 목록 동등성, 가드 3종(vendor·자기 강등·마지막 admin) 회귀 테스트, permission_audit_log before/after 스냅샷을 단언한다.

## 8. 열린 질문

1. 적재기의 judgment_change 반영 SLA(다음 20분 적재인지 별도 claim 루프인지)와 rd.cycle.status 코드표(적재 모듈).
2. outbox 워커 주체와 GRANT(P5). 생성 직후 미추적 표시를 UX 로 허용하는지.
3. 감사 트리거 채택과 앱 명시 쓰기 중 무엇을 정본으로 할지. DB-v2.sql:112·155 주석 정리 필요.
4. P4(회차 원장 완료율 관리자 노출) 채택 여부. 계약 D8 ③ 과 긴장한다.
5. 관리 화면(admin_long 창)을 1초 SLO 대상에서 빼는지(G-23 b 문언은 예외 시 SLO 제외를 명시).
6. /admin/ga4·/admin/keyword-tools 의 배정 모듈과 단위 ID.
7. rd.dim_source.domain 이 오버라이드 domain 과 같은 정규화(소문자, www. 제거)인지(미확인). 다르면 AD-3 FULL OUTER JOIN 키가 어긋난다.
8. category_src 1~6 배지 라벨 정본(social 분리)과 citation_category 12종·13종 차이(미확인).
9. AD-5 reset-password 와 menu_groups 편집 UI 는 신규 기능이라 이관 범위에 넣을지. is_qa_reviewer 부여 위치.
10. 답변 드롭 되돌리기(드롭 해제) API 필요 여부. v2 는 rd.job.dropped 플래그라 가역일 수 있다(적재 모듈 확인).
