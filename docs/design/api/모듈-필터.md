# 필터 모듈 설계 (filters: F-1, F-2)

기준: 설계 공용 계약 v2(DESIGN-CONTRACT.md), 확정 DDL db/DB-v2.sql, 현행 코드 7639b9e.

## 1. 개요

필터 모듈은 읽기 화면의 필터 패널과 달력이 쓰는 옵션을 낸다. 지표를 계산하지 않는다. 엔드포인트는 둘이다.

| ID | 메서드 | 경로 | 역할 | 위험 |
| --- | --- | --- | --- | --- |
| F-2 | GET | /v1/filters/dates | 선택 가능 회차 날짜, 스냅샷 기준일, 최초 회차일, 프리셋 끝점 | low |
| F-1 | GET | /v1/filters/options | 브랜드×국가×언어 매트릭스, 국가, 엔진, 택소노미, 출처 카테고리, 커스텀 필드 | 스냅샷 low, 기간 medium, 1년 high |

명세 §8 초안은 `GET /v1/filters?surface=` 단일 경로였다. 여기서는 비용 등급이 달라 둘로 나눈다. 두 호출은 선후 의존이 없다(옵션의 기본 창은 서버가 스스로 해석).

이 모듈은 `core.window.resolve_window`(창 해석)의 최초 소비자다. 이후 모든 읽기 모듈이 같은 함수를 쓰므로 여기서 정의를 확정한다. 그래야 화면 전체의 as_of 가 한 값이 된다.

## 2. 엔드포인트 명세

### 2.1 F-2 GET /v1/filters/dates

- 쿼리: `surface`(global|website|project, 필수), `project_id`(uuid, surface=project 일 때 필수), `family`(mentions|citations|all, 기본 mentions). 공통 필터 축은 전부 ignored_filters 로 알린다(from/to 포함: 날짜 목록은 옵션 창의 입력이라 창 제한을 걸지 않는다).
- 응답 data: `surface`, `latest_round_date`(스냅샷 기준일, R05), `first_round_date`(게이트 통과 최초 회차일, 프리셋 클램프·달력 min 용), `dates`(내림차순, 최대 400, 서버 상수), `dates_truncated`, `presets`([{preset: weekly|biweekly|monthly|yearly, from, to}]).
- 구현: core `cycles.selectable_round_dates(surface, project_keys, family, limit)` 가 아래 SQL 을 한 문장으로 낸다(날짜·전체 개수·최초일·generation).
- 규칙: R01 servable, R03 `view_date IS NOT NULL AND view_date <= rd.today_kst()`, R04 `hidden_scope <> ALL(:excluded)`. excluded 는 family 별로 mentions {1,3}, citations {1,2}, all {1,2,3}이다. 현행 anchorNotHiddenSql(scope-answer-anchors.ts:276)과 현행 값 공간에서 동치다.
- SQL:
```sql
WITH picked AS (
  SELECT DISTINCT round_date FROM rd.cycle
  WHERE surface = :s AND project_key = ANY(:pks) AND servable
    AND view_date IS NOT NULL AND view_date <= rd.today_kst()
    AND hidden_scope <> ALL(:excluded))
SELECT round_date, min(round_date) OVER () AS first_rd, count(*) OVER () AS n
FROM picked ORDER BY round_date DESC LIMIT 400;
```
- presets: presetRange(dimension-filter-panel.tsx:1852)의 Python 이식. end = latest_round_date, min_day = first_round_date.

### 2.2 F-1 GET /v1/filters/options

- 쿼리: `surface`(필수), `project_id`(surface=project 필수), `from`·`to`(둘 다 있거나 둘 다 없음, 아니면 422). 사용자 선택 축(brand[]·country[]·lang[]·engine[]·funnel[]·brand_presence[]·list_type[]·depth1~3[]·source[])은 결과를 좁히지 않는다. 패널이 draft 로 좁히므로(§4 규칙 5, 현행 listMeasuredScopeMatrix scope-aggregates.ts:7636 과 같은 설계) meta.ignored_filters 로 알린다.
- 옵션 창: from/to 가 있으면 그 기간, 없으면 F-2 와 같은 스냅샷. 숨김 배제는 가장 느슨한 {1}(all)만 쓴다(현행 OPTION_HIDDEN_FAMILY='mentions', scope-aggregates.ts:2038 의 '옵션 ⊇ 데이터' 취지).
- 응답 data:
  - `geo_matrix`: [{brand: brand_code|null, region: code, lang: bcp47|null}]. brand null 은 공통(엄브렐러·무브랜드). 필드 이름은 현행 프론트
    계약 `MeasuredScopeCombo {brand, region, lang}`(front/components/dash/dimension-filter-panel.tsx:643)을 따른다(값 = 국가 코드).
  - `regions`: [{code, area: 권역 코드|null, kind: iso|virtual_brand}]. 숨김 국가는 뺀다. 권역 코드 = core `Refs.area_code`(rd.dim_region).
  - `engines`: [{code, is_default}]. 창 안에서 측정된 엔진.
  - `catalog`: {funnel, brand_presence, list_type, depth1, depth2, depth3: [{code, parent_code}]}.
  - `source_categories`: [{slug, name, ord}].
  - `custom_fields`: [{field_id, label, values}] (surface=project 만).
- 매트릭스 SQL(global·project, 1단계 사실 표):
```sql
SELECT geo_key, lang_key, cat_mask
FROM rd.answer
WHERE surface = :s AND round_date BETWEEN :lo AND :hi AND cyc_key = ANY(:cyc_keys)
  AND cit_in AND geo_key = ANY(:geo_keys)          -- 국가 무제한이면 이 항 생략
GROUP BY 1, 2, 3;
```
  2단계(수백 행 소집합)에서 한다: geo_key 0 과 숨김 국가를 빼고, 브랜드 스코프 교집합(`(cat_mask & (brand_mask|umbrella_bit)) <> 0 OR cat_mask = 0`)을 걸고, 비트를 brand_code 로 전개한다(엄브렐러 비트와 0 은 null). 비트 식은 사실 표 WHERE 에 두지 않는다(계약서 §3).
- website 매트릭스: 같은 1단계를 surface=2 로 돌리고 project_key 를 함께 뽑는다. brand·country 는 rd.dim_project.site_brand_bit·site_geo_key 에서, lang 은 answer.lang_key 에서 온다. rd.dim_country(kind='virtual_brand') 중 창 안 사이트 브랜드와 맞는 가상 코드를 덧붙인다(현행 withWebsiteBrandGeoCombos, website-virtual-geo.ts:57). 숨김은 app.hidden_market(surface='website')이다.
- 엔진·출처 카테고리: DISTINCT 전수 스캔 대신 차원 행마다 EXISTS 조기 종료를 쓴다.
```sql
SELECT e.code, e.is_default FROM rd.dim_engine e
WHERE EXISTS (SELECT 1 FROM rd.answer a WHERE a.surface = :s AND a.round_date BETWEEN :lo AND :hi
                AND a.cyc_key = ANY(:cyc_keys) AND a.cit_in AND a.engine_key = e.engine_key);
SELECT c.slug, c.name, c.ord FROM app.citation_category c
WHERE EXISTS (SELECT 1 FROM rd.citation x JOIN rd.dim_source s ON s.source_key = x.source_key
              WHERE x.surface = :s AND x.round_date BETWEEN :lo AND :hi AND x.cyc_key = ANY(:cyc_keys)
                AND x.cit_in AND s.category_key = c.category_key) ORDER BY c.ord;
```
- 택소노미: global·website 는 rd.catalog_entry(루트 카탈로그)를 dim_prompt 와 조인하지 않고 읽는다(prompt_key NULL 행 보존). 브랜드 스코프 계정은 brand_bit ∈ 스코프 ∪ 엄브렐러로 거르고, dim_taxon 으로 code·parent 를 해석한다. project 는 app.prompt(project_id, deleted_at IS NULL)의 brand_presence·list_type·depth1~3·funnel_stage DISTINCT 다(현행 listCatalogTaxonomy(id), standards.ts:394). 택소노미는 측정 창과 무관하다(현행 계약).
- custom_fields: app.project_custom_field(NOT archived) ⋈ app.prompt_custom_field_value DISTINCT value.

### 2.3 공통 응답 meta

`{surface, mode: snapshot|period, as_of, cycles: [round_date...], generation, ignored_filters: [...], dropped_filters: {}, suppressed: {}}`. suppressed 는 명세 §8 대로 객체다. 내부 정수 키(cyc_key·brand_bit·geo_key)는 어떤 필드에도 싣지 않는다.

## 3. 공통 구성요소

- 라우터: `APIRouter(prefix="/v1/filters")`, 모듈 파일 router.py · schemas.py · repo.py · presets.py.
- core.window.resolve_window: 스냅샷 = 허용 project_keys 의 게이트 통과 max(round_date) 한 날의 회차 전부. 그날 회차가 없는 프로젝트는 결손으로 돌려준다(현행 pickWebsiteCycles, summary-cycles.ts:207 함대 규칙). 기간 = round_date BETWEEN from AND to. 반환 상수(cyc_keys, lo, hi)를 사실 표 질의에 그대로 넣는다. 함대 앵커 불일치는 서버 로그로 남긴다(현행 logFleetAnchor, lib/scope/server.ts:5399).
- core.window.HIDDEN_EXCLUDE: mentions {1,3}, citations {1,2}, all {1,2,3}, options {1}.
- core.scope.get_scope: app.user_account → Scope. 국가 = effectiveScopeCountries(lib/rhq/index.ts:87) 규칙: countries 우선, 없으면 regions 확장, 둘 다 없으면 무제한. 브랜드 스코프는 엄브렐러 포함(standard-filters.ts:64). 계산이 비면 403.
- core.scope.resolve_surface_projects: global 루트 1건, website 스코프 교집합 사이트들(작은 dim_project 위 계산), project 는 멤버십 확인 후 1건. 미존재·비멤버는 똑같이 404.
- core.filters.CommonFilterQuery: 공통 필터 모델. from/to 쌍 검증(422)을 포함한다.
- core.meta.build_meta.
- filters.presets.preset_range: TS 원본과 골든 테스트로 동치를 보장한다.

## 4. 읽기 스키마

- rd: cycle, surface_generation, today_kst(), dim_project, answer(surface, round_date, cyc_key, geo_key, lang_key, engine_key, cat_mask, cit_in), citation(surface, round_date, cyc_key, source_key, cit_in), dim_source, dim_country, dim_region, dim_lang, dim_engine, catalog_entry, dim_taxon.
- app: user_account, rhq_region_country, brand, project, project_member, prompt, project_custom_field, prompt_custom_field_value, citation_category, hidden_market.
- ing: 읽지 않는다.
- 인덱스: cycle_pick_idx, cycle_project_idx, answer_rd_brin, answer_cell_idx, answer_p_proj_idx, cit_source_idx, cit_rd_brin, dim_source_category_idx, prompt_project_live_idx. 모두 DB-v2 에 있다.
- 제안 컬럼·인덱스: 없음. 단위 설계의 이름을 DB-v2 카탈로그와 대조한 결과 불일치는 0건이다.

## 5. 권한

- 인증: A8, Supabase JWT 를 FastAPI 가 JWKS 로 검증한다.
- 스코프는 서버가 계산하고 클라이언트 입력으로 넓힐 수 없다. 옵션 API 는 사용자 선택을 받지 않으므로 dropped_filters 는 항상 비어 있다.
- global: 루트 프로젝트. 달력은 브랜드 무관 축이다(현행). 옵션은 국가·브랜드 스코프로 거른다.
- website: 사이트 브랜드·지오가 스코프와 교집합인 project_keys 만 쓴다.
- project: app.project_member(status='active') 확인. 멤버가 아니면 404(존재 누설 방지).
- 운영자 게이트는 적용하지 않는다(읽기 전용, 비용 액션 아님).

1년 경로의 대안(사전 집계 없이): (a) answer_cell_idx index-only 로 (prompt_key, geo_key) DISTINCT 후 dim_prompt 전개. 단 elig 게이트를 잃으므로 바깥에서 숨김·대상 시장을 다시 건다. (b) 리프 Parallel Append. 화면당 동시 호출(G-25)은 옵션 지연 로드(패널 열림 시)로 줄이는 안을 프론트 설계에 넘긴다.

## 7. 대조 방법

- 하네스 F06(국가 목록 + 엔진 정적 목록)과 달력 날짜 목록을 계정 스코프 조합(admin, hq, 브랜드 스코프, region, country)별로 비교한다.
- 의도된 차이를 먼저 등록한다: ① 기간 미지정 창이 '최근 7일 run'(scope-aggregates.ts:847-852)에서 최신 노출 회차로 바뀜 ② 웹사이트 옵션이 등록 기준(website-sites.ts:142·175)에서 측정 기준으로 바뀜 ③ 엔진이 정적(dimension-filter-panel.tsx:173)에서 측정 기반으로 바뀜.
- 불변식 테스트: 옵션 매트릭스의 모든 (brand, region, lang) 조합에 대해, 같은 창의 kpi API 가 그 조합으로 모수 > 0 을 낸다(옵션에 있으면 데이터가 있다).
  기준일: F-2 `latest_round_date(family) ≤ F-1 meta.as_of`. 최신 게이트 통과 회차가 그 family 로 숨겨지지 않았으면(hidden_scope 가 family 배제
  집합 밖이거나 1 이라 둘 다 직전 회차로 물러남) 같다. F-1 스냅샷 = core 함대 스냅샷(row 계열, {1}만 배제), F-2 = family 별(§8 열린 질문 3 의
  family 별 안). hidden_scope 3 은 Q18 예비값이라 운영에서 아직 갈리지 않는다.
- presets: TS presetRange 와 Python preset_range 를 골든 입력 수백 건으로 비교한다.

## 8. 열린 질문

1. 웹사이트 옵션을 측정 기준으로 바꾸면 첫 측정 전 신규 사이트가 옵션에서 사라진다. 제품 요구와 맞는가.
2. 엔진 옵션 측정 기반 통일: 운영진이 데이터 도착 전 엔진을 먼저 노출하고 싶은가(K-3 과 합의).
3. 스냅샷 숨김 계열: 현행 pickWebsiteCycles 는 모든 숨김을 배제하고(summary-cycles.ts:222-226 cycleNotHiddenSql), 달력은 family 별로 배제한다. 새 구조에서 스냅샷 기준일도 family 별로 둘지(인용 화면만 이전 회차) 확정이 필요하다. 이 설계는 family 별 안이다.
4. 스코프 반영 '수집 기간'(현행 standardCollectionDates, scope-aggregates.ts:9601)은 어느 모듈이 내는가. F-2 first_round_date 는 스코프 무관 함대 값이다.
5. cat_mask 적재 규칙: 공통(무브랜드) 프롬프트는 0 인가, 엄브렐러 비트인가. 확인 전까지는 둘 다 공통으로 통과시킨다.
6. (해소, core 5라운드) project 표면에 표준 숨김 지역(hidden_standard)과 계정 국가 스코프를 적용하지 않는다. 현행 프로젝트 경로는 프로파일
   스코프를 주입하지 않는다(front app/api/scope/signal-prompts/route.ts:26-33, answer/route.ts:36-40, lib/scope/hidden-regions.ts:8-9).
   global 의 숨김 표준 국가는 데이터 경로에서 적재 판정 elig 로 빠진다(seed-40-facts.sql elig, 현행 answerWhere scope-aggregates.ts:2234-2237 와 동치).
7. 옵션 지연 로드(G-25 완화)를 프론트에서 채택하는가.
8. 1년 옵션이 RDS 실측에서 1초를 넘으면 대안 (a) 채택 여부. 대안 (a)는 옵션이 데이터보다 넓어지는 방향(죽은 옵션 가능)이다.
