# 프로젝트 모듈 설계 (PJ-1 ~ PJ-4)

작성: 모듈 설계 리드 · 기준: DESIGN-CONTRACT v2, DB-v2.sql(2026-09-27) · 현행 코드: hmg-geo 통합 프리뷰 7639b9e

## 1. 개요

프로젝트 모듈은 고객 프로젝트(app.project kind='customer')의 생애주기를 다룬다: 프로젝트 본체(PJ-1), 멤버십(PJ-2), 프롬프트와 측정 실행(PJ-3), 설정(PJ-4). 집계 지표(M01~M12)를 계산하지 않는 app 스키마 CRUD 모듈이며, rd 를 읽는 곳은 프롬프트 영향 미리보기(PJ-3)와 Scope 연결 진단(PJ-4) 두 곳뿐이다.

설계 결론 요약:
- Scope 반영(프로젝트 생성·수정·삭제, 프롬프트 발행·중지·재개·삭제, 엔진 스케줄)은 전부 `app.scope_outbox` 비동기 적재다. API 는 외부 HTTP 를 동기 호출하지 않는다(계약 §5, DB-앱-도메인.md:42).
- 판정 입력 변경은 `app.judgment_change` 로 적재기에 넘긴다. app.project·app.prompt 는 DDL 주석이 트리거 몫으로 선언했고, 나머지(tracked_*, owned_base, tracked_url)는 API 가 명시 INSERT 한다.
- PJ-4 는 단위 산출물이 비어 있어(더미 "test") 설계 리드 보충 초안이다. 단위 설계 재실행이 필요하다.

## 3. 엔드포인트 명세

### PJ-1 프로젝트 (`/v1/projects`)
- `GET /v1/projects?q=&cursor=&limit=`(기본 50, 최대 100): kind='customer'. 비관리자는 `project_member(status='active')` JOIN(project_member_user_idx), admin 은 JOIN 없음(현행 projects/page.tsx:40-41). 정렬 (created_at DESC, project_id DESC) 키셋. 항목: project_id, name, description, domain, brand_code, country_code, scope_project_id, ga4_property_id, ai_engines, my_role, created_by, created_at, updated_at.
- `POST /v1/projects`: body {name, description?, domain?, brand_code?, country_code, ai_engines[1..]}. 게이트 canCreateProject(operator=global 또는 admin, operator-policy.ts:21) + 국가·브랜드 스코프 검증(scope-policy.ts:286). 한 트랜잭션: INSERT app.project → INSERT project_member(owner, active, accepted_at=now()) → domain 있으면 owned_base 1행 + resync_project_domain → INSERT project_engine_history(첫 행) → outbox(project:create, payload{project_id,name,domain,brand_code,country_code}) → outbox(schedule:set_targets, {engines}). 201.
- `GET /v1/projects/{id}`: 상세 + my_role + scope_linked(bool). require_project(member).
- `GET /v1/projects/by-scope/{scope_project_id}`(BG-36): 고객 프로젝트(admin ∨ 활성 멤버) → {kind:"project", project_id}, 없으면 웹사이트 사이트(표면·브랜드·국가 스코프 안) → {kind:"website", brand_code, country_code}, 그 밖 404 하나(본문 동일, DECISIONS-API B-1·B-2).
- `GET /v1/projects/creation-options`(BG-37): {brands, countries, brand_locked, engines, default_engines}. 게이트 = POST 와 같음. 순서는 DECISIONS-API B-3.
- `PATCH /v1/projects/{id}`: {name?, description?, brand_code?, ga4_property_id?(숫자만, setting/_actions.ts:188-196)}. require_project(owner). brand_code 변경 시 rebuild_tracked_brand, outbox(project:update). project_setting judgment_change 는 트리거 몫.
- `DELETE /v1/projects/{id}`: body {confirm_name}. require_project(owner). SELECT ... FOR UPDATE → 이름 대조(불일치 409 name_mismatch) → DELETE app.project(FK CASCADE, DB-v2.sql:121-176) → outbox(project:delete, {scope_project_id}) → access_audit(data_access). 204.

### PJ-2 멤버
- `GET /v1/projects/{id}/members`: pending+active, 정렬 role(owner 먼저), invited_at. user_account 2회 PK 조인(email, display_name, invited_by_email). require_project(member).
- `POST /members` {email}: 가입자 없음 404 invitee_not_found, 본인 400 self_invite, 기존 활성 멤버 409 already_member, 초대 대기 409 already_invited(core 9 U9-1, details.status 는 호환용), 동시 경합은 재조회해 둘 중 하나(그 사이 지워졌으면 409 retry_conflict). INSERT(viewer, pending) + member_audit(invite, 'role=viewer'). require_project(owner). 이메일 발송 없음(현행 Q5(a) member/_actions.ts:113-114 계승, 열린 질문).
- `PATCH /members/{user_id}` {role}: FOR UPDATE, active 만(409 not_active), 같은 역할 409, 강등 시 활성 owner 수 ≤1 이면 409 last_owner_cannot_demote. + member_audit(promote|demote).
- `DELETE /members/{user_id}?expect=pending|active`: 본인 400, owner 409 cannot_remove_owner(현행 member/_actions.ts:159-164), pending→cancel_invite, active→remove. 204. expect(core 9 U9-2, 선택): pending = 초대 취소 전용(활성이면 409 not_pending), active = 제거 전용(대기면 409 not_active). 상태 확인은 대상 행 FOR UPDATE 안이라 조회-삭제 경합 창이 없다.
- `POST /members/me:accept`, `POST /members/me:reject`: UPDATE/DELETE ... WHERE user_id=세션 AND status='pending', 0행이면 404 no_pending_invite. + member_audit(accept|reject).
- `GET /v1/projects/{id}/member-audit?cursor=&limit=`(기본 20, 최대 200): (created_at DESC, audit_id DESC) 키셋. 제안 인덱스 필요.
- `GET /v1/me/project-invites`: project_member_user_idx(user_id, status='pending') + app.project 이름.

### PJ-3 프롬프트
- 후보: `GET /prompt-candidates`, `POST /prompt-candidates:select` {candidate_ids[]}(승격, 후보 유지), `DELETE /prompt-candidates/{cid}`, `POST /prompt-candidates:bulkDelete`.
- `GET /prompts?status[]=&kind=&q=&field_id=&field_value=&cursor=&limit=`: prompt_project_live_idx(project_id, created_at) 키셋, 태그값은 prompt_id = ANY(:page_ids) 로 1회 조립. 항목: prompt_id, text, kind, status, brand_code, category, prompt_type, lang, regions, scope_prompt_id, created_at, updated_at, tags{field_id: value}.
- `POST /prompts` {text}(줄바꿈 분리), `PATCH /prompts/{pid}`(text 는 draft 만, 409 prompt_not_draft), `DELETE /prompts/{pid}`(draft ∧ 미발행만).
- `GET /prompts/{pid}/lifecycle-impact`(Owner, api_ro): 아래 §6 쿼리. scope_prompt_id NULL 이면 전부 0.
- `POST /prompts/{pid}:pause`(Owner): status ∈ {queued,running,done,failed} 만, 공유 행 >0 이면 409 shared_prompt(현행 :283-291). outbox(prompt:disable) + status='paused' + access_audit.
- `POST /prompts/{pid}:resume`(operate): paused 만, outbox(prompt:enable) + status='done'(현행 :339).
- `POST /prompts/{pid}:hardDelete`(Owner): 공유 0 이면 outbox(prompt:delete; paused 가 아니면 disable 선행 의미 포함) + deleted_at=now(); 공유 >0 이면 deleted_at 만. 트리거가 judgment_change('catalog', 옛 scope_prompt_id) 를 남기고 적재기가 rd·ing 정리.
- `POST /prompts:execute`(operate): 대상 = draft ∪ (queued ∧ scope_prompt_id NULL ∧ 미완료 outbox 없음). FOR UPDATE → 각 행 outbox(prompt:create, {prompt_id, text, brand_code, category, lang, regions, kind}) → status='queued'. 대상 0 이면 409. 202 {queued, skipped_pending}.
- `GET /prompts:export`(member, xlsx 스트림, access_audit download), `POST /prompts:import`(Owner, multipart, 행 상한 제안 5,000: 현행 상한 미확인).
- 커스텀 태그: `GET/POST /prompt-fields`, `:archive`, `:restore`, `DELETE`, `PUT /prompts/{pid}/fields/{fid}`, `POST /prompt-fields/{fid}:bulkSet`, `DELETE /prompts/{pid}/fields/{fid}`. 예약어는 API 상수(현행 RESERVED_FIELD_LABELS prompt/_actions.ts:681-686), UNIQUE(project_id, label) 위반은 409 duplicate.

## 6. rd 쿼리(2곳)

lifecycle-impact(:pk = rd.dim_prompt WHERE prompt_id = :scope_prompt_id):
```sql
WITH a AS (SELECT round_date, answer_key FROM rd.answer WHERE surface = 3 AND prompt_key = :pk)
SELECT (SELECT count(*) FROM a) AS answers,
       (SELECT count(*) FROM a JOIN rd.answer_brand b ON b.surface = 3 AND b.round_date = a.round_date AND b.answer_key = a.answer_key) AS mentions,
       (SELECT count(*) FROM a JOIN rd.citation c ON c.surface = 3 AND c.round_date = a.round_date AND c.answer_key = a.answer_key) AS citations;
```
shared_rows 는 app.prompt(prompt_scope_idx) 에서 별도 조회.

scope-link:
```sql
SELECT project_key FROM rd.dim_project WHERE scope_project_id = :sp;                 -- UNIQUE
SELECT round_date FROM rd.cycle WHERE project_key = :pk ORDER BY round_date DESC LIMIT 1;  -- cycle_project_idx
SELECT count(*) AS jobs, count(*) FILTER (WHERE served) AS served, max(measured_at) AS last_measured_at
  FROM rd.job WHERE surface = 3 AND round_date = :rd AND project_key = :pk;          -- job_round_idx 접두
SELECT op, attempts, next_attempt_at, done_at, last_error FROM app.scope_outbox
 WHERE aggregate = 'project' AND aggregate_id = :project_id ORDER BY created_at DESC LIMIT 5;  -- 제안 인덱스
```
state: unlinked | pending_link | link_error | no_data | partial(served < jobs) | healthy.

## 8. 성능(10배 가정)
- app 표 경로: 단일 프로젝트 행 수(멤버 수십, 프롬프트 수백~수천 추정, 미확인)라 폭 10배에도 페이지당 O(limit). 전부 low.
- lifecycle-impact: medium. 프롬프트 1개의 전 회차 answer 를 answer_prompt_idx 로 surface=3 전 leaf 에서 찾고 PK 접두 조인. 새 인덱스 없이 가능하나 실측 필요.
- scope-link: 최신 회차 1개 한정이라 low.
- 설정 화면: 묶음 GET 으로 2회 이내(G-25).
- D8: 사전 집계·캐시 없음. count 는 조회 시 계산.

## 9. 대조 방법
- 이 모듈은 F01~F07 지표 하네스 대상이 아니다. 계약 테스트로 대조한다: 현행 테스트(member/_actions.test.ts, _actions.audit.test.ts, prompt/_actions.execute.test.ts, prompt/_actions.custom-fields.test.ts, setting/_actions.test.ts·_actions.tracked.test.ts·_actions.engines.test.ts)의 불변식을 pytest API 테스트로 이식.
- 섀도 비교(읽기): 샘플 사용자별 프로젝트 목록 집합, 프로젝트별 멤버 집합·역할, 프롬프트 수·상태 분포, 커스텀 태그값, owned base·추적 URL·경쟁사·차종 집합을 현행 DB 와 신규 DB 에서 뽑아 일치 확인(이관 검증).
- lifecycle-impact 는 현행 promptImpact(scope-mirror.ts:567) 와 비교하되 단위 변경(answers·mentions)을 mig.known_diff 로 등록.
- by-scope 사이트 분기의 스코프 게이트(스코프 밖 사이트 = 404, 현행은 스코프 검사 없이 /website 로 redirect)를 mig.known_diff 로 등록(DECISIONS-API B-1). creation-options 선택지 순서는 서버가 DB 결정적 순서를 주고 어댑터가 현행 순서로 재정렬한다(B-3).
- 비동기 경로: 스테이징에서 생성 → outbox 드레인 → scope_project_id 회수 → execute → scope_prompt_id 회수까지 E2E 단언.

## 10. 열린 질문
1. 워커 계약: outbox op 어휘·payload 스키마, 순서(프로젝트 링크 전 프롬프트 create 지연), Scope 멱등 키 지원 여부(미확인).

3. 단순 삭제를 draft ∧ 미발행으로 좁히는 것에 대한 제품 확인.
4. 초대 이메일 실제 발송 여부(현행은 발송 없음).
5. 관리자 승계 액션의 member_audit_log.action 값(미확인)과 CHECK 목록.
6. 운영자 global 스코프 대조 도입 시 영향 사용자 목록.
7. import 행 상한(현행 상한 미확인).
8. PJ-4 는 보충 초안이므로 단위 설계자가 query_design·perf 를 재작성해야 한다.
9. 엔진 어휘를 rd.dim_engine 코드와 일치시킬지(현행 lib/scope/engines.ts 상수 계승 여부).
