# 프롬프트 모듈(prompts) 설계: P-1 카탈로그 · P-2 변경 이력

기준: 설계 공용 계약 v2(DESIGN-CONTRACT.md), 확정 DDL DB-v2.sql, 현행 코드 7639b9e. 작성 2026-09-27.

## 1. 개요

- 목적: 글로벌 표준 카탈로그와 웹사이트 카탈로그를 "무엇으로 측정하는가" 관점에서 열람하고, 글로벌 카탈로그의 변경 이력을 보여 준다. 지표(M01~M12)는 계산하지 않는다.
- 엔드포인트 2개, 모두 읽기 전용(api_ro). 쓰기는 관리자 카탈로그 모듈(/v1/admin/catalog)과 트리거 tg_catalog_change 소관.
- 현행 대응: 글로벌 = listStandardCatalogScoped(lib/db/repositories/standards.ts:287), 웹사이트 = listWebsitePromptsScoped·listWebsitePromptsForExport(lib/db/repositories/website-sites.ts:507·574), 이력 = promptAuditLogRepository.listGlobalScoped·listForPrompt(lib/db/repositories/prompt-audit-logs.ts:94·82).
- 화면: /standard/prompts(카탈로그 탭 + 변경 이력 탭 + 행별 타임라인 패널), /website/prompts(서버 페이징 표 + 엑셀 내려받기), /admin/standards/prompts(행별 타임라인 패널만 이 모듈 사용).

## 3. 공통 구성요소

- 라우터: APIRouter(prefix="/v1/prompts"), 경로 "" 와 "/history".
- 의존성: get_principal → require_surface_route → resolve_scope → 파라미터 모델 → 리포지토리.
  - require_surface_route: global·history = 역할 hq·region·country·admin(현행 STANDARD_VIEWERS route-policy.ts:28) ∧ 메뉴 그룹 standard. website = 여기에 website 역할 추가(WEBSITE_VIEWERS route-policy.ts:32) ∧ 메뉴 그룹 website. menu_groups NULL 은 무제한(route-policy.ts:335-338). csv 도 같은 경로.
  - ScopeContext: all, brands, countries_catalog(현행 effectiveScopeCountries lib/rhq/index.ts:87), countries_site(현행 effectiveCountries website-sites.ts:38).
- 술어 빌더(한 벌, 목록·csv·이력 공유)
  - catalog_brand_scope: scope.all 이 아니면 brand_code IS NULL OR brand_code = ANY(:umbrella_codes) OR brand_code = ANY(:scope_brands). 우산은 app.brand.is_umbrella.
  - catalog_market_scope: 3분기(standards.ts:237-261 이식).
  - catalog_market_filter: 요청값 정확 포함(prompt-markets.ts:110-118). 'x:' 의사코드는 스코프 검사 면제.
  - presence_effective: COALESCE(brand_presence, CASE WHEN brand_code IS NULL THEN NULL WHEN brand_code = ANY(:umbrella_codes) THEN 'unbranded' ELSE 'branded' END).
  - website_site_scope_cte: 사이트를 먼저 해석(10배 1,280행). 가상 브랜드 코드는 rd.dim_country(kind='virtual_brand') ⋈ app.brand(brand_bit = virtual_brand_bit) 로 브랜드 치환, 그 브랜드가 스코프에 있으면 허용(website-sites.ts:301-315 계승).
- 측정 렌즈 SQL 한 벌(website): visible_cycles + measure_meta_sql. 모양 A(페이지 키 = ANY)와 모양 B(전 범위 해시 집계)가 공유.
- 차원 캐시: rd.dim_engine, app.brand, 루트 project_id. 키 사전일 뿐 결과 캐시가 아니다(D8 무관). 세대 변화 시 무효화.
- 커서: base64url(JSON{v, sort, dir, filter_hash, key}). 불일치 422. last_measured NULL 은 '0001-01-01' 센티넬로 튜플 비교.

### 3-1. SQL 스케치

글로벌 목록

```sql
SELECT p.prompt_id, p.text, p.kind, p.scope_prompt_id, (p.scope_prompt_id IS NOT NULL) AS measured,
       p.brand_code, p.brand_presence, <presence_effective> AS brand_presence_effective,
       p.prompt_type, p.category, p.list_type, p.depth1, p.depth2, p.depth3, p.depth4,
       p.funnel_stage, p.lang, p.regions
FROM app.prompt p
WHERE p.project_id = :root_project_id AND p.deleted_at IS NULL
  AND <catalog_brand_scope> AND <catalog_market_scope>
  AND <요청 필터: brand·country·lang·funnel·presence·list_type·depth1~4·kind·measured·search>
ORDER BY p.depth1, p.depth2, p.depth3, p.text, p.prompt_id
LIMIT 50001;
```

웹사이트 모양 B(기본 뷰·csv)

```sql
WITH lo_hi AS (...)                        -- 요청 from/to 또는 [표면 최초 회차, rd.today_kst()], 먼저 조회해 상수로 박는다
, vis AS (SELECT c.cyc_key FROM rd.cycle c
          WHERE c.surface = 2 AND c.round_date BETWEEN :lo AND :hi
            AND c.view_date <= rd.today_kst() AND c.hidden_scope <> 1)
, m AS (SELECT a.prompt_key, count(*)::int AS answers, max(a.round_date) AS last_rd,
               array_agg(DISTINCT a.engine_key) AS engine_keys
        FROM rd.answer a
        WHERE a.surface = 2 AND a.round_date BETWEEN :lo AND :hi
          AND a.cyc_key IN (SELECT cyc_key FROM vis)
          AND a.engine_key = ANY(:engine_keys)           -- engine[] 있을 때만
        GROUP BY a.prompt_key)
, s AS (<website_site_scope_cte>)
, r AS (SELECT wp.website_prompt_id, wp.prompt_text, wp.target_url, wp.domain, wp.lang_code,
               wp.owned_base_url, wp.scope_prompt_id, s.brand_code, s.country_code
        FROM app.website_prompt wp JOIN s ON s.site_id = wp.site_id
        WHERE <lang·measured·search>)
SELECT r.*, COALESCE(m.answers, 0) AS answers, m.last_rd, m.engine_keys
FROM r
LEFT JOIN rd.dim_prompt dp ON dp.prompt_id = r.scope_prompt_id AND dp.surface = 2
LEFT JOIN m ON m.prompt_key = dp.prompt_key
WHERE (COALESCE(m.last_rd, '0001-01-01'), r.website_prompt_id) ... (:cursor)   -- 키셋, 방향은 dir 에 따름
ORDER BY COALESCE(m.last_rd, '0001-01-01') DESC, r.website_prompt_id ASC
LIMIT :limit + 1;
```

웹사이트 모양 A(네이티브 정렬): r 을 키셋 + LIMIT 으로 먼저 자르고, 그 페이지 scope_prompt_id 로 dim_prompt 를 = ANY 조회해 prompt_key(≤200)를 얻은 뒤 m 에 AND a.prompt_key = ANY(:keys) 를 더한다. total 은 SELECT count(*) FROM r 별도 1회.

이력

```sql
SELECT pal.audit_id, pal.prompt_id, pal.event_type, pal.changes, pal.actor_id, pal.actor_type,
       pal.batch_id, pal.created_at, ua.email AS actor_email, p.text AS prompt_text, p.brand_code AS prompt_brand
FROM app.prompt_audit_log pal
LEFT JOIN app.prompt p ON p.prompt_id = pal.prompt_id
LEFT JOIN app.user_account ua ON ua.user_id = pal.actor_id
WHERE pal.project_id = :root_project_id
  AND pal.created_at >= :from_kst AND pal.created_at < :to_kst_next
  AND pal.prompt_id = :prompt_id                     -- 지정 시
  AND pal.event_type = ANY(:event_types)             -- 지정 시
  AND <catalog_brand_scope(p)> AND <catalog_market_scope(p)> AND <요청 brand·country>
  AND (pal.created_at, pal.audit_id) < (:c_ts, :c_id) -- 다음 페이지
ORDER BY pal.created_at DESC, pal.audit_id DESC
LIMIT :limit + 1;
```

제안(확정 DDL 아님, 모두 보류)

- 제안 1: pg_trgm GIN(app.prompt.text 부분 인덱스 WHERE deleted_at IS NULL, app.website_prompt.prompt_text, app.website_prompt.target_url). D8: 인덱스라 위반 아님. 착수 조건: 검색 p95 200ms 초과.
- 제안 2: rd.answer (prompt_key, round_date) INCLUDE (engine_key, cyc_key). D8: 위반 아님. HOT: 두 열 모두 재판정 제자리 UPDATE 대상 아님. 착수 조건: 웹사이트 기본 뷰 1초 초과.
- 기각: app.prompt.excluded bool(제외 목록이 비어 있음).

DDL 대조: 단위들이 적은 이름은 모두 DB-v2.sql 에 실재한다. tg_catalog_change 는 주석만 있고 본문이 없다.

## 5. 권한

- 인증: A8(Supabase Auth JWT, FastAPI JWKS 검증). 계정 status='suspended' 는 401.
- 라우트: 표면별 역할 집합 ∧ 메뉴 그룹(3절). vendor 는 전 엔드포인트 403, website 역할은 website 표면만.
- 데이터 스코프(default-deny, 서버 계산 후 교집합)
  - 글로벌·이력: 브랜드 = 스코프 브랜드 ∪ 우산·NULL. 대상 시장 = countries_catalog 와 3분기 교집합(B1, 2026-09-03).
  - 웹사이트: 브랜드 = 스코프 브랜드 엄격 일치. 국가 = countries_site 교집합, 가상 브랜드 코드는 그 브랜드가 스코프에 있으면 허용.
  - 요청값이 스코프 밖이면 meta.dropped_filters 에 담고 버린다. 요청 축의 교집합이 비면 빈 결과(조건을 빼서 전체가 열리는 일이 없게 false 술어).
  - prompt_id 단일 조회도 같은 스코프(현행 listForPrompt 의 스코프 미적용 결함 해소).
- soft-delete 행은 뷰어 엔드포인트에서 항상 제외(관리자 카탈로그가 별도로 다룸). 이력은 삭제 이벤트를 그대로 보인다.
- csv 는 비용 액션이 아니라 운영자 게이트 없음. 다운로드 접근 감사는 AU-1 결정 후 연결.

| 웹사이트 모양 B(기본 뷰) | 가시 회차 전체 rd.answer_w(수백만 행대 추정, 현행 website 행 수 미확인) + 행 해시 조인 | surface=2 · round_date 범위 leaf 가지치기, 해시 집계 | high |
| csv | 모양 B + 최대 5만 행 직렬화 | 같음 | medium |
| 이력 | 90일 원장(관리자 저빈도 이벤트, 볼륨 미측정) | prompt_audit_project_idx 레인지 + LIMIT 조기 종료, prompt_id 모드는 prompt_audit_prompt_idx | low |

- 모든 rd 사실 표 질의에 surface = 2 와 round_date 범위를 준다(계약 §3). 가시 회차는 1,000 개를 넘을 수 있어 semi-join.
- api_ro statement_timeout 5s 가 상한. 모양 B 가 1초를 넘으면 제안 2, 기본 정렬 변경, 기본 렌즈 창 축소 순으로 검토(열린 질문 2).
- 사전 집계·매트뷰·결과 캐시는 쓰지 않는다(D8).

## 7. 대조 방법

기존 하네스(hmg-refactor-proto/harness, F01~F07)는 프롬프트 기능을 다루지 않는다. 아래를 추가한다.

- 계정 표본: admin(scope_all), hq(브랜드 1), region(권역), country(Hyundai·KR), website 역할, Hyundai N 브랜드 계정, 메뉴 그룹 제한 계정.
- F-P1g(글로벌): 계정별 현행 listStandardCatalogScoped 행 id 집합 대 새 응답 prompt_id 집합(완전 일치 기대), 순서 비교(동점 tie-break prompt_id 추가분만 차이 허용), 화면 필터 11종 조합 표본별 현행 filterRows 결과와 서버 필터 결과 일치.
- F-P1w(웹사이트): 계정·필터 조합별 total 일치, 네이티브 정렬 5키 첫 3페이지 id 순서 일치. 측정 메타(answers·last_measured·engines)는 허용 차이 목록(드롭 제외, R03 노출 게이트, measured_at 축에서 round_date 축) 외 불일치 0. 가상 코드 HYUNDAI-N 필터 결과 일치.
- F-P1c(csv): 현행 xlsx 의 행 집합·순서와 새 csv 일치, 상한 표식.
- F-P2(이력): 90일 전역 목록 audit_id 집합 일치(UTC 대 KST 경계 9시간 차이만 허용), prompt_id 타임라인 일치, 스코프 밖 prompt_id 는 새 구조에서 빈 결과(의도된 차이).
- 권한 레드팀: vendor 403, website 역할의 global·history 403, 메뉴 그룹 밖 403, 스코프 밖 브랜드·국가 요청이 dropped_filters 로 떨어지고 행이 늘지 않음.

## 8. 열린 질문

1. 글로벌 카탈로그 전량 응답 유지(현행 패리티, 10배 약 2.4만 행)냐, 화면 전환 시 서버 페이징으로 가느냐. 서버 페이징이면 현행 클라이언트 filterRows 를 서버 술어로 일원화할 수 있다.
2. 웹사이트 기본 정렬(last_measured desc)의 전 기간 집계 비용. 옵션: (a) 유지하고 제안 2 인덱스, (b) 기본 정렬을 prompt 로 변경(UX 변경), (c) 기간 무지정 시 렌즈를 최근 N 회차로 제한(answers 의미 변경).
3. 글로벌 카탈로그에도 answers·last_measured·engines 를 붙일지. 권장: 현행 패리티(measured 불리언만).
4. 엑셀: API 는 csv 만 내고 xlsx 변환·라벨(i18n)은 프론트(Next.js 라우트)에서 할지, FastAPI 가 xlsx 를 만들지. 고객 원문 요구는 엑셀(이노션 2026-09-11). 권장: 앞의 안(UI 문자열을 프론트에 둔다는 현행 경계 유지).
5. 측정 메타에 servable(발행) 게이트를 걸지. 현행은 걸지 않음(패리티로 미적용).
6. 스코프 국가 의미 두 벌(countries_catalog 대 countries_site)을 통일할지(auth 모듈 결정).
7. 웹사이트 카탈로그 변경 이력: website_prompt 감사 원장이 없다(judgment_change 'website_catalog' 만). 필요하면 별도 원장 제안.
8. actor_email 을 고객 계정에게 계속 노출할지(현행 계승).
9. tg_catalog_change 본문 구현 주체(관리자 카탈로그 모듈 또는 DB 보완).
10. 비회차 API 의 meta 규칙(mode 'catalog'·'audit', as_of null, cycles [], generation null, suppressed {})을 계약서 §8 에 반영할지.
