# 인용(citations) 모듈 설계 (v1, 2026-09-27)

## 1. 개요

- 담당 단위: C-1 도메인 상위, C-2 출처 카테고리·톤, C-3 프롬프트별 인용, C-4 타겟·자사 URL 인용률.
- 지표: M05 인용 점유율, M06 타겟 URL 인용률, M07 자사 URL 인용률, M09 출처 카테고리 분포, M10 도메인 상위.
- 원천: `rd.citation`(인용 원소 1:1, G-02 (c) 정본)과 `rd.answer`(M06·M07 불리언, C-2 톤, 커버리지 분모). 사전 집계·캐시 없음(D8).
- 원칙: 모든 인용 기능은 **하나의 술어 조립기**(`citation_where`)와 **하나의 자사 판정식**(`own_expr`)을 쓴다. kpi(M05 카드)·geo(국가별 인용)·trend 모듈도 같은 함수를 import 한다(P4).

## 2. 엔드포인트 명세

공통: 모든 엔드포인트는 §4 공통 필터 모델을 받고, 응답은 `{ data, meta }`(meta = 계약 공통 형태). 비율은 전부 `Ratio{num, den, pct}`(pct 는 응답 직전 계산, den=0 이면 null). 목록은 `PageIn{cursor, limit=50(1~200)}` / `PageOut{next_cursor, limit}` 키셋, 정렬 (주 카운트 DESC, 외부 식별자 ASC).

### 필터 지원 표

| 엔드포인트 | global | website | project |
| --- | --- | --- | --- |
| /domains, /domains/{skey}, /sources, /sources/tone, /sources/types, /prompts | own_brand, brand[], country[], lang[], engine[], from/to, funnel[], brand_presence[], list_type[], depth1~3[], source[] | 카탈로그 축 제외 전부(카탈로그 축은 ignored_filters) | 같음 + 프로젝트 커스텀 필드(filters 모듈 결정 후) |
| /targets | (해당 없음: 400) | own_brand, brand[], country[], lang[], engine[], from/to. source[] 가 오면 suppressed 로 카드 생략(현행 동작) | 열린 질문 |

### C-1 GET /v1/citations/domains

- 추가 파라미터: `limit`(기본 50, 0 이면 요약·경쟁사만), `cursor`, `mention_brand`(표시 브랜드명, 선택: 언급 드릴다운의 인용 출처 탭).
- 응답 data:
  - `summary`: `total_citations`, `unique_sources`, `own_share: Ratio`(M05: 자사 인용 / 전체 인용), `answers_den`(커버리지 분모).
  - `rows[]`: `skey`(표시 열 'domain', 공식 소셜 계정은 host+path), `category: CategoryRef`, `citations`, `share: Ratio`, `citing_answers`, `coverage: Ratio`(citing_answers / answers_den), `own_citations`, `is_own`, `is_target`(website·project 에서만 의미), `competitor_brand`(name 또는 null).
  - `competitor_totals[]`: `brand`(name), `citations`, `sources`.
  - `page: PageOut`.
- 질의(문장 2개):
  1. 주 스캔: `SELECT c.source_key, count(*) citations, count(*) FILTER (WHERE own_expr) own_citations, bool_or(own_expr) is_own, bool_or(c.tgt_hit) is_target, count(*) FILTER (WHERE c.src_first) citing_answers FROM rd.citation c WHERE citation_where GROUP BY c.source_key` 를 MATERIALIZED CTE 로 두고, 같은 문장에서 (a) 요약 합계, (b) rd.dim_source 조인 후 competitor_brand_key 별 합, (c) 키셋 페이지 행(dim_source·app.citation_category·rd.dim_brand_name 조인)을 뽑는다. CTE 크기는 출처 키 수(10배 약 5만) 수준.
  2. 분모: `SELECT count(*) FROM rd.answer a WHERE a.surface·round_date·cyc_key·bgrp·geo·engine·lang·prompt_key 술어 AND a.cit_in`(source[] 는 답변 단위 축이 아니라 분모에 걸지 않음: 현행 sampledAnswers 와 같음, scope-aggregates.ts:6479).
- mention_brand: `rd.dim_brand_name.name → brand_key`, 두 문장 모두에 `EXISTS (SELECT 1 FROM rd.answer_brand ab WHERE ab.surface = c.surface AND ab.round_date = c.round_date AND ab.answer_key = c.answer_key AND ab.brand_key = :bk AND ab.std_in)`.
- 폐기한 초안 필드: `prompts`(G-21 a: 측정 단위로 대체), `drilldown_omitted`·`top_n`(드릴다운 분리로 불필요).

### C-1 GET /v1/citations/domains/{skey}

- 드릴다운(현행 표 행의 urls·promptList 대체, 상한 계승 scope-aggregates.ts:5283-5287).
- 응답 data: `urls[]`(url, title, citations, engines[], country, 상위 10), `prompts[]`(prompt_id, text, funnel, citations, own_citations, engines[], `answers: AnswerRef[]` 상위 8, 상위 12).
- 질의: `rd.dim_source.skey → source_key` 후 `c.source_key = :sk AND citation_where` 로 cit_source_idx 범위 스캔, url_key·prompt_key 별 집계. 제안 인덱스 P-2(INCLUDE)가 있으면 인덱스 전용 스캔.

### C-2 GET /v1/citations/sources

- 응답 data:
  - `categories[]`: `category: CategoryRef`, `citations`, `share: Ratio`(M09: 카테고리 인용 / 전체 인용).
  - `by_engine[]`: `engine`, `categories[{category_key, citations}]`(현행 engineCategories).
  - `total_citations`.
  - `tone`: `positive{urls, citations, answers}`, `negative{...}`.
- 질의(문장 2개):
  1. `GROUPING SETS ((ds.category_key), (c.engine_key, ds.category_key), ())`, `rd.citation ⋈ rd.dim_source`(카테고리는 적재 시 확정, 조회 시 재분류 없음).
  2. 톤: `rd.citation ⋈ rd.answer ON (surface, round_date, answer_key)`, `tone_expr(own_cols)` 로 `count(DISTINCT c.url_key) FILTER (...)`, `count(*) FILTER (...)`, `count(DISTINCT c.answer_key) FILTER (...)`.
- 카테고리 Δ 는 이 엔드포인트에 두지 않는다: trend 모듈(R10).

### C-2 GET /v1/citations/sources/tone

- 추가 파라미터: `tone`(positive|negative, 필수), `group_by`(url|source, 기본 url), `q`(표시 URL ILIKE, 기본 없음), 페이지.
- 응답 data: `rows[]`(key, url|null, skey, title|null, citations, category, prompt_text|null), `page`.
- 질의: 톤 조인 위에서 한 톤만 FILTER, `GROUP BY c.url_key` 또는 `c.source_key`. q 는 집계 뒤 좁혀진 행의 rd.dim_url.url 에만 적용(현행 citationDisplayUrlSql scope-aggregates.ts:11413 과 같은 표시 규칙을 Python 쪽 정규화로 이식, 적재 시 dim_url 에 표시 URL 열이 없으므로 식 이식 필요).

### C-2 GET /v1/citations/sources/types

- 현행 fetchStandardCitationTypeCategories(lib/scope/server.ts:3390) 이관. 당사 언급 답변이 유형 X 신호를 가지면 그 답변의 인용 전부를 X 에 귀속(중복 계상 허용, 현행 규약).
- 질의: `rd.citation c` 에 `rd.answer_brand ab`(own_bit <> 0 AND std_in, 같은 파티션 좌표) 를 답변 단위로 접은 유형 플래그와 조인, 유형 5종 × category_key 집계.
- 존치 여부는 열린 질문. M-2 는 이 기능을 명시 제외했으므로 폐기되지 않는 한 이 모듈 소유.

### C-3 GET /v1/citations/prompts

- 추가 파라미터: `owned`(bool, 필수: true = 자사 인용 있음, false = 인용은 있으나 자사 0), `q`(프롬프트 텍스트 ILIKE), 페이지.
- 응답 data: `rows[]`(prompt_id, text, funnel, citations, engines[], `answers: AnswerRef[]` 상위 8), `counts{owned, uncited}`, `page`.
- 버킷 정의: 현행 pr 은 호스트 있는 인용이 1건 이상인 프롬프트만 모은다(scope-aggregates.ts:6874-6895). 'uncited' 는 '인용 없음'이 아니라 '자사 미인용'이다. owned 카운트가 0 이면 화면이 섹션을 숨기는 규칙(scope-aggregates.ts:6716-6722)은 프론트가 유지.
- 질의(문장 1개): `rd.citation` 단일 스캔 → 1차 `GROUP BY prompt_key, answer_key, engine_key, geo_key`(cites, bool_or(own_expr)) → 2차 `GROUP BY prompt_key`(sum cites, bool_or owned, array_agg DISTINCT engine) → 버킷 카운트 + 키셋 페이지(rd.dim_prompt 조인, q) → 페이지 prompt_key 의 답변 표본 `ROW_NUMBER() OVER (PARTITION BY prompt_key ORDER BY cites DESC, answer_key) <= 8` 을 1차 집계 CTE 에서. rd.job 조인 없음(job_id 는 페이지 표본 ≤ 400 행에 대해서만 rd.job PK 조회).
- 웹사이트 '자사 base 프롬프트 분리 상위 5'(10-feature-trace.tsv:153)는 `limit=5` 로 대체.
- 보류: `GET /v1/citations/prompts/{prompt_id}/answers`(더보기). 현행에 없는 기능이라 첫 빌드에서 제외.

### C-4 GET /v1/citations/targets

- surface=website 만(그 외 400). 응답 data: `measured`, `target: Ratio`(M06), `owned: Ratio`(M07), `provenance: {source: live|report, publication_slug, reason}`.
- 라이브: `SELECT count(*) FILTER (WHERE web_reg) den, count(*) FILTER (WHERE web_reg AND tgt_cited) t, count(*) FILTER (WHERE web_reg AND own_url_cited) o FROM rd.answer WHERE surface = 2 AND round_date 범위 AND cyc_key = ANY AND cit_in AND bgrp = ANY AND geo_key = ANY [AND engine] [AND lang]`. 두 지표 모두 측정 단위·가산(A2, DB-인용 D-C3).
- 발행값(R09·D-C9 (i)): 조회 회차에 status='active' 발행물이 있고 켜진 필터가 발행 축(brand·country·lang)뿐이면 `rd.report_unit_value` 합(in_headline_pool, pub 조인). 엔진을 기본 밖으로 좁히면 라이브 + provenance.reason. 라우팅 판정은 lib/reports/truth-axes.ts:81(resolveReportTruthRoute)·:246(decidePublishedSelection) 이식.
- source[]·카탈로그 축: ignored_filters, source[] 는 추가로 meta.suppressed(현행 카드 생략).

## 3. 공통 구성요소

- `resolve_citation_scope()`: 권한 교집합(default-deny), bgrp 허용 목록(own_brand ∪ HMG 공통, brand[] 교차), geo_keys(권역 펼침, 웹사이트 가상 코드 → bgrp), lang_keys, engine, 카탈로그 축 → prompt_keys(global), source 카테고리, 회차, 자사 입력, own_cols 를 한 번에 푼다.
- `resolve_cycles()`: rd.cycle(cycle_pick_idx)에서 servable ∧ view_date ≤ rd.today_kst() ∧ hidden_scope ∉ {1,2}. 스냅샷 = 최신 노출 round_date 1개(A1), 기간 = [from,to] 전부(D1). meta.as_of·cycles·generation 도 여기서.
- `citation_where()`: 활성 술어만 정적 조립. 고정: surface, round_date 범위, cyc_key = ANY, cit_in, source_key <> 0, bgrp = ANY, geo_key = ANY. 선택: engine, lang, prompt_key, project_key, source 카테고리(dim_source 조인).
- `own_expr(surface)`: global `owner_key = ANY(:allowed_owner_keys)`, website `loc_owned OR tgt_hit`, project `loc_owned`. FILTER 안에서만 사용.
- `allowed_owner_keys()`: app.owned_base 브랜드 → 국가 → 언어 좁힘과 공집합 폴백(hmg-brands.ts:242-272), root_home 은 전 언어.
- `tone_expr(own_cols)`: sent_pos_* 합 대 sent_neg_* 합(G-03, P1 예외 '관점별 톤 비교').
- 공유 모델: Ratio, PageIn/PageOut, 불투명 커서, CategoryRef, AnswerRef, Provenance, Envelope[T].
- 외부 식별자: skey, prompt_id, job_id, brand name, category_key. 내부 정수 키는 응답·경로에 없다.

## 8. 열린 질문

1. 톤 요약 타일에 source[] 를 적용할지(현행 미적용, 이유 소멸). 적용을 기본으로 두고 A4 고지 목록에 넣는 안을 권장.
2. /sources/types(유형×카테고리)를 존치할지 폐기할지. 명세 M09 정의에 없다.
3. mention_brand 드릴다운에서 std_in(언급 모수) 교집합으로 분석 결손 답변의 인용이 빠지는 것을 허용할지.
4. /targets 의 project 표면 확장: web_reg 는 웹 카탈로그 전용이라 분모 정의가 다르다. 현행 KPI⑥(인용 정확도, 답변 기준)을 별도 지표로 유지할지 kpi 모듈과 결정 필요.
5. 발행값 경로에서 엔진 필터가 기본 밖일 때 target 만 엔진별 발행값(report_site_engine_fact)을 쓰고 owned 는 라이브로 쪼갤지(현재 설계는 전면 라이브).
6. 명세 §6 이 M07 을 '유닛·비가산'으로 적었으나 확정 DB(D-C3)는 측정 단위·가산. 명세 표기 정정 요청.
7. source_key 0 = 호스트 없음 해석(적재 모듈 확인), own_url_cited ⊇ tgt_cited 적재 계약(P-4).
8. 프로젝트 커스텀 필드 필터의 공통 필터 모델 편입과 prompt_id 대응 경로(filters 모듈).
9. trend 모듈이 차원 시계열(주별 상위 10 출처, 카테고리 구성 추이, 카테고리 Δ)을 지원하는지. 지원하지 않으면 현행 기능 3개가 빈다.
10. 표시 URL 규칙(citationDisplayUrlSql)을 조회 시 식으로 이식할지, 적재 시 rd.dim_url 에 표시 URL 열로 굳힐지(후자는 P1 취지에 맞지만 확정 DDL 변경).
