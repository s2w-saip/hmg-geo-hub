API 명세 / 인용

인용

APIRouter(prefix="/v1/citations", tags=["citations"]) : 모듈 경로 app/modules/citations/{router.py, schemas.py, scope.py, sql.py, repo.py}. 엔드포인트 8개: GET /domains, GET /domains/{skey}, GET /sources, GET /sources/tone, GET /sources/types, GET /prompts, GET /targets (+ /prompts/{prompt_id}/answers 는 보류). 모든 핸들러는 공통 필터 모델(filters 모듈 소유 CommonFilters)과 세션 스코프 의존성(auth 모듈)을 Depends 로 받고, 모듈 내부 의존성 resolve_citation_scope() 가 권한 교집합·회차 게이트·자사 판정 입력을 한 번에 풀어 ResolvedCitationScope 로 넘긴다. DB 는 api_ro 롤, rd·app 스키마만 읽는다.

인용 모듈은 rd.citation(인용 원소 1:1, G-02 (c)) 한 표를 공통 술어 하나로 스캔해 M05·M09·M10 과 프롬프트별 인용을 내고, M06·M07 은 rd.answer 불리언(web_reg·tgt_cited·own_url_cited)만 읽는다. 단위 4개를 합치며 22건의 불일치를 해소했다. 핵심은 (1) 자사 판정을 표면별 한 함수로 통일(글로벌 owner_key = ANY(허용 배열, 브랜드→국가→언어 좁힘), 웹사이트 loc_owned OR tgt_hit, 프로젝트 loc_owned). C-1 의 dim_url.owner_key<>0 은 타 브랜드 자사까지 세는 오류 (2) 도메인 그룹 키를 dim_url.domain(text)에서 c.source_key(현행 citationGroupKeySql 과 같은 공식 소셜 계정 분리 키)로 교정하고 인용 답변 수를 count(*) FILTER (src_first) 로 바꿈 (3) G-21(a) 위반인 도메인별 count(DISTINCT prompt_key) 폐기(측정 단위) (4) 호스트 없는 인용 전 기능 제외(source_key <> 0) (5) 회차 게이트(servable·view_date·hidden_scope NOT IN (1,2))를 공유 resolver 로 통일(C-3 는 게이트 자체가 없었음) (6) 필터 지원 축 통일: 현행 detailAnswerWhere 가 인용 기능 전부에 카탈로그 축과 source[] 를 걸었으므로 C-1·C-2 의 무시 선언을 지원으로 바꿈 (7) C-3 의 파티션 키 누락 조인과 전 leaf 스캔 표본 질의를 단일 스캔으로 재설계 (8) 응답 비율 형태를 {num, den, pct} 로, 페이지네이션을 불투명 키셋 커서로 통일. 빈틈이던 엔진×카테고리, 도메인 드릴다운(URL·프롬프트), 유형×카테고리, 대시보드 경쟁사 인용 행을 모듈 안에 배정했고, 주별 상위 도메인·카테고리 추이·카테고리 Δ 는 trend 모듈 의존으로 넘겼다. 최대 위험은 웹사이트 1년 창의 /domains·/sources(원소 그레인 1.7~2.0초 추정, D8 예외 ④ 게이트 대상)와 인용 화면의 동시 호출(G-25)이다.

모듈 공통

공통 구성요소
  • 라우터 구조: app/modules/citations/router.py 에 APIRouter(prefix='/v1/citations') 하나. 핸들러는 얇게(파라미터 검증 → resolve_citation_scope → repo 함수 → 응답 조립). SQL 은 sql.py 에 SQLAlchemy Core 텍스트 조각으로, 조립은 repo.py. 한 요청 = 한 커넥션·한 READ ONLY 트랜잭션(SET LOCAL statement_timeout), 문장 수 상한 3(G-25 대응).
  • 공통 의존성 resolve_citation_scope(filters: CommonFilters, session: Session, family='citations') -> ResolvedCitationScope: (a) 권한 교집합: 세션 스코프(brand·region·country·project 멤버십)와 요청 필터를 교집합, 공집합이면 403(default-deny), 밖 값은 dropped_filters. (b) bgrp 허용 목록: own_brand(서버 결정) ∪ HMG 공통, brand[] 교차 마스크를 '= ANY(상수 배열)' 로 펼침(DB-측정-코어.md §5, WHERE 비트식 금지). (c) geo_keys: country[]·권역을 rd.dim_country 로 펼침, 웹사이트 가상 코드(HYUNDAI-N 등)는 bgrp 조건으로 변환(lib/scope/website-virtual-geo.ts:23). (d) lang_keys(global·website). (e) engine: 비면 dflt, 있으면 engine_key = ANY. (f) prompt_keys: 카탈로그 축(funnel·brand_presence·list_type·depth1~3)은 global 에서만, rd.catalog_entry 에서 '한 카탈로그 행이 모든 선택 축을 만족'하는 prompt_key 집합을 먼저 풀어 = ANY(1,000 초과면 rd.catalog_entry 세미조인), website·project 에선 ignored_filters. (g) source_category_keys(source[]). (h) 회차 게이트 resolve_cycles() 결과. (i) 자사 판정 입력(allowed_owner_keys 또는 표면 플래그). (j) own_cols(h/k/g 중 관점 브랜드 열 목록, G-03). 결과는 frozen dataclass, 모든 단위가 같은 객체를 받는다.
  • resolve_cycles(surface, project_keys, from, to, family='citations'): rd.cycle 에서 cycle_pick_idx(surface, round_date DESC) 로 servable AND view_date <= rd.today_kst() AND hidden_scope NOT IN (1,2)(R03·R04, 인용 계열은 all·citations 숨김 제외) 인 회차를 고른다. from/to 없으면 최신 노출 회차의 round_date 1개(A1·R05), 있으면 [from,to] 안 전부(D1·R06). 반환: cyc_keys int4[], rd_from, rd_to, as_of, cycles(cycle_id 목록), generation(max). 사실 표 질의는 반드시 c.surface = :s AND c.round_date BETWEEN :rd_from AND :rd_to AND c.cyc_key = ANY(:cyc_keys) 세 술어를 함께 쓴다(파티션 가지치기 + 게이트).
  • citation_where(scope) -> SQL 조각: 활성 술어만 정적으로 조립한다(C-2·C-3·C-4 초안의 '(:p IS NULL OR col = ANY(:p))' 범용 술어 금지: 확장 통계 추정을 흐리고 PgBouncer transaction 모드에서 prepared statement 캐시가 꺼져 있어 얻는 것도 없다). 고정 술어: surface·round_date 범위·cyc_key = ANY·c.cit_in(G-21 g, 분석 결손 무관)·c.source_key <> 0(호스트 없는 인용 제외, G-21 a·D-C6)·c.bgrp = ANY·c.geo_key = ANY. 선택 술어: engine(dflt 또는 = ANY), lang_key = ANY, prompt_key = ANY, project_key = ANY(website·project), source[] 는 JOIN rd.dim_source ds ON ds.source_key = c.source_key AND ds.category_key = ANY(:cats)(출처 키가 1,000 개를 넘을 수 있어 상수 배열로 풀지 않는다).
  • own_expr(surface, alias='c') -> SQL 불리언 식(FILTER 안에서만 사용): global = c.owner_key = ANY(:allowed_owner_keys), website = (c.loc_owned OR c.tgt_hit), project = c.loc_owned (DB-인용-도메인-웹사이트.json access_patterns[0] 정의). kpi(M05 카드)·geo(국가별 인용)·trend 모듈이 같은 함수를 import 한다(P4 산식 한 곳).
  • allowed_owner_keys(own_brands, country_codes, lang_codes): app.owned_base 에서 brand_code ∈ 관점 브랜드(HMG 면 3사)로 거르고, 국가가 있으면 geo_code 로 좁히되 공집합이면 브랜드 목록으로 폴백, 언어도 같은 방식(현행 ownedBasePrefixesForScope lib/scope/hmg-brands.ts:242-272 의 좁힘·폴백 규칙 이식). kind='root_home' 은 전 언어 자사(M05). 수십 행이라 요청마다 조회(캐시 없음, D8).
  • tone_expr(own_cols): 답변 톤 = sum(sent_pos_{own_cols}) 대 sum(sent_neg_{own_cols}) 비교, positive = P > NG, negative = NG > P, 동률·0 은 제외(현행 scope-aggregates.ts:11345-11371 계승). own_cols 는 관점 브랜드로 h·k·g 중 선택(HMG 면 h+k+g 합), 컬럼명은 화이트리스트로 정적 생성. rd.answer 조인은 반드시 (surface, round_date, answer_key) 등치.
  • Pydantic v2 공유 모델(schemas.py): Ratio{num:int, den:int, pct:float|None}(pct = round(100*num/den, 1), den=0 이면 None, P3), PageIn{cursor:str|None, limit:int=50(1~200)}, PageOut{next_cursor:str|None, limit:int}, 커서 = base64url(JSON [정렬값, 키]) 불투명 문자열(서버 검증, 변조 시 400), CategoryRef{category_key:int, slug:str, name:str}, AnswerRef{job_id:uuid, engine:str, country:str|None, citations_in_answer:int}, Provenance{source:'live'|'report', publication_slug:str|None, reason:str|None}. 응답 봉투 Envelope[T]{data:T, meta:Meta} 의 Meta 는 filters 모듈 공통 형태(surface, mode, as_of, cycles, generation, ignored_filters, dropped_filters, suppressed)를 그대로 쓴다.
  • 지원 축 선언 표(FILTER_SUPPORT): 엔드포인트 × 표면별로 지원 축을 상수로 선언하고, 공통 의존성이 선언 밖 축을 meta.ignored_filters 로 옮긴다(§4 규칙 2). 초안별로 다르던 선언을 이 표 하나로 대체한다(consistency_fixes 참조).
  • 외부 식별자 규약: 응답·경로에 내부 정수 키를 노출하지 않는다. 출처 = rd.dim_source.skey(도메인 또는 공식 소셜 계정 경로, 현행 표 'domain' 열과 같은 값: citation-group-key.ts 머리 주석, 제품 책임자 2026-08-28), 프롬프트 = rd.dim_prompt.prompt_id(uuid), 답변 = rd.job.job_id(uuid), 브랜드 = rd.dim_brand_name.name, 카테고리 = app.citation_category.category_key(앱 PK)+slug. 예외 없음.
단위 간 정리
  • F1 자사 판정 불일치(C-1·C-3): C-1 은 count(*) FILTER (WHERE u.owner_key<>0) 로 '어느 브랜드든 자사 base 에 걸린 인용'을 셌다. 관점 브랜드가 Kia 인데 hyundai.com 인용이 자사로 잡히는 오류이고, 웹사이트 표면의 유닛 판정(loc_owned·tgt_hit)도 무시한다. C-3 은 owner_key = ANY 를 브랜드로만 좁혀 국가·언어 좁힘(hmg-brands.ts:242-272)을 빠뜨렸다. 해소: 공유 own_expr(surface) 하나로 통일(global owner_key = ANY(allowed_owner_keys), website loc_owned OR tgt_hit, project loc_owned). allowed_owner_keys 는 브랜드→국가→언어 좁힘·폴백을 이식한 공유 함수.
  • F2 도메인 그룹 키(C-1): GROUP BY u.domain(rd.dim_url 텍스트)는 공식 소셜 계정(linkedin.com/company/hyundai 등)을 linkedin.com 하나로 합친다. 현행은 citationGroupKeySql(lib/db/repositories/citation-group-key.ts:57)로 계정 단위 분리 키를 쓴다(scope-aggregates.ts:6824). 해소: GROUP BY c.source_key(정수, cit_source_idx), 표시는 rd.dim_source.skey. 텍스트 GROUP BY 도 사라진다.
  • F3 G-21(a)·D-C7 위반(C-1): 도메인별 prompts = count(DISTINCT prompt_key) 는 채택된 '도메인 표 프롬프트 수는 측정 단위'와 반대이고 비가산이다. C-1 은 metrics_rules 에 G-21(a) 를 적어 두고 반대로 계산했다. 해소: prompts 필드 폐기, citing_answers = count(*) FILTER (WHERE c.src_first)(src_first 는 (답변, source_key) 안 최소 ord 라 source_key 그룹에서만 DISTINCT 와 동치), coverage = citing_answers / 같은 필터 cit_in 답변 수. A4 1회 고지 목록에 '프롬프트 수 → 인용 답변 수' 추가.
  • F4 호스트 없는 인용(G-21 a·D-C6): 네 단위 모두 제외 술어가 없었다. 해소: citation_where 에 c.source_key <> 0 고정. v2 DDL 은 source_key NOT NULL DEFAULT 0 이고 rd.dim_source 는 1 부터 발급되므로 0 = 호스트 없음으로 해석했다(DB-인용 초안의 'NULL = 호스트 없음'을 v2 가 0 으로 바꾼 것으로 추정, 적재 모듈 확인 필요로 표기).
  • F5 회차 게이트 편차: C-1 은 hidden_scope 를 안 걸었고, C-3 은 rd.cycle 게이트(servable·view_date·hidden_scope)가 아예 없었다(R03 위반: 미노출 회차가 고객에게 보임). C-2·C-4 는 각자 CTE 로 걸었다. 해소: resolve_cycles() 하나가 cyc_keys 배열을 먼저 풀고 모든 사실 표 질의가 cyc_key = ANY(:cyc_keys) 와 round_date 범위를 함께 쓴다.
  • F6 brand[] 축 처리 차이: C-1 은 brand[] 를 supported·ignored 어디에도 적지 않았고(누락), C-3 은 rd.catalog_entry.brand_bit 로 걸었으며, C-2·C-4 는 bgrp 로 걸었다. 해소: DB-측정-코어.md §5 매핑대로 brand[]·own_brand 모수는 fact 표의 bgrp = ANY(교차 마스크 목록). catalog_entry 는 카탈로그 축(funnel 등) 전용.
  • F7 카탈로그 축 지원 차이: C-1·C-2 는 funnel·brand_presence·list_type·depth1~3 을 ignored 로 선언했지만 현행 인용 기능은 전부 detailAnswerWhere(scope-aggregates.ts:6230, catalogPromptPreds :6236, funnel :6280 부근)를 공유해 이 축들을 건다. C-3 은 ignored: [] 로 적어 website·project 표면에서도 지원하는 것처럼 선언했다. 해소: global 표면에서 C-1·C-2·C-3 모두 지원(prompt_key = ANY), website·project 표면은 ignored_filters. C-4 는 answer 불리언 표면 특성상 ignored.

열린 질문
  • M06·M07 그레인 표기 불일치: 스펙 §6 표는 M07 을 '유닛'·비가산으로 적었지만 확정 DB 설계(DB-인용-도메인-웹사이트.md)는 둘 다 답변 행 불리언·가산으로 확정했다. 이 설계는 DB 를 따랐는데, 스펙 표기 정정이 필요한지 확인 요청
  • surface=project 확장 여부: app.project_owned_base/app.project_tracked_url(현행 project_owned_bases/project_tracked_urls)이 이미 있고 '프로젝트 자사·추적' 판정이 rd.citation.loc_owned/tgt_hit 재판정 트리거 표에 실려 있어(DB-인용-도메인-웹사이트.md §4) rd.answer.tgt_cited/own_url_cited 가 project 표면도 커버할 개연성이 있다. 다만 web_reg 플래그는 website 카탈로그 등록 전용이라 project 표면 분모 정의가 다르다(현행 KPI⑥ aggregateCitationAccuracy 는 답변 그레인이지 M06 과 산식이 다르다). project 표면을 이 엔드포인트에 합칠지, KPI⑥ 을 별도 유지할지 결정 필요
  • own_url_cited 가 적재 시점에 tgt_cited 를 이미 포함하는지: 포함되면 쿼리의 방어적 OR 가 불필요해져 더 단순해진다. 코어 적재 영역에 정의 확인 요청
  • 엔진별 세부: report_unit_value/report_site_engine_fact 는 target_hit_prompts 만 엔진별로 있고 owned_prompts 엔진별 값이 없다. 엔진 필터가 기본값이 아닐 때 발행값 경로를 전면 배제할지, target 만 발행값을 쓰고 owned 는 항상 라이브로 쪼갤지 결정 필요(현재 설계는 전면 배제로 보수화)
  • 이 엔드포인트가 요약값 외에 등록 타겟 URL별 적중 여부(드릴다운 리스트)도 내야 하는지: 현행 화면(citations-view.tsx)에는 요약카드만 있고 타겟 URL별 표는 없다. 필요하면 C-1/C-3 과의 경계, D8 예외 필요 여부를 별도 논의해야 한다

쿼리 설계
라이브 경로(발행값 미해당 시): WITH allowed_cyc AS (SELECT cyc_key FROM rd.cycle WHERE surface=2 AND project_key = ANY(:scope_project_keys) AND round_date BETWEEN :from AND :to AND servable AND view_date <= (now() AT TIME ZONE 'Asia/Seoul')::date AND hidden_scope NOT IN (1,2)) SELECT count(*) AS measured, count(*) FILTER (WHERE tgt_cited) AS target_hit, count(*) FILTER (WHERE own_url_cited OR tgt_cited) AS owned_hit FROM rd.answer_w WHERE surface=2 AND round_date BETWEEN :from AND :to AND cyc_key = ANY(SELECT cyc_key FROM allowed_cyc) AND project_key = ANY(:scope_project_keys) AND web_reg AND cit_in AND (CASE WHEN :engine_empty THEN dflt ELSE engine_key = ANY(:engine_keys) END) AND geo_key = ANY(:allowed_geo_keys) AND (:lang_empty OR lang_key = ANY(:lang_keys)) AND (:brand_empty OR bgrp = ANY(:brand_masks)). 스냅샷(from/to 미지정)은 round_date = 최신 노출 회차 1개로 좁힌다(cycle_pick_idx 로 조회). 발행값 경로(R09 조건 충족 시): SELECT coalesce(sum(measured_prompts),0), coalesce(sum(target_hit_prompts),0), coalesce(sum(owned_prompts),0) FROM rd.report_unit_value v JOIN app.report_publication p ON p.id = v.pub_id AND p.status='active' WHERE v.round_date = :published_round_date AND v.in_headline_pool AND v.brand = ANY(:allowed_brands) AND (:country_empty OR v.country_code = ANY(:countries)) AND (:lang_empty OR v.lang_code = ANY(:langs)). 라우팅 판정(엔진이 기본값뿐이고 brand/country/lang 만 켜졌는지, 권한이 발행 모집단을 덮는지)은 현행 resolveReportTruthRoute/decidePublishedSelection(server.ts:5083-5150) 로직을 이식.
