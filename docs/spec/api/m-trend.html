T-1 지표 추이 (Trend) medium

회차(또는 주·월로 롤업한)버킷 단위로 M01~M11 지표의 시계열을 반환하고, 원장에 회차 자리가 있는데 값이 없는 지점은 갭으로 표시한다(R11). 카드(kpi/summary)와 같은 산식·같은 모수를 써서 D6(단위 통일)을 보장하는 유일한 시계열 원천 — 대시보드 스파크라인, website KPI 추이, 답변분석 우선노출도/경쟁사 추이, 엔진별 추이를 이 하나의 엔드포인트가 모두 흡수한다.

GET/v1/trend회차·주·월 버킷 지표 추이(갭 표시). D6 에 따라 카드(kpi/summary)와 같은 그레인 합산.

  • website KPI 추이(5계열+인용정확도선)
  • 답변분석-언급 AI 우선노출도 탭(회차 시계열)
  • 답변분석-언급 엔진별 섹션(engine_split=true)
  • 답변분석-언급 경쟁사 스파크라인·본문 하단 주별 브랜드 언급 추이(M11)
  • 답변분석-인용 주별 상위 도메인/카테고리 구성 추이(M09·M10 — 다만 도메인·카테고리 분해는 citations 모듈이 담당할 수도 있음, open_questions 참조 안 함: 본 목록은 §8 trend 모듈 소속 화면만 선별)

추가 파라미터
  • bucket: enum(cycle|week|month), 기본 cycle. R11 의 '원장 자리' 단위를 결정
  • metrics: string[], 콤마 구분. 지원값 = M01(exposure_rate)·M02(sov)·M03(favorability)·M04(avg_position)·M05(citation_share)·M06(target_url_rate, website 전용)·M07(own_url_rate, website 전용). 미지정 시 surface 기본 세트(global=M01~M05, website=M01~M07)
  • engine_split: bool, 기본 false. true 면 §7 언급 M11/M08 대신 metrics × engine_key 로 계열을 쪼갠다(현행 fetchStandardKpiEngineTrend 대체, 값 산식은 metrics 와 동일 — R05 셀 정의가 engine_key 를 이미 포함하므로 새 컬럼 불필요)
지표·규칙
  • D1: 기간 지정 시 버킷 = 앵커 날짜(anchor_date)가 그 버킷 창 안인 모든 완료 측정 합
  • D6: 카드 값 = 같은 기간에 걸친 추이 버킷들의 분자·분모 합. kpi/summary 와 이 엔드포인트는 같은 WHERE·같은 std_in/cit_in 모수를 써서 자동으로 일치시킨다(별도 재검증 로직 불필요)
  • R05: 기간 미지정(스냅샷) 요청은 이 엔드포인트에선 정의하지 않는다 — 스냅샷은 kpi/summary 가 담당하고 trend 는 항상 from/to 또는 최근 N버킷 기본 창을 쓴다(open_questions 참조)
  • R06: 프롬프트 단위 지표(M06·M07)의 버킷 정의는 A2(측정 단위) 채택 — 회차 내 '타겟 URL 인용된 측정/측정'으로 가산형, 프롬프트 스캔 없음
  • R11: 추이 격자 = rd.cycle 에서 그 surface·프로젝트의 원장 자리(회차)만 그린다. 버킷 안에 자리가 있는데 rd.answer 가 0건이면 gap=true(사유 no-answer), 자리 자체가 없으면 그 버킷을 만들지 않는다(없던 주를 채우지 않음)
  • R10: compare(Δ)는 별도 엔드포인트(kpi/compare)가 이 추이 배열의 마지막 두 유효 점을 사용 — 이 엔드포인트는 Δ를 계산하지 않는다
  • M01~M05, M08~M11: §6 정의 그대로, 분자·분모 정수로 응답(가산성 표 그대로)
  • R03: view_date <= 오늘(KST)인 회차만 노출 — rd.cycle.servable=true AND view_date<=CURRENT_DATE 필터를 자리 목록에 선적용
  • R04: hidden_scope 에 따라 all/citations/mentions 숨김 — 인용 계열 metrics(M05~M07,M09,M10)는 hidden_scope IN (1,2)인 회차에서 그 시리즈만 결측 처리, 언급 계열은 hidden_scope IN (1,3)
읽는 표·열

권한
역할·데이터 스코프는 §9 공통(hq·region·country·admin·vendor·website, `deriveScopeFilter` 계승) 그대로 적용. own_brand 는 서버가 세션에서 결정(§4 표 첫 행, 클라이언트 변경 불가). country[]·brand[] 등은 서버 스코프와 교집합, 스코프 밖 값은 dropped_filters. 추가 게이트 없음(비용 액션 아님, 운영자 필드 불필요). fail-closed: 스코프 계산 실패·세션 없음이면 401/403, 빈 스코프면 data 없이 meta.suppressed 로 사유 표시(전량 거부가 아니라 빈 배열 반환 — 카드·추이가 같은 필터로 공존하므로 빈 화면이 정상 응답).

"WITH slots AS (\n  -- R11: 원장 자리(회차) 목록. R03 노출 게이트·R04 숨김을 여기서 선적용.\n  SELECT c.cyc_key, c.round_date,\n         date_trunc(CASE WHEN :bucket='month' THEN 'month' WHEN :bucket='week' THEN 'week' ELSE 'day' END, c.round_date)::date AS bucket_key\n  FROM rd.cycle c\n  WHERE c.surface = :surface AND c.project_key = :project_key\n    AND c.servable AND c.view_date <= CURRENT_DATE\n    AND c.round_date BETWEEN :from AND :to\n),\nfacts AS (\n  SELECT a.surface, a.round_date, a.cyc_key,\n         a.own_mask, a.own_rk_h, a.own_rk_k, a.own_rk_g,\n         a.ment_total, a.ment_h, a.ment_k, a.ment_g,\n         a.sent_pos_h, a.sent_neg_h, a.sent_all_h,   -- (own_brand 에 따라 h/k/g 컬럼 선택)\n         a.tgt_cited, a.own_url_cited, a.has_cit\n  FROM rd.answer a\n  WHERE a.surface = :surface AND a.round_date BETWEEN :from AND :to\n    AND a.std_in                      -- 언급 계열 모수(생성 컬럼)\n    AND a.project_key = :project_key\n    AND (:engine_keys IS NULL OR a.engine_key = ANY(:engine_keys))\n    AND (:geo_keys    IS NULL OR a.geo_key    = ANY(:geo_keys))\n),\nagg AS (\n  SELECT s.bucket_key,\n         count(*) FILTER (WHERE f.answer_key IS NOT NULL)                 AS answers,\n         count(*) FILTER (WHERE f.own_mask <> 0)                          AS own_present,   -- M01\n         sum(f.ment_h)                                                     AS own_mentions,  -- M02 분자\n         sum(f.ment_total)                                                 AS all_mentions,  -- M02 분모\n         sum(f.sent_pos_h)                                                 AS pos_mentions,  -- M03 분자\n         sum(f.sent_all_h)                                                 AS sent_mentions, -- M03 분모\n         sum(f.own_rk_h) FILTER (WHERE f.own_rk_h > 0)                     AS rank_sum,      -- M04 분자\n         count(*) FILTER (WHERE f.own_rk_h > 0)                            AS rank_n          -- M04 분모\n  FROM slots s LEFT JOIN facts f ON f.round_date = s.round_date AND f.cyc_key = s.cyc_key\n  GROUP BY s.bucket_key\n),\ncit AS (\n  -- 인용 계열은 별 CTE: rd.citation ⋈ 자리, cit_in 모수, R04 hidden_scope IN (1,2) 시 NULL 처리\n  SELECT s.bucket_key,\n         count(*) FILTER (WHERE c.source_key IS NOT NULL)                 AS all_citations,\n         count(*) FILTER (WHERE c.is_own)                                 AS own_citations   -- M05\n  FROM slots s\n  LEFT JOIN rd.answer a2 ON a2.round_date = s.round_date AND a2.cyc_key = s.cyc_key AND a2.cit_in\n  LEFT JOIN rd.citation c ON c.round_date = a2.round_date AND c.answer_key = a2.answer_key\n  GROUP BY s.bucket_key\n)\nSELECT s.bucket_key, s.round_date,\n       (agg.answers IS NULL OR agg.answers = 0) AS gap,\n       agg.*, cit.*\nFROM (SELECT DISTINCT bucket_key, round_date FROM slots) s\nLEFT JOIN agg ON agg.bucket_key = s.bucket_key\nLEFT JOIN cit ON cit.bucket_key = s.bucket_key\nORDER BY s.bucket_key;"
