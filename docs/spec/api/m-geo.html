국가별

단위 상세

G-1 G-1 국가별 현황 (GET /v1/geo) medium

국가(웹사이트는 사이트 국가)별로 당사(관점 브랜드) 대 경쟁사의 시장 위치를 KPI 5종(노출률·점유율·우호도·우선노출도·인용점유율)과 최대경쟁사·선두 자사브랜드로 보여준다. 권역(RHQ) 단위로 국가를 묶어 지도/트리로 드릴다운하는 것이 목적이며, 다른 KPI 모듈(kpi/summary)과 산식은 같고 국가 축으로만 좁힌 것이다(M11 브랜드·경쟁사 비교와 그레인 공유).

메서드경로요약
GET/v1/geo국가별 GEO 현황: 권역→국가 트리, 국가·권역별 KPI 5종(M01·M02·M03·M04·M05)과 최대경쟁사·선두 자사브랜드. surface=global 은 전 세계 측정 국가, surface=website 는 사이트 선언 국가 기준(현행 웹사이트 GEO 는 언급 수만 지원했으나 통합 그레인 채택으로 5종 전부 가능해짐, open_questions 참조).

  • /website GEO(지도+스냅샷, showsGeoMap 권한자만, getLiveWebsiteGeo, surface=website)

권한
역할: hq·region·country·admin·vendor·website(§9 정본). own_brand 는 계정 스코프(scope.brands) 또는 project 브랜드에서 서버가 결정(§4 표, 클라이언트 무시). 데이터 스코프: 서버가 role→{brands,regions,countries} 계산 후 요청 country[]·brand[] 와 교집합(default-deny), 근거 lib/auth/scope-policy.ts(신 구조는 동등 predicate 를 FastAPI 의존성으로 이식). geo_key 허용집합은 교집합 결과를 rd.dim_country.code 로 매핑해 WHERE geo_key = ANY(:allowed_geo_keys) 에 주입. vendor·website 역할은 이 화면 라우트 접근 자체가 route-policy 밖일 수 있음(현행 lib/auth/route-policy.ts::ROUTES 승계, admin/hq/region 에 한해 showsGeoMap true — 현행 lib/auth/scope-policy.ts 의 showsGeoMap 상수, 신 구조는 role 목록을 그대로 이식하되 새 위치 미확인이라 제안 표시). 감사 로그(app.access_audit_log) 쓰기 주체 미정(AU-1) — 계약서 §3 미결 사항 그대로 인계.
쓰기
없음(읽기 전용). 쓰기 스키마(app/ing)는 이 API 가 만지지 않는다 — 재판정 요청(judgment_change)도 이 화면에는 진입점 없음(당사 판정 own_bit·브랜드 롤업은 카탈로그·엔티티 레지스트리 재판정의 부수효과로 다른 모듈(관리자 entities/catalog)이 담당).
성능(10배)
10배 폭 합성 기준(근거 미확정, 계약서 §3 성능 근거의 한계): 스냅샷(기간 미지정) 쿼리는 최신 노출 회차 1개(round_date 단일값) 파티션 프루닝으로 rd.answer 는 answer_rd_brin 덕에 그 회차 분량만 읽음 — 현행 6.6만 job/전체 체인 규모에서 회차당 수천~수만 행 추정(정확한 회차당 표준 답변 수는 미확인, DB-보정.md 에 수치 없음). rd.answer_brand 는 답변당 평균 브랜드행(자사 3+경쟁 다수) 배수라 같은 회차에서 answer 대비 3~6배 행 추정. 1년 기간 조회(from/to 최대창)는 계약서가 명시한 고위험 사례('웹사이트 인용 1년 조합 1.7~2.0초 추정')와 같은 유형 — GEO 도 전 세계 국가를 한 번에 그룹핑하므로 기간이 길수록 answer_brand 스캔 행수가 선형 증가.
인덱스: answer_rd_brin(rd.answer, round_date) — 스냅샷/기간 파티션 프루닝, answer_cyc_idx(rd.answer, cyc_key) — R05 최신 노출 회차 선택 보조(cyc_key 는 rd.cycle.cycle_pick_idx 로 먼저 결정), cycle_pick_idx(rd.cycle, surface, round_date DESC) INCLUDE(...) — 스냅샷 대상 회차(servable·view_date) 선택, ab_rd_brin(rd.answer_brand, round_date) — 기간 조회 파티션 프루닝(스냅샷은 프루닝 효과 작음, 단일 회차라 이미 좁음), 제안: answer_brand_geo_idx ON rd.answer_brand (surface, round_date, geo_key) INCLUDE (brand_key, competitive, mention_count, rk, own_bit) — 현재 ab_brand_idx 는 (brand_key, round_date) 순이라 이 화면의 GROUP BY geo_key 접근에는 안 맞고, D8 은 매트뷰·요약표만 금지할 뿐 group-by 축에 맞춘 통상 btree 커버링 인덱스는 성능 최적화(P7)의 정상 범위로 판단. v3 실측 전 제안으로만 표시.
가장 무거운 부분은 시장 전체·경쟁사 집계를 위한 rd.answer_brand 스캔(rd.answer 당사 열 활용으로 '우리' 쪽은 이미 제거됨, G-03/D8 예외 ②). 스냅샷(기본 진입 화면)은 위험 낮음(회차 1개, 국가 전체라도 파티션이 작음); 1년 등 장기간 조회는 answer_brand 전량 스캔이라 계약서가 지목한 고위험군에 포함되므로 medium 으로 표시하고 v3 폭 10배 실측 게이트에서 재판정 필요.
