# 입력 계약 (서비스 → 수집 · 분석)

프롬프트·기준정보 원본(서비스 DB)을 수집과 분석이 프롬프트·기준정보 API로 읽는 약속이다. 수집은 프롬프트 · 측정 설정 · 수집 기준정보를, 분석은 분석 기준정보를 읽는다. 원본은 서비스가 만들고 관리하며, Gold DB와 분리해 둔다. 계약 1(Bronze)보다 앞 단계다.

## 주는 것

| 구분 | 입력 | 내용 | 받는 쪽 | 서비스 관리 화면 |
|---|---|---|---|---|
| 프롬프트 | Global prompts | 본문, 언어, 측정 국가, 분류, 상태 | 수집 | Admin › 글로벌 프롬프트 관리 |
| 프롬프트 | Project 프롬프트 · 커스텀 태그 | 본문, 언어, 측정 국가, 분류, 커스텀 태그, 상태 | 수집 | Project › Prompt |
| 측정 설정 | 측정 설정 | 측정할 브랜드 · 국가, website 측정 단위 · 기준 URL, AI 엔진, 측정 주기, ACR 반복 수, 소유 URL, 추적 URL, 추적 대상(경쟁 브랜드 · 모델) | 수집 | 프로젝트 설정 |
| 수집 기준정보 | AI 엔진(`engine`) | AI 엔진 목록 | 수집 | — |
| 수집 기준정보 | 국가(`country`) · 언어(`language`) | 국가와 언어 목록 | 수집 | — |
| 수집 기준정보 | 글로벌 키워드 카탈로그(`interest_keyword`) | 검색 키워드, 수집 조건, 브랜드 | 수집 | Admin › 고객 관심 데이터 관리 |
| 수집 기준정보 | 글로벌 소스 URL(`interest_source`) | 커뮤니티 수집 소스 URL, 채널, 브랜드 | 수집 | Admin › 고객 관심 데이터 관리 |
| 분석 기준정보 | 분류 체계(`taxon`) | 프롬프트 분류 경로(Depth 1 ~ 4) | 분석 | — |
| 분석 기준정보 | 자사 브랜드(`brand`) | 자사 브랜드 목록 | 분석 | — |
| 분석 기준정보 | 도메인 큐레이션(`source_override`) | 도메인 → 출처 카테고리 교정 | 분석 | Admin › 인용 출처 분류 |
| 분석 기준정보 | 시드(`source_seed`) | 도메인 → 출처 카테고리 | 분석 | Admin › 인용 출처 분류 |
| 분석 기준정보 | 공식 소셜(`source_social`) | 공식 소셜 계정과 URL 매칭 규칙 | 분석 | Admin › 인용 출처 분류 |
| 분석 기준정보 | 코드표(`source_code`) | 출처 카테고리 13개, 분류 출처 6개 | 분석 | Admin › 인용 출처 분류 |
| 분석 기준정보 | 브랜드 엔티티 역할(`entity_role`) | 역할(자사 · 제외. 경쟁사는 기본값), 자사 브랜드, 대표 이름 | 분석 | Admin › 엔티티 카탈로그 |
| 분석 기준정보 | 서비스 코드표(`surface` · `brand_bit` · `mention_type`) | 표면, 브랜드 비트, 언급 유형 | 분석 | — |

자사 브랜드와 브랜드 엔티티 역할은 분석이 Silver를 만들 때 자사 분류에 쓴다. 자사 여부 판정은 가공(BFF)이 한다. 분석이 분류해 두어야 BFF가 자사인지 구분할 수 있다.

## 전달 규칙

- 받는 쪽이 프롬프트·기준정보 API로 읽어 간다. 상세는 [prompt-reference-api.md](../service/prompt-reference-api.md).
- 변경은 `change_seq`와 etag로 알린다. 받는 쪽은 바뀐 것만 다시 읽는다.
