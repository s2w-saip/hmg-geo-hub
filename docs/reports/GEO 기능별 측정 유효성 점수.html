GEO 기능별 측정 유효성 점수

hmg-geo-hub가 제공하는 기능 72개를 기능 단위로 나열하고, 각 기능이 GEO 성과를 얼마나 믿을 만하게 재도록 구현됐는지 5점 만점으로 매겼습니다. 측정과 무관한 10개를 뺀 62개의 평균은 2.7점이고 5점은 없습니다. 산식과 적재 파이프라인은 탄탄하지만, 숫자를 얼마나 믿을지에 대한 근거(오차, 판정 정확도, 모델 고정)가 전 기능에 걸쳐 비어 있습니다.

기준: hub-share 스냅샷 72c260a3(2026-10-02). 기능 목록과 화면 경로는 back/taxonomy.json, 근거는 back/app/core/measure.py·profile.py, 기능별 README, 적재 판정 SQL(back/migration/seed/seed-40-facts.sql)을 읽고 매겼습니다. 화면에 붙어 운영 중인 것은 front 레거시 경로이고 back(FastAPI)은 스테이징 단계라, back에만 있는 기능은 stg 로 표시했습니다. 점수는 아래 기준에 따른 판단값입니다.

5점이 없는 이유

  • 표본. 표준 지표는 회차·질문·엔진·국가 셀마다 답변 1건으로 계산하고(profile.py cell_rep), 오차 범위나 유의성을 다루는 코드가 back·front·docs 어디에도 없습니다. 전사 합계는 셀이 수만 개라 안정적이지만, 국가·질문으로 쪼갠 화면은 변동이 노이즈인지 구분할 수 없습니다.
  • 판정. 언급·감성·유형·ACR 선택은 Scope 분석 결과를 받아 투영만 합니다. 허브 자체 분석 엔진은 설계 초안(ANALYSIS-ENGINE-DESIGN.md)뿐이고, 계획된 검증도 사람 라벨 대비가 아니라 원본 구현과 같은 값이 나오는지입니다. 10-07 미팅 결정대로 분석을 S2W가 맡으면 이 항목이 인수 후 가장 먼저 걸립니다.
  • 재현성. ChatGPT·Gemini는 웹 화면 수집이라 모델이 고정되지 않습니다(front/lib/scope/engines.ts). 모델 식별자는 답변 상세 표시에만 쓰이고, 추이에서 기준선을 나누지 않습니다.
  • 지표 정의. 우선 노출도는 답변 안 등장 위치 순위의 평균인데, 언급된 답변만 분모에 들어갑니다(seed-40-facts.sql 418~434행). 노출률이 낮아도 순위는 좋게 나올 수 있습니다. 산식 정본은 measure.py 812~830행입니다.
  • 레거시 재현. back의 현행 프로필은 운영 값과 완전히 같게 하려고 레거시 결함(별칭 중복 집계 등)까지 재현하도록 결정돼 있습니다.

링크 안내

front 코드를 읽고 정리한 내용이며, 운영 사이트에서 직접 열어 확인하지는 않았습니다.

  • 링크 주소는 https://hmg-geo.vercel.app 뒤에 화면 경로를 붙인 것이고 새 탭으로 열립니다. 언어 접두사 없이 들어가면 앱이 /ko 또는 /en 주소로 넘깁니다. 로그인이 필요합니다.
  • 점선 테두리 링크는 [id] 같은 자리가 있는 경로입니다. 위 프로젝트 ID 칸에 ID나 프로젝트 화면 주소를 넣으면 그 프로젝트 화면으로 바로 가고, 비워 두면 프로젝트 목록(/projects)으로 갑니다. [jobId] 경로는 검수 목록으로, [scopeId] 경로는 프로젝트 목록으로 연결됩니다.
  • 검수 콘솔(/raw-data-qa) 링크는 대시보드에 로그인된 상태에서 여십시오. 언어 접두사 없는 주소는 미들웨어가 공개 경로로 인식하지 못해, 로그인하지 않은 상태면 로그인 화면으로 넘어갑니다(front/middleware.ts).
  • 「메뉴 숨김」 표시는 사이드바에는 없지만 주소로는 열리는 화면입니다. 그중 /website/ai-funnel/acr 본문은 정적 표본입니다.
  • 「화면 없음」은 워커나 API로만 제공되는 기능입니다. 「분류표 밖」은 레포에는 있지만 72개 분류표에 없는 모듈이며 합계와 평균에서 뺐습니다.
