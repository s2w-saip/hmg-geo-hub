확정된 전제: 답변 원문 공급은 앤서 HUB RDS ing 스키마를 S2W가 DB로 직접 읽는 방식, 영구. Scope 원문 API(/raw·/turns)는 공급 경로 아님. Scope API는 측정 등록·수동 측정·스케줄(협의안 §3·§4)에만 사용. 구조: Scope 코어 → (앤서 ingest, 20분 pull) → HUB RDS ing → (DB 읽기) → S2W 엔진·시스템(Azure)

꼭 받아 올 것 3개

  1. H2 턴 원문 일정 — ing.answer에 turn_index 없음, answer_text는 turn-1뿐. 원문 API가 없으니 앤서가 ing.turn(또는 턴 컬럼)을 추가하는 게 유일한 해법. 일정이 안 나오면 우리 엔진을 job 단위로 설계해야 함.
  2. C5 전환일 + 운영 환경 — 현 레거시 연동 종료일, prod RDS 기동 시점(지금 정지 상태), 대상이 stg인지 prod인지(Q6). stg ingest 워커가 실제로 도는지·ing 적재 범위(Q1).
  3. 운영 SLA 초안 합의 — 영구 의존이므로 문서로: ingest 가동 보장, 측정 지연·적재 실패 통보, ing DDL 변경(DB-v2.x 패치) 사전 고지, RDS 정지/기동 정책, 복제본·VPN 비용 분담.
