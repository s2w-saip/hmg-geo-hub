후속 재검토 · 초기 Next 선정 기록 반영

SPA 우선 추천을 철회했다. 5/22 설계는 Next를 BFF 호스트로 명시적으로 선택했다. 현재 FastAPI가 있어도 Next의 브라우저 세션·토큰 중계 책임이 자동으로 이전되지는 않는다. BFF 귀속·렌더링·독립 API 필요성을 분리하고 A~D 네 구성을 비교한다.

아래 6건은 기존 세 차례 검토 이후 발견한 근거에 따른 개정이다. 기존 17건과 각 회차의 판단·검증 기록은 당시 상태로 보존하며, 이전 기록의 SPA 우선 추천은 현재 추천으로 읽지 않는다.

발견: 2026-05-22 초기 선정·Vite SPA 기각 기록이 추천 근거에서 빠졌다.

반영: 변경 합의 전 모든 읽기 API cold p95 1초·10배 데이터·발행 후 20분, 발행값 보존과 데이터 영향 변경 게이트 유지. 재분석 노출은 별도 미결로 명시.

근거: functional-spec.html §10·A5·A13; 인수 올인원 §3-4·5-2

본문: drivers · geo · poc · decisions

R1-02 중요도 중간

발견: Azure가 단순 방향 또는 미확정 플랫폼처럼 표시되어 10/7 합의 수준이 약화됨.

반영: S2W Azure 합의와 H-Cloud·런타임·외부 통신 적용 미결을 구분.

근거: 인수 올인원 §5-1 항목 5 및 §3-4

반영: 기존 결정 변경표 추가. 버전 식별과 물리 집계 구별, 집계·캐시 도입 ADR, RDS 읽기 후속 합의, 발행 보존과 새 정의 노출을 명시.

R2-01 중요도 높음

발견: 반복 표본·외부 실행 재시도·HTTP 중복 전달·원문 revision 식별이 구체적이지 않음.

근거: geo 절의 실행·시도·턴 및 원문 리비전 제안 간 경계 검토

본문: geo

R2-02 중요도 높음

발견: 서버 페이지네이션·silent failure 방지가 원칙에 그쳐 전체 선조회·변하는 cursor·전체 선택·부분 실패를 구현자가 다르게 해석할 수 있음.

반영: 페이지/바이트/시간 상한, 안정 정렬과 세대 cursor, 서버 대상 스냅샷, 권한·revision 재확인, 0/실패/결손/stale 구분과 HTTP 오류 형식 명시.

근거: backend·ui 절; PG17 SELECT 안정 정렬; RFC 9457

본문: backend · ui

R2-03 중요도 높음

발견: manifest 버전 참조와 원자적 active pointer만으로 결과 보존·여러 HTTP 요청의 동일 세대 읽기가 보장되지 않음.

반영: 불변 결과/사전/보정 보존, 발행 전 완료 대조, 동시 발행 충돌, 화면·export generation 고정, 만료·삭제 파급 범위 추가.

근거: versioning 절의 manifest·active pointer 제안에 대한 반례 검토

본문: versioning

R2-04 중요도 높음

발견: 접수·workflow·DB 완료 상태의 정본과 취소 경쟁이 불명확하며 구조도가 API에서 실행기로 직접 dispatch하는 것으로 보임.

반영: DB 접수+outbox 경로로 도식 수정. 멱등 접수, 결과 commit+업무 상태, workflow 대조, fencing, 부분 완료, 취소 요청/완료, 외부 과금 잔존을 정의.

본문: target · execution

R2-05 중요도 높음

발견: 중첩 재읽기·dedupe가 임의 지연 커밋까지 무누락을 보장하는 것으로 읽힐 수 있고 checkpoint·격리 commit 경계가 빠짐.

반영: 지연 상한/완료 원장/전체 대조의 보장 조건, snapshot→증분 연결, 내구성 저장과 checkpoint, 복제 지연 삭제 오판 방지 추가.

근거: supply 절 및 인수 올인원 H1/H2·운영 SLA 미결

본문: supply

R2-06 중요도 높음

발견: tenant+권한 버전만으로 서로 다른 membership의 캐시가 분리된다는 보장이 없으며 다운로드 시 권한 철회·세션 공유 정책이 부족함.

반영: 서버가 계산한 실제 접근 범위 fingerprint, 현재 인가, 계정 변경 캐시 폐기, 다중 인스턴스 세션, export 재인가·서명 URL 만료 한계 추가.

반영: 격리 영역·고유 판정 키·동시 claim, 코드/입출력 버전, 모델 단종 후 저장 결과 조회·새 버전 승격, 라벨 합의와 원문 그룹 분할 추가.

검증 범위와 남은 결정

HTML 검증은 문서 링크·근거 지문·의존성 목록·조건 선택 도구·데스크톱/모바일 표시를 확인한다. 소프트웨어 아키텍처의 성능·복구·권한을 실제로 통과했다는 뜻은 아니다.

HTML·링크·브라우저 검증 JSON · 회차별 입력·출력 SHA-256 기록

프레임워크·런타임·실행 제품·물리 집계/캐시의 최종 선정은 P1~P6 실증과 허용 환경, 팀 조건 확인 후에 한다. 모델 품질 임계값·공급 무누락 보장·RPO/RTO·컷오버 일정은 미결로 남겼다. 앱 코드, 운영 DB, 외부 유료 모델, 배포 환경은 변경하지 않았다.

초안과 회차별 HTML 바이트는 부록의 ‘재설계 재검토 이력’에 보관했다. SHA-256으로 검토 순서를 연결한다. 스냅샷은 원본 바이트 보관용이며 현재 문서 탐색은 위 수정본 링크를 사용한다.
