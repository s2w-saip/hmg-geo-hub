# 알려진 오류 (2026-10-20 v7 검토 결과)

v7 검토에서 확인한 오류입니다. v8 패치에 이미 반영된 것은 뺐습니다. 근거 줄 번호는 `back/db/DB-v2.32.sql`(DDL) 과 레포 경로 기준입니다. 반영할 때도 근거를 다시 열어 확인합니다.

## 01_dim
- `dim_country.kind`: CHECK 에 `unknown` 이 더 있습니다(DDL:381, geo_key 0 표식 행).
- `dim_region`: 현행은 ISO → 대륙 매핑입니다(`migration/seed/seed-3x-rules.sql:62` `_r_iso_region`, `back/ingest/project/apply/queries.py:262-272`, 합성 DB 값 Africa · Asia · Europe …). 입력 `app.rhq_region` 과 설명 '권역 코드'가 틀립니다. RHQ(권역 본부)는 BE 가 `app.rhq_region` 에서 직접 읽는 다른 개념입니다. 용도 '권역·본사 전환율'도 확인이 필요합니다.
- `dim_cycle`: BE 는 rd.cycle 을 쓰지 못합니다. 숨김은 judgment_change `cycle_admin`(비동기 202)으로 요청하고 적재기가 고칩니다.
- `dim_population`: A41 스위치가 std_in → std_in_nc, cit_in → cit_in_nc 로 바꾸는 모수가 모수 규칙에 없습니다.

## 02_prompt
- `web_unit`:
  - 입력이 틀립니다. 현행은 `app.website_prompt` · `app.website_site` 로 만듭니다(`back/ingest/project/apply/rejudge.py:205-250`).
  - `app.website_report_unit` 은 `web_report_prompt` 의 원천입니다(DDL:3712, 3790-3802).
  - `file_seq` 단독 UK 가 아니라 UNIQUE(project_key, file_seq) 입니다.
  - 용도의 'Website KPI 모수 게이트'는 web_report_prompt 입니다. BE 는 web_unit 을 R09 범위에만 읽습니다(`back/app/core/measure.py:926, 1530`).
  - '⑥ 유닛 판정'은 현행 `frz.card_web` 유닛 플래그에서 나옵니다(measure.py:1360-1367).
- `web_report_prompt.report_fs`: web_unit 으로 FK 를 그렸지만 현행 DDL 에 없습니다. file_seq 혼자로는 (project_key, file_seq) 를 가리킬 수 없습니다.
- `web_report_prompt` 용도 WEBREG16: 레거시 프로필 스위치 `web_registered_only` 이고 카드 경로 요청에만 적용됩니다(`core/profile.py:145-150`, measure.py:286-318).
- `web_target_url`: `web_accuracy_flat` 스위치의 ⑥ 화면 모드에서 읽습니다(measure.py:1373-1376).

## 03_fact
- `job_index.status_code`: `3 기타` 가 빠졌습니다(DDL:444, `core/codes.py` STATUS_CODE).
- `answer_fact` 우선 노출도: 현행은 카드 ④ · 국가별 GEO 현황 모두 경쟁 순위(rank)입니다(`features/analytics/geo/markets/service.py:50, 82-85, 96`). own_fp 는 레거시 동등화를 위한 신규 열이고 근거는 지침 5-6. "카드 ④ = 경쟁 순위가 레거시"라는 근거는 레포에 없습니다.
- `answer_brand_fact`:
  - `rd.propagate_answer_gates` 는 std_in · elig · dflt · cyc_key · is_rep 만 복사합니다(DDL:3415-3440). std_in_nc 는 `rd.fill_answer_nc` 가 채웁니다(DDL:3591-3620).
  - exposure_answers = Σrid_n 은 `brand_exposure_per_alias` 스위치일 때만이고, 기본은 행 수입니다(`core/profile.py:104-108`, measure.py:1605-1606).
- `answer_stance_fact` 용도 '답변 상세'가 틀립니다. 상세는 `rd.v_answer_stance_raw` 를 읽습니다(`features/analytics/answers/detail/queries.py:120-126`).
- 확인된 맞는 것:
  - `*_nc` 열은 A41 `catalog_incl_deleted`(measure.py:352, 409; profile.py:88-92) · `freeze_at_publish`(measure.py:370) · ingest `rep_pick_latest_first`(elig_nc) 가 읽습니다.
  - rep_cit_delta 는 `rep_round_date_cell` 스위치에서 `is_rep <> (answer_key IN delta)` 입니다(measure.py:422-423, 443-445).
  - 톤 인용은 `count(DISTINCT url_key)` 입니다(`citations/tone/queries.py:71`).

- `kpi_cell` 우선 노출도 규칙: 03_fact 항목과 같습니다.

  - 입력은 `app.report_publication ⋈ app.report_site_fact` 입니다(`back/ingest/cycles/ledger/queries.py:292-304`).
  - 현행 PK 는 (round_date, file_seq) 입니다. prev_* 는 BE 가 읽지 않습니다.
- `url_prompt_cell`:
  - prompt_key OR 는 Website 자사 · 타겟 카드에만 해당합니다(measure.py:712-727, DC-02 결정 6).

## 11_pub
- 카드 경로 7개는 `core/card_routes.py` CARD_ROUTES 와 같습니다. 단 kpi/engines 는 website 만 카드이고, citations/domains 는 기간 미지정일 때만 카드입니다.
- `frz.generation.surface` 는 int CHECK 1~3 입니다. 허브 발행은 global · website 만 만듭니다.
- 현행 카드 뷰는 동결 셀 집합(frz.cell)으로 **현행 rd.answer 를 라이브로** 읽습니다. 동결 뒤 바뀐 답변만 frz.kept · keep_* 보관 행으로 읽습니다(`frz.card_answer_w` 정의). 골드의 build_id 고정은 이 보관 장치를 대체하는 설계입니다.
- `frz.ops_judgment` 가 문서에 없습니다(BE 가 읽는지 확인).

  - `rcache.tg_bump` 트리거 33개 테이블(app 13 · frz 1 · rd 19)이 올리는 `sum(rcache.data_version.version)`
  - `rd.today_kst()`
  - `core/result_cache.py:32-33` docstring('app 11 + rd 15')은 낡았습니다.
- `active_release` 의 "(승인 없음, 20261015 회의)": 회의록에는 '논의 · 제안'으로 "골드는 승인 없이 회차마다 자동 생성"만 있습니다(`20261015/01_architecture.md:58`, actions A04). 검증 게이트 · 짧은 트랜잭션 · 포인터 전환은 설계입니다.

## 14_queue
- judgment_change 를 쌓는 DB 트리거는 둘뿐입니다.
  - `app.prompt` `prompt_catalog_change` → catalog · prompt_kind (DDL:1060)
  - `app.project` `project_setting_change` → project_setting (DDL:975)
  - 나머지는 BE 서비스가 `core/write.enqueue_change` 로 넣습니다.
- BE 쓰기 경로가 없는 설정이 있습니다: owned_base, brand, competitor_domain_token, non_competitor_name, hidden_market, rule_param, rule_set, website_prompt, website_report_unit, citation_category, report_publication.
  - 그래서 kind owned_base · brand_rule · competitor_token · hidden_market · website_catalog · rule_param · report_publication 은 지금 생산자가 없습니다.
- 적재기의 app 쓰기는 상태 열만이 아닙니다.
  - project.scope_project_id · prompt.scope_prompt_id(`back/ingest/cycles/workers/queries.py:66, 69`)
  - ecat_apply · ecat_review · ecat_audit_log
  - `app.ecat_activate` 를 통한 ecat_version 상태 · entity_registry · entity_alias 교체(DDL:4347-4357)
  - access_audit_log 파티션 생성
- payload 필수 kind 에 entity_version(apply_id · op, DDL:4137)과 dfs_fetch(`core/contracts.py:178`)가 더 있습니다.
- scope_prompt:
  - 큐 행은 수집 감시의 투영 공백 자동 채움에서만 생깁니다(`back/ingest/cycles/watch/service.py:201`).
  - Scope 쪽 regions · lang · kind 변경은 큐 없이 `rejudge('scope_prompt')` 를 바로 부릅니다(`back/ingest/pull/sync/service.py:5-6, 153`).
