# 골드 ERD 요소 검토 지침

> **2026-10-20 사용자 지시: 이 문서는 메달리온 골드 레벨 ERD 만 담는 골드 설계 문서입니다.**
> - 페이지에는 ERD 탭 · 그림 · 상세 패널만 남깁니다. 화면 커버리지 · 현행 열 대응은 키트 빌드 검사(`node node_check.js`)로만 확인합니다.
> - 현행 대응(rd · frz · ext · ing), 현행 동작 설명, BE 내부(프로필 스위치 · 코드 경로 · API 경로), app · 캐시(rcache · 결과 캐시 · judgment_change · scope_outbox · app.*) 내용은 모두 지웁니다.
> - 골드가 참조하던 app 테이블은 골드 차원으로 투영하거나(예: `dim_owned_base`) 참조 없는 식별자 열로 둡니다. 골드 밖을 가리키는 FK 는 두지 않습니다.
> - 아래 7절 '골드 설계 변환 규칙'이 4절보다 우선합니다.

페이지에 보이는 **모든 요소**에 판정과 근거를 남깁니다. 틀린 요소는 원본(`src/`)을 고친 뒤 판정합니다. `node review.js check <html>` 가 미검토 0 이어야 빌드 결과를 루트에 올립니다.

## 1. 작업 순서

```
python -X utf8 -I build.py <내 출력.html>                 # src/ 를 조립
node review.js todo <내 출력.html> <원장>                 # 그 원장에서 검토할 요소(JSON)
  … 근거 확인 · src 수정 · 다시 build …
node review.js put <내 출력.html> <원장> <판정.json>      # 판정 기록 (t 는 현재 텍스트로 자동 채움)
node review.js check <내 출력.html>                       # 전체 대조
node node_check.js <내 출력.html>                         # 열 · 모듈 · 화면 항목 · ERD 무결성
```

- 원장 이름 = 표 정의 파일 이름(`01_dim` …) · `views` · `schema` · `page` · `manual` · `colmap`. 파일은 `검토/<원장>.json`.
- 판정.json: `{ "T:dim_region:inputs": { "v": "cur", "e": "ingest/project/apply/queries.py:262-272" } }`
- 텍스트를 고치면 그 요소는 '변경 후 미검토'가 됩니다. 고친 뒤 다시 `put` 합니다.
- 다른 사람이 맡은 파일은 고치지 않습니다. 빌드가 남의 파일 문법 오류로 실패하면 잠시 뒤 다시 합니다.
- 커밋하지 않습니다. `back/` · `front/` · `ingest/` 코드는 읽기만 합니다.

## 2. 요소 키

| 키 | 화면 위치 | 텍스트 |
|---|---|---|
| `T:<id>:head` | ERD 상자 제목 · 상자 아래 한 줄(grain) | `{name, s, fam, grain}` |
| `T:<id>:col:<i>` | 상자 열 줄 · 상세 열 표 | `[이름, 키, 설명, 참조, 펼침]` |
| `T:<id>:grain · pk · inputs · triggers · uses · cur` | 상세 패널 '한 행 · PK · 입력 · 갱신 · 용도 · 현행' | 문자열 |
| `T:<id>:rule:<i>` | 상세 패널 '규칙' | 문자열 |
| `T:<id>_ref:ghost` | 다른 탭 참조 상자 | `{name, cols}` |
| `V:<탭>` · `V:<탭>:note` · `V:<탭>:derive:<i>` | 탭 이름 · 탭 노트 · 파생 화살표 라벨 | |
| `N:<대상>` | 신규 · 변경 요청 표 행 | |
| `AG:` · `IN:` · `SC:` | 스키마 패널 그룹 · 설명 · 규칙 | |
| `H:` · `J:` · `K:` | 정적 HTML 문구 · 렌더 코드 문구 · 상수 | |
| `M:<라우트>|<항목>` | 화면 기능 전수 대응의 수동 매핑 | |
| `CN:` | 현행 열 대응 표의 설명 | |

## 3. 판정

| v | 뜻 | 근거(e) |
|---|---|---|
| `cur` | 현행 사실을 말한다 (열 이름 · 값 · 동작 · 화면 사용) | `레포경로:줄` · `db:rd.job.status_code` · `sql: …` 중 하나 이상. 여러 개면 ` · ` 로 잇는다 |
| `des` | 골드 설계(신규 · 변경)를 말한다. 현행 사실을 주장하지 않는다 | 요구 출처: 화면 항목(라우트 · 항목), 결정, 사용자 지시, NEWREQ |
| `dec` | 회의 결정을 말한다 | 회의록 경로 + 결정 ID (`hmg-geo-hub-discussion-history/20261015/01_architecture.md D07`) |
| `lbl` | 라벨 · 표기 · 계산으로 채우는 자리 | 생략 가능 |

현행과 설계가 한 요소에 섞이면 `cur` 로 두고 e 에 현행 근거를 적은 뒤 `· 설계: …` 를 덧붙입니다. 텍스트에서도 현행 부분은 "현행 …" 으로 시작해 구분합니다.

**정확의 기준**: 요소의 모든 낱말이 근거와 맞아야 합니다. enum 값 하나, 열 이름 하나, 화면 이름 하나라도 틀리면 고칩니다. 근거를 찾지 못한 현행 주장은 지우거나 설계 문장으로 바꿉니다. "거의 맞음"은 없습니다.

## 4. 필드별 규칙

- **열 행** `[이름, 키, 설명, 참조, 펼침]`
  - 현행 열을 옮긴 것은 현행 이름 그대로 둡니다. 새 열은 설명 끝에 `(신규)` 를 붙입니다.
  - 키: `PK` 기본 키, `FK` 참조, `PF` 둘 다, `UK` 유일. 복합 유일이면 설명에 함께 적습니다.
  - 참조가 있으면 키는 FK 또는 PF 여야 합니다(키 묶음 `s:'key'` 제외).
  - 설명은 상자에 잘려 보입니다. 24자 안팎으로 씁니다. enum 은 현행 CHECK · 코드 값을 빠짐없이 적습니다.
  - 펼침(5번째)은 이름이 `C 좌표` · `prev_*` 처럼 열 이름이 아닌 표기일 때만 둡니다. 실제 물리 열 목록입니다.
- **grain (상자)**: 짧은 한 줄. **d.grain (상세)**: "… 1개 = 1행" 형식.
- **inputs**: 누가 무엇으로 채우는지. 골드는 `데이터 분석팀` 으로 시작하고, 판정에 읽는 app 설정만 덧붙입니다(`데이터 분석팀 · app.owned_base`). 브론즈 · 실버 단계 이름(답변 정제 · 언급 추출 …)은 쓰지 않습니다. 신규 테이블은 `데이터 분석팀 (출처 제안: …)`.
  - app 테이블을 적으려면 현행 적재기(`back/ingest`)가 실제로 그 테이블을 읽는지 확인합니다.
- **triggers**: 언제 다시 만들어지는지. 현행에 없는 경로("정기 수집" 등)를 현행처럼 쓰지 않습니다.
- **uses**: 화면 · API. `node uses.js <id>` 로 후보를 보고 코드로 확인합니다. 화면 이름은 ★ 점검표 메뉴 이름(`inventory.json` 의 menu)을 씁니다. 신규 화면 공급(정적 표본 대체)은 "(신규 공급)" 으로 구분합니다.
- **cur**: `rd.x` 처럼 현행 객체. "(열 전부)" 는 현행 열이 이름까지 전부 같을 때만 씁니다. 다르면 차이를 적습니다(`rd.job (load_id → last_build_id)`). 신규면 `없음 (신규 …)`.
- **rules**: 구현 규칙. 현행 동작이면 근거를, 설계면 "골드에서는 …" 처럼 설계임이 드러나게 씁니다.

4. 용어: 골드를 채우는 쪽은 "데이터 분석팀"(사용자 10-19). 회의록 용어(수집팀 · 파이프라인 팀)와 다르지만 이 문서는 사용자 용어를 씁니다.

## 7. 골드 설계 변환 규칙 (2026-10-20)

**남길 것.** 골드가 담는 것만 남깁니다.
- 열 · 키 · 값 집합
- 한 행 정의 · PK
- 채우는 쪽: 데이터 분석팀, 그리고 같은 골드 안의 입력 테이블
- 다시 만드는 시점 (설계)
- 쓰는 화면: ★ 점검표 메뉴 이름 · 화면 요소
- 골드 설계 규칙

**지울 것.**
- `d.cur` 필드 전체.
- 현행 시스템 서술: "현행 …" 문장이나 절, `rd.` · `frz.` · `ext.` · `ing.` 객체 이름, 현행 열 이름 대응("현행 load_id"), 이관 설명, 레거시와의 비교.
- 표지: `(신규)` · `(신규 공급)` · `(현행)`.
- BE 내부:
  - 프로필 스위치 이름(`web_registered_only` · `freeze_at_publish` · `brand_exposure_per_alias` · `catalog_incl_deleted` · `rep_round_date_cell` · `web_accuracy_flat` · `filter_options` · A41 · WEBREG16 · R09 …)
  - 코드 경로 · 함수 이름
  - API 경로(`/v1/…`)
  - 화면이 없는 용도("API(화면 없음)")
- app · 캐시: `app.*`, judgment_change, scope_outbox, rcache, 결과 캐시, GEO HUB 설정 화면 이야기.

**바꿔 쓸 것.**
- **app 을 가리키던 열:** 골드 차원으로 투영하거나 참조 없는 식별자로 둡니다. 골드 밖 FK 는 금지이고 `node_check` 가 잡습니다.
- **스위치 때문에 있는 열:** 스위치 이름 대신 그 열이 담는 뜻을 씁니다(예: `cat_mask_all` = 삭제 행 포함 카탈로그 비트).
- **inputs:** `데이터 분석팀`, `데이터 분석팀 · <골드 테이블>`, `데이터 분석팀 (출처 제안: …)` 중 하나의 꼴.
- **uses:** 화면만 씁니다. 화면에 쓰이지 않는 용도는 지웁니다.
- **rules:** 모두 설계 규칙이므로 "골드에서는" 같은 접두를 떼고 규칙만 씁니다.
- **BE 를 주어로 쓰지 않습니다.** "조회 때 계산(저장하지 않음)"처럼 씁니다.

**바꾸지 않을 것.**
- 현행 열을 옮긴 열의 이름.
  - `node node_check.js` 의 현행 열 1039 · 화면 항목 789 가 이 이름에 걸려 있습니다.
  - `manual_map.py` 가 참조하는 열을 바꿔야 하면 조정자에게 알립니다.
- 값 집합(enum). 골드 값 정의로 남깁니다.

**판정.**
- 지우기만 하거나 같은 뜻으로 줄여서 남은 문장이 여전히 근거와 맞으면, 옛 판정 · 근거를 물려받습니다. `todo` 의 `prev` 에 있습니다.
- 새로 쓴 문장은 근거를 다시 확인합니다.
- 화면 사용(uses)처럼 현행 화면 사실을 말하면 `cur`, 설계 문장은 `des` 입니다.
