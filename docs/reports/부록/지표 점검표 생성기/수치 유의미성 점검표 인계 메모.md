다른 PC에서 이어서 작업하기 위한 메모입니다. 이 메모만으로 현재 상태와 다음 할 일을 알 수 있게 적었습니다.

## 1. 문서와 생성기

- 결과 문서: 워크스페이스 루트의 `★ 수치 유의미성 점검표.html`. 레포 밖이라 커밋되지 않습니다.
  - 이 폴더에서 `python -I build_metric_meaning.py`를 실행하면 다시 만들어집니다.
- 판정 질문은 하나입니다: **이 수치가 전략팀(HMG 전략기획실)이나 마케팅 팀에 인사이트를 줄 수 있는가.**
  - 구현 여부나 값의 정확도는 판정하지 않습니다(사용자 결정).
- 파일 구성:
  - `metric_meaning_data.py`: 지표 묶기·데이터 소스 분류·판정 기준(INSIGHT_CRITERIA·TIERS·USES)·표현 개편 원칙(ELEMENTS·PRINCIPLES)·진행 현황.
  - `조사 데이터/insight_judgments.json`: 성과 지표 120개의 인사이트 판정. 등급·용도·판정 근거 4개·인사이트 문장·개선안이 들어 있습니다.
  - `조사 데이터/insight_redesign.json`: 핵심 지표 26개의 개편안(5요소 진단·바꿀 표현·헤드라인 예시)과 개편 뷰 6개의 구성.
  - `metric_meaning_template.html`: 화면 구조와 디자인(Pretendard, 디자인 토큰, 하비볼 ●◐○).
- 판정을 고칠 때는 두 JSON을 직접 고칩니다. 생성기가 아래 규칙을 검사하고, 맞지 않으면 생성이 실패합니다.
  - 등급과 판정 근거가 서로 맞는가.
  - 등급과 용도가 서로 맞는가.
  - 모든 핵심·보조 지표가 개편 뷰 하나에 들어가는가.
- 결과(2026-10-19): 핵심 지표 26 · 보조 지표 57 · 규모 정보 23 · 인사이트 없음 14. 운영 지표 55개는 점검에서 뺐습니다.

## 3. 진행 중: 개편안 시험 프로젝트 `hmg-geo-hub-test`

사용자 결정(2026-10-19):

- 폴더는 워크스페이스에 `hmg-geo-hub-test`로 만들고, 본 레포를 **로컬 git clone**해서 씁니다. 통째 복사는 하지 않습니다.
- 화면은 **기존 화면을 개편안으로 교체**합니다.
- 첫 범위는 더미 DB에 데이터가 있는 **4개 뷰**입니다.
  - 콘텐츠 기회 백로그
  - 경쟁 포지션 보드
  - 출처 공략 리스트
  - AI 추천 퍼널(GA4 단계 제외)
  - 더미 DB에 없는 칸은 '데이터 없음'으로 표시합니다.
- 더미 DB에 없는 데이터: GA4, 키워드 검색량, 소셜, 페이지 크롤. 그래서 시장 우선순위 맵의 시장 중요도 축과 페이지 성과 보드는 나중에 합니다.

## 4. 교체 대상 화면과 API 맵 (2026-10-19 조사)

경로는 레포 루트 기준입니다. `F/` = `front/`, `B/` = `back/app/`, 화면 라우트 = `F/app/[locale]/(dash)/` 아래.

### 공통 구조

- 화면마다 API 모드와 레거시 모드 중 하나로 동작합니다.
  - 스위치는 `F/lib/hgh/client.ts`의 `hghSource(group)`이며, 환경변수 `HGH_SOURCE_<그룹>=api|legacy`를 읽습니다. 값이 없으면 legacy입니다.
  - 그룹: Overview = G1, 답변 분석(언급·인용) = G2, AI 퍼널 = G4.
  - 화면 코드는 `isAnalysisApi(area, surface)`(`F/lib/hgh/adapters/filters.ts`)로 분기합니다.
- API 호출은 `hghGet<경로>()`(`client.ts`)로 하고, 응답 타입은 `F/lib/hgh/api-types.ts`에서 가져옵니다.
  - 이 파일은 `npm run gen:api-types`가 FastAPI OpenAPI에서 생성합니다. 백엔드 스키마를 바꾸면 다시 생성해야 하고, 생성 결과가 어긋나면 CI가 실패합니다.
- 필터 흐름: URL 파라미터 → `readStandardFilters`(`F/components/dash/standard-filters.ts`) → `analysisQuery`(`filters.ts`) → `/v1/*` 쿼리.
  - 여러 값은 `~`로 이어 붙입니다.
  - 필터 바는 `DimensionFilterPanel`(`F/components/dash/dimension-filter-panel.tsx`)을 공통으로 씁니다.
- 백엔드 엔드포인트는 `B/features/<영역>/<도메인>/<기능>/`의 router·schemas·service·queries 4개 파일로 되어 있습니다.
  - 모든 분석 엔드포인트가 `CommonFilters`(`B/core/filters.py`)를 받고, 응답은 `{data, meta}` 봉투입니다.
  - 화면별 모듈 목록은 `back/app/views/VIEWS.md`, 전체 엔드포인트 목록은 `back/FEATURES.md`에 있습니다.
- UI 스택: Tailwind v4 + shadcn(`F/components/ui/`), 차트는 recharts, 지도는 d3-geo. 문구는 `F/messages/ko.json`에 있습니다.
- 사이드 메뉴는 `F/components/dash/sidebar.tsx`의 `STANDARD_SUB_ITEMS`, 접근 권한은 `F/lib/auth/route-policy.ts`에서 정합니다.

### 개편 뷰에 필요한 데이터와 현재 API의 빈칸

- 프롬프트 × 브랜드 매트릭스를 한 번에 주는 엔드포인트가 없습니다.
  - `/v1/mentions/prompts?mode=brand`는 호출 한 번에 브랜드 하나만 받습니다.
- 프롬프트 → 인용 도메인을 주는 엔드포인트가 없습니다.
  - 반대 방향(도메인 → 프롬프트)은 `/v1/citations/domains/{skey}`에 있습니다.
  - `/v1/citations/prompts`는 프롬프트별 인용 수와 자사 인용 유무만 줍니다.
- 프롬프트 × 엔진별 ACR 승자는 `/v1/funnel/acr`의 `battle`에 이미 있습니다.
- 언급된 브랜드별 인용 도메인은 `/v1/citations/domains?mention_brand=`로 받을 수 있습니다. 이것도 호출 한 번에 브랜드 하나입니다.
- 시장별 KPI는 `/v1/geo`에 있습니다(지역·국가별 M01–M05, 자사 순위, 최상위 경쟁사).
  - 브랜드·엔진·추이에는 국가별 group_by가 없어서, 국가마다 따로 호출해야 합니다.
- 엔진별 분해는 이미 있습니다: `/v1/mentions/brands?group_by=engine`, `/v1/kpi/engines`, `/v1/trend?dimension=engine`.
