## 2. 역할·문서 대조 모순

1. **A-7 "S2W 키로 수동 측정을 여는 것은 협의 중"** — 협의안 §4 제목이 "변경 예정: S2W 키에 개방"이고 부록 OpenSpec에 요구사항("파트너 키 수동 측정 … SHALL")까지 적혀 있다. 앤서가 열기로 **한** 것이며, 협의 대상은 하루 한도·비용(C2)과 전환 일정(C5)이다. (협의안:124, 277, 364-377, 246-250)
2. **분석 소유 기준의 혼선(E-1~E-4 "있음" vs E-5 "부분")** — 협의안 §1은 "Scope는 원문만 제공, 분석 값은 S2W 분석 엔진이 계산"(:30)이지만, 현재 운영(v0)은 **Scope가 분석까지 해서 pull로 들어온다**(AED:38 "v0 = Scope가 계속 분석해서 pull로 들어오는 값"). E-1·E-2가 근거로 든 모델명은 **인계본 scope-analysis/Scope 코어의 설정값**이고 S2W가 운영하는 엔진이 아니다. 전환 뒤 S2W가 가져야 할 엔진은 "Python 재구현 설계 초안, 미구현"(HS/README.md:22; AED:9 status 검토중)이며 "TS 코드 이식"은 비목표(AED:85). E-1~E-4를 "있음"으로 두려면 "Scope 측/인계본 기준"이라는 주석이 필요하다.
3. **I-3 "20분 주기로 Scope에서 원문을 당겨"** — 현재 pull은 원문과 **Scope 분석값(occurrences·stances)**을 함께 받는다(AED:576 `include=occurrences,stances`). 협의안 §6 원문 전용 API는 "신설 예정"(:169). 행의 "판정·투영"은 허브 규칙 판정(R-rules)이지 LLM 분석이 아니다 — 지금 문장은 S2W가 원문을 받아 분석까지 하는 것처럼 읽힌다.
4. **A-5 "한국 시장 질문도 ChatGPT·Gemini 답변만 본다"** — DeepSeek도 선택 가능하되 국가 구분 없이 `region=US`로 기록된다(협의안:62, 379-387). "ChatGPT·Gemini(·DeepSeek, 국가 구분 없음)"로.
5. **B-6 ⑥ 산식** — "지정한 페이지를 인용한 답변 ÷ 자사 URL을 인용한 답변"은 **'AI 타겟 출처 인용률(citationAccuracy)'**의 식이다(ko.json:273-275 이름, :286, :299; measure.py 도크 "인용 정확도 = 타겟 ∧ 자사 / 자사"). ⑥ 타겟 URL 인용률은 현행 = **타겟 URL 인용 프롬프트 수 ÷ 측정 프롬프트 수**(ko.json:284, 296), 신설계(A2/C-4) = 타겟 URL 적중 측정 ÷ 인용 모수 측정(`cit_in`, 웹사이트 등록 프롬프트)(units/C-4…json:36; DESIGN-CONTRACT.md:9 A2).
6. **B-5 ⑤** — 글로벌 표면의 분자는 자사 base URL이 아니라 **출처 카테고리 Official(HMG)**이다(measure.py 도크 M05 global; ko.json `citationShareGlobal`:287, 300). 웹사이트·프로젝트 표면만 자사 base URL(`cit_owned`). 행 설명은 후자만 적었다.
7. **B-2 ②** — 명세 M02는 "당사 언급 / 전체 언급"(spec:235), ko.json은 "전체 업계 브랜드 언급 횟수"(:278). "비경쟁 브랜드를 뺀"은 엔티티 명부 role=excluded가 `ment_*` 열에 반영되는 간접 근거(units/AD-2…json:48)로만 성립한다. 확인(간접).
8. **B-11 근거 M-1** — M-1 JSON에 자동 비교 기준 문구가 없다. 근거는 ko.json:552 autoNote("지정된 비교 기준이 없어 **현재 필터에서** 점유율 1위인 외부 브랜드를 자동으로 비교"). "집계 기간마다" → "현재 필터에서".
9. **F-4 근거 "contracts/v1.ts citations"** — v1.ts:174는 "`citations[]`도 싣지 않는다"(분석 티켓은 `citationHostsToClassify[]`만). 인용 URL이 기록된다는 근거로 부적절. 적절한 근거: 협의안 §6.1 `citations: [{url, title, domain}]`(:189, 207) 또는 front 미러 `scope_citations`.
10. **C-4 근거 "contracts/v1.ts"** — 이 파일은 Scope 코어↔분석 서비스의 **분석 티켓 계약**이지 수집 계약이 아니다. 수집 계약(협의안 §6.1 :176-208)에도 검색 실행 플래그가 없으므로 결론은 유지되지만 근거를 협의안으로 바꿔야 한다.
11. **I-1 근거 "back core/scope"** — 그런 모듈이 없다. 실제는 `HS/back/app/core/auth.py` (`DataScope(principal, refs)`, default-deny :9; `Role` :50; `scope_brands/regions/countries` :164-167).
12. **I-4·H-2 인계본 알림** — `_archive/hmg-geo/lib/alerts`는 Slack이 아니라 **GitHub issue**(github-issue.ts; 루트 README.md:33 `GITHUB_ALERT_REPO`). "운영 장애 알림(Slack)만 있다"는 hub-share back 기준이다.
13. **F-3 근거** — "이탈리아 질문이 kia.com/uk를 인용" 예시는 `kpi5-base-url-attribution-policy.md:10-13`에 있다. playbook:29는 `kia.com/it`·`kia.com/uk`를 경계 예시로 언급할 뿐이다.
14. **E-3 "사전이 바뀌면 과거 인용도 다시 분류"** — front는 read-time 파생이라 즉시 재분류(taxonomy.ts:19-20) 맞다. back 신설계는 적재 시 선계산 + 오버라이드 편집 시 재판정(`judgment_change 'citation_override'`)(units/AD-3…json:10; measure.py 도크). 결과는 같지만 메커니즘이 다르다.
15. **G-7 "보여 준다"** — AI 가시성 화면은 표준 SNB에서 `hidden: true`("mock-only")이고(HS/front/lib/auth/route-policy.ts:99-109), 프로젝트 SNB에서도 숨김(app/[locale]/(dash)/projects/[id]/ai-funnel/page.tsx:4). 라우트 직접 접근만 남아 있다.
