19번 문서의 잔여 문제 [5]·[6]에 대한 수정 기록이다. 화면·문구·메뉴·사용 흐름·권한은 바꾸지 않았고, 데이터를 읽는 방식과 잘림 처리만 고쳤다. 19번 문서는 당시 점검 스냅샷으로 그대로 둔다.

운영 API·인증·DB 요청 0건. 로컬 합성 DB(PostgreSQL 17)·모의 응답·단위/동등성 시험으로만 검증했다.

기능·디자인 보존

  • 화면 구조 변경 없음: context-map-view.tsx의 JSX는 한 줄도 바뀌지 않았다. 바뀐 것은 판정 함수 import 1줄과 판정 호출 3곳이다. 문구·메시지 키 추가도 없다.
  • 판정 의미 동일: ‘이미 추가됨’ = 생성 문구가 후보 풀에 정확히 같은 텍스트로 있음. 기존 addedTexts.has(question)와 같은 규칙이며, 비슷한 문구는 기존처럼 similar_to 힌트로만 보인다. 판정 함수는 lib/social-scraping/catalog-added.ts 하나로, 화면과 동등성 시험이 같은 함수를 쓴다.
  • legacy 경로 변경 없음: 직접 DB 경로는 지금처럼 후보 텍스트 전체로 판정한다.
  • 남는 차이(경합 시에만): 나중에 붙는 행의 판정 시점이 legacy는 ‘페이지 진입 때 읽은 후보 목록’, 수정 후 API는 ‘생성 응답 시점의 후보 풀’이다. 다른 화면에서 동시에 후보를 추가한 경우에만 결과가 다를 수 있고, 이때 수정 후 쪽이 최신 상태다.

API 계약 변경과 배포 순서

GET·POST /v1/intent/social/prompts의 GeneratedPrompt에 in_candidate_pool: boolean 응답 필드 1개를 추가했다. 기존 operation 218개·스키마 612개의 수와 기존 필드는 그대로이며, openapi.json·api-types.ts를 다시 생성했다.

남은 작업

19번의 나머지 항목은 이번 범위가 아니다: 신규 /screen 조회의 필터 옵션·총건수 반복 집계, 결과 캐시 기본 비활성, 대시보드 KPI 재계산. 20번에서 확인한 GA4 카드의 불필요한 페이지 집계와 QA 진행률 중복 계산과 함께 다음 작업(BE 중복 계산)에서 다룬다.

작업 위치: 코드와 이 문서는 같은 저장소(s2w-saip/hmg-geo-hub)의 main에 있다. 이 문서와 16~22번 문서의 코드 링크는 저장소로 옮기면서 저장소 루트(front/·back/) 기준으로 바꿨다. 행 번호는 각 문서가 밝힌 기준 커밋 시점의 값이다.
