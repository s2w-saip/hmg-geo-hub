01 · ARCHITECTURE AT A GLANCE

Next.js와 FastAPI 데이터 경로가 공존하는 전환 구조

현재 소스는 Next.js 풀스택 앱 + FastAPI 모듈형 모놀리스 + 별도 Python 적재 워커 + PostgreSQL로 구성된다. Next.js 안에 기존 데이터 조회·업무 코드가 남아 있고, 그룹별 플래그가 켜진 부분부터 FastAPI로 옮기는 구조다.

이 문서의 ‘현재’는 로컬 공유 소스의 현재다. 2026-10-08에 HEAD 392ca454를 분석했다. README는 2026-10-02 개발 리비전 72c260a3의 공유 스냅샷이라고 설명한다. 운영 환경변수·DB·트래픽·배포 이력은 조회하지 않았다. 따라서 특정 경로가 운영에서 활성화됐다고 단정하지 않는다. A01 A02

06 · END-TO-END FLOWS

요청이 처리되는 세 가지 흐름

화면 조회: 데이터를 어디서 읽는지 먼저 결정

  1. 브라우저 → Next.js

    로그인 쿠키·locale·페이지 접근을 처리한다. 서버 데이터 함수가 계정과 요청 필터를 확인한다.

  2. 업무 그룹·surface로 source 선택

    legacy면 repository/미러/요약·기존 외부 연동을 사용한다. api면 서버 BFF 클라이언트를 호출한다.

  3. API 경로: 인증 → 읽기 컨텍스트 → SQL

    JWT 검증, DB 계정·권한·스코프, 회차·필터를 적용한다. 허용된 캐시 경로는 권한 검사 뒤 조회한다. 지표에 따라 rd 또는 frz를 선택한다.

  4. 응답 → 어댑터 → 화면

    meta의 필터·억제·페이지 정보를 화면 모델로 변환한다. 첫 핵심 섹션과 나머지 스트리밍 섹션의 호출 시점이 다르다.

새 API 설정 변경: 저장 성공과 지표 반영 완료는 두 단계

  1. 사용자 요청 → BFF → 쓰기 API

    역할·운영자 권한과 프로젝트 접근을 검사한다.

  2. 하나의 DB 트랜잭션

    app 운영 행을 갱신한다. 변경 종류에 따라 코드 또는 트리거가 judgment_change를 남긴다. Scope 반영이 필요한 경우 scope_outbox도 같은 트랜잭션에 남긴다.

  3. API 응답 시점

    운영 데이터의 커밋이 끝난 시점이다. 외부 Scope 작업과 조회 모델 재판정까지 끝났다는 뜻은 아니다.

  4. 워커가 후속 반영

화면에는 저장됨·반영 대기·반영 실패를 구분할 수 있는 작업 상태가 필요하다. 이는 현재 비동기 구조에서 도출한 UI/운영 계약이며, 모든 화면이 이미 이 상태를 표시한다는 뜻은 아니다.
