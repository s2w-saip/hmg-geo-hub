## 공통 규칙

### 같은 트리에서 지킬 것

- git으로 작업 트리를 바꾸는 명령을 쓰지 않는다: `pull` · `rebase` · `reset` · `checkout` · `stash` · `clean`. 다른 세션의 작업이 날아간다.
- 자기 소유 파일만 고친다(각 절의 '소유').
- 공용 파일을 고칠 때는 먼저 아래 '공유 파일 잠금' 표에 한 줄 적는다.
  - 공용 파일: `back/bff/screens/_*.py`, `shared.py`, `back/bff/api.py`, `back/bff/app.py`, `front/app/[locale]/(renewal)/renewal/_components/*`, `front/components/renewal-ui/*`, `front/lib/*`, 골든 `back/bff/tests/golden/README.md`.
  - 다른 세션이 잠근 파일이면 사용자에게 묻는다.
- 문구 파일 `front/messages/ko.json` · `en.json` · `units/*.json` 다루는 법:
  - 자기 화면의 키만 Edit로 바꿔 넣는다.
  - 파일 전체를 다시 쓰거나, 정렬·포맷 도구를 돌리지 않는다.

### 로컬 스택 (하나만 둔다)

- HUB 저장소(Docker), Gold API `127.0.0.1:5555`, Next dev `127.0.0.1:3333`은 S4가 한 번 띄운다(`scripts/start-hub-storage.ps1`). 상태는 `http://127.0.0.1:5555/healthz`로 본다.
- 다른 세션은 스택을 띄우거나, 끄거나, 다시 띄우지 않는다. 자기가 띄우지 않은 프로세스는 끄지 않는다.
- 스택이 죽어 있으면 결과 칸에 적고, 스택이 필요 없는 일을 먼저 한다.
- 프런트에서 `next build`를 돌리지 않는다. dev 서버가 쓰는 `.next`를 덮어쓴다.
- BFF 시험용 dev DB는 `bash back/db/dev-db.sh up` 뒤 자기 이름으로 clone해서 쓴다: `s1` · `s2` · `s3` · `s4`.
- 2026-10-30 기동 상태: API · Next · HUB 저장소 모두 정상이다. 다만 `manage.py sync-gold-catalog`가 대량 변경 가드에서 멈췄다(28,073개 항목에 새 리비전 29,008개). 그래서 HUB 카탈로그는 이전 가져오기 상태이고, `--expect-mass-change`로 다시 돌리지 않았다. 이 가져오기가 필요한 세션은 사용자에게 묻는다.

### 시험

- 자기 범위 시험을 먼저 돌린다. 세션 끝에 BFF 시험 전체와 프런트 `npm run test` · `typecheck` · `lint`를 돌린다.
- 다른 세션이 작업 중인 파일 때문에 실패하면 결과 칸에 적고, 그 파일은 고치지 않는다.
- 버그 수정은 재현 시험(수정 전 실패 확인) → 수정 → 전후 비교 순서로 한다.
- Gold 값 대조는 `gold-metric-review.html` 1절 방법을 따른다. 읽기 전용 계정으로 Gold 사실 테이블에서 직접 계산한다.
- 시험 환경(Windows 주의점 포함): `p4-acr-model-denominator.html` 5절.
- 데이터 원칙은 admin-todo 규칙 5를 따른다. Gold에 쓰지 않는다. 귀속을 다시 정하지 않는다. 새 판단을 만들지 않는다.

### 커밋

- 사용자가 요청할 때만 한다.
- 순서는 S2 → S3 → S4 → S1. 각 세션은 자기 소유 파일만 경로로 지정해 스테이징한다.
- 문구 json은 처음 커밋하는 세션이 파일째 넣는다. 키를 더하는 것은 서로 해가 없어서다. 뒤 세션은 바뀐 것이 남아 있으면 다시 넣는다.
