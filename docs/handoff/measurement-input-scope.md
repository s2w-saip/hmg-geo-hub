# T6.3 측정 설정 입력 범위

2026-11-07 기준. Website · Global 측정 설정 입력 화면을 만들 때의 범위표다. 코드와 입력 DB를 대조했다.

## 지금 있는 것

| 항목 | 값 |
|---|---|
| 프로젝트 | Global 1, Website 127, Project 130. 전부 `active` |
| 측정 설정 버전 | 258개 모두 v1 이상 |
| 소유 URL 등록 | Website 106/127, Project 0/130, Global 0/1 |
| 추적 URL 등록 | 0 |
| 측정 주기 · ACR 반복 수 | 0/258 |
| 이름 | 입력 DB `definition.name`과 `gold.dim_project` 모두 없음. 화면은 짧은 ID로 보인다 |
| 쓰기 경로 | `POST /v1/hub/projects/{id}/measurement`는 표면을 가리지 않는다. 폼은 Project › Setting에만 있다 |
| 새 프로젝트 | `catalog.project`를 만드는 코드는 `sync_catalog.py`뿐이었고 T10.1로 멈췄다. 레거시 `/projects/new`는 이전 저장소에 쓴다 |

## 이번에 하는 것

| 항목 | 내용 |
|---|---|
| Admin › 측정 설정 | `/renewal/admin/standards/measurement`. 세 표면의 프로젝트를 한 목록으로 보고, 행을 누르면 서랍에서 Project › Setting과 같은 폼으로 고친다 |
| 찾기 | 표면, 소유 URL 등록 여부, 브랜드, 검색. 소유 URL 미등록 수를 목록 위에 보인다 |
| 프로젝트 만들기 | Project 표면만. 입력 항목은 레거시 `/projects/new`와 같다(제목, 설명, 도메인, 브랜드, 국가, AI 엔진) |
| 쓰기 | 모두 허브 서버. 프로젝트와 첫 버전, 첫 측정 설정을 한 트랜잭션에 넣는다 |
| 읽기 | `GET /v1/hub/measurements`. 입력 DB만 읽으므로 허브 서버에 둔다 |
| 새 프로젝트의 탭 | 첫 회차가 적재되기 전에도 Project 목록과 프로젝트 탭에서 열린다. Setting · Prompt는 입력 DB로 보이고 저장되며, 나머지 화면은 '아직 측정 데이터가 없습니다'를 보인다. 이름은 입력 DB의 값을 목록과 탭 카드에 쓴다 |

## 하지 않는 것

| 항목 | 이유 |
|---|---|
| Website 사이트 추가 | 브랜드 × 국가 단위이고 측정 단위(`web_units`)를 입력하는 폼이 없다. 필요해지면 별도 태스크로 한다 |
| `web_units` 편집 | 지금 폼처럼 보여 주기만 하고 저장할 때 그대로 넘긴다 |
| 측정 설정 · 프로젝트 삭제 | 값을 비우는 것으로 충분하다. 프로젝트를 없애는 흐름은 소비자(수집)와 함께 정한다 |
| GA4 속성 지정 | 사용자 2026-11-06 |
| API 내보내기 승인 | 새 프로젝트도 `manage.py publish-project`로 승인해야 수집이 읽는다. 지금과 같다 |

## 결정

| 질문 | 고른 안 | 다른 안 |
|---|---|---|
| 등록은 누가 언제 하나 | 관리자가 Admin › 측정 설정 또는 Project › Setting에서 필요할 때 한다. 추정해서 미리 채우지 않는다 | 답변의 추출 표시나 도메인으로 미리 채우기(없는 데이터를 만든다) |
| 등록 전 Project의 자사 · 타겟 URL | 추출 표시 유지. 등록하면 그 프로젝트만 등록값 규칙으로 바뀐다 | 등록 즉시 전 프로젝트에 규칙 적용(0%로 떨어진다) |
| Project도 이 목록에 넣나 | 넣는다. 등록 0/130을 한곳에서 채울 수 있다 | Website · Global만(Project는 프로젝트마다 들어가야 한다) |
| 새 프로젝트는 어디서 만드나 | 이 목록의 '프로젝트 만들기' | Project 목록(`gold_db`를 읽으므로 데이터가 생기기 전에는 보이지 않는다) |
