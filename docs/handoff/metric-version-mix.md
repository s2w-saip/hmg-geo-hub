# Mention·Citation 추이의 metric_version 혼재 — 조사 보고

2026-10-30 · Gold live global release 603 (version 27, rule `2026-10-25.provisional.2`) · 읽기 전용 계정(`geo_readonly`, READ ONLY 트랜잭션)으로 SELECT만 · 코드는 고치지 않았다.

배경: `acr-next-session.html` 2절 '남은 일과 제안' 첫 줄. live release의 cell·fact family에 metric_version 6가지가 섞여 있어, Mention·Citation 추이가 측정 방식이 다른 회차를 가로지를 수 있다. 2026-10-29에 ACR은 측정 방식이 바뀌어도 숨기거나 경고하지 않기로 정했다. 이 문서는 같은 원칙이 Mention·Citation에도 맞는지 판단할 사실 자료다. 조치는 고르지 않는다(7절은 선택지만).

## 2. 방법

- **값:** 회차마다 화면과 같은 조건의 셀을 (질문, 국가, 엔진) 단위로 합쳤다. 비율 지표는 그 합의 분자 ÷ 분모다. 10-05 값이 화면 값(live)과 같다: 노출률 76.6, 점유율 38.72, 우호도 54.12, 우선 노출도 2.353, 인용 점유율 24.98.
- **같은 질문 비중:** 뒤 회차 단위 중 앞 회차에도 있는 단위의 비율.
- **같은 질문 Δ:** 두 회차에 모두 있는 단위만으로 계산한 Δ.
- **잡음 범위(±):** 같은 질문 단위를 다시 뽑아 계산한 Δ의 95% 범위 폭의 절반이다. 단위별 Poisson(1) 가중으로 1,000회, 두 회차를 같은 가중으로 묶는 짝지은 재표집이다. ACR 문서 3절의 클러스터 부트스트랩과 같은 단위다.
- **'버전 안 주간 변동':** 같은 metric_version 안 회차쌍의 같은 질문 Δ다. 25d5 3쌍(07-13 → 08-03)과 fe8b 3쌍(09-07 → 09-28)을 썼다.
- 인용 점유율(`kpi_cell` cit_m05 ÷ cit_total)은 Citation 화면 '공식(HMG) 비중'(`citation_cell` category 1 ÷ 전체)과 14회차 모두 같은 값이라 한 줄로 적는다.

## 6. 결론 (사실만)

**영향이 큰 지표와 구간**

1. **08-31 → 09-07(6dd8 → fe8b)의 노출률·점유율·우호도.** 같은 질문 94%에서 +5.0 · −3.3 · +4.9pp다. fe8b 안 주간 변동 최대치(3.0 · 1.6 · 3.7)를 넘고, ChatGPT 쪽이 더 크다(노출률 +7.2, 우호도 +7.0). 직전 08-31의 같은 버전 안 하락(−10.5)과 이어진다. 같은 경계에서 경쟁사 노출률도 모두 fe8b 안 최대치의 약 2배로 올랐다: Toyota +2.0(대 1.4), BMW +3.0(1.7), Tesla +3.3(1.5), Mercedes-Benz +2.4(1.1).
2. **당사 점유율(SoV).** 같은 질문 94% 이상인 경계 셋 모두에서 버전 안 최대치를 넘는다(−1.2 대 1.0, −3.3 대 1.6, −1.7 대 1.6). 첫째·셋째는 넘는 폭이 0.1 ~ 0.2pp다.
3. **08-10 ~ 08-31 구간 전체.** 같은 질문 16 ~ 38%, 국가 6 → 9 → 8 → 44개, 회차 안 두 버전(08-10 91a3, 08-24 6dd8). 이 구간의 전체 Δ는 구성 변화가 크다. 회차 안에 섞인 cycle 하나가 회차 값을 최대 3.5pp(08-10 우호도·Toyota 노출률) 움직인다.

**참고**

- 9월 규모의 잡음 범위는 ±0.2 ~ 0.5pp다. 같은 버전 안 주간 Δ도 대부분 이보다 크다. 회차마다 바뀌는 무언가(모델 응답, 실제 변화, 버전에 안 잡히는 수집 차이)가 단위 표집 잡음보다 크다는 뜻이다. 어느 쪽인지는 이 자료로 가를 수 없다.
- metric_version의 뜻은 Gold에 적혀 있지 않다. 같은 날 다시 만든 build들이 회차 묶음마다 다른 값을 가진다.

| 상류 문의 | ACR P2 질문 1(b)(c)에 Mention·Citation을 더한다: metric_version의 뜻, 08-31 노출률·유형 하락(같은 버전), 07-27 → 08-03 감정·유형 분류 변경, 08-10 91a3 cycle의 범위와 값, 09-28 인용 수 2배, 08-24 cycle 1318이 Citation에서만 숨겨진 이유 | 버전으로 설명되지 않는 변화가 많아, 회차별 '비교 가능' 표시는 버전과 다른 기준이 필요할 수 있다 |

## 8. 다시 재는 법 (SQL 요지)

화면 리더(`gold_reader/context.py` `Context.predicate`)와 같은 조건이다.

```sql
-- live global release의 cell build
SELECT build_id FROM gold.release_item WHERE release_id = 603 AND family = 'cell' AND state = 'ready';

-- Mention 단위 합 (population 1 = 전체 답변 std_in, 관점 own_bits = 7)
SELECT f.round_date, f.cyc_key, f.prompt_key, f.geo_key, f.engine_key,
       sum(answers), sum(tracked), sum(own_mentions), sum(total_mentions), sum(sent_pos), sum(sent_all),
       sum(rank_sum), sum(ranked), sum(t_comparison), sum(t_recommendation), sum(t_final_choice) /* … */
FROM gold.kpi_cell f
WHERE f.build_id = ANY($cell_builds) AND f.surface = 1 AND (f.bgrp & 15) <> 0
  AND f.population_key = 1 AND f.perspective_key = (SELECT perspective_key FROM gold.dim_perspective WHERE own_bits = 7)
  AND EXISTS (SELECT 1 FROM gold.dim_cycle cy WHERE cy.cyc_key = f.cyc_key AND cy.servable
              AND coalesce(cy.hidden_scope, 0) NOT IN (1, 3)                 -- Citation은 (1, 2)
              AND (cy.view_date IS NULL OR cy.view_date <= current_date))
GROUP BY 1, 2, 3, 4, 5;

-- Citation: 같은 조건에 population 2, sum(cit_m05), sum(cit_total), sum(answers)
-- 카테고리: gold.citation_cell population 2 · 관점 7, sum(citations) FILTER (WHERE category_key = k)
-- 경쟁사: gold.brand_cell population 1 · competitive, brand_key별 sum(mention_count), sum(answers_present)
--         (경쟁사 점유율 분모 = kpi_cell total_mentions, 노출률 분모 = kpi_cell answers)

-- build·버전: gold.release_item ⨝ gold.build(metric_version, started_at) ⨝ gold.dim_cycle(slice_key = 'cyc:' || cyc_key)
```

- 같은 질문 Δ: 두 회차의 (prompt_key, geo_key, engine_key) 교집합에서 합한 분자 ÷ 분모의 차.
- 잡음: 그 교집합 단위에 Poisson(1) 가중 1,000회, 두 회차를 같은 가중으로 묶어 Δ의 2.5 · 97.5 백분위.
- 조사 스크립트와 산출(`pairs.csv`, `within.csv`, `cyc_pairs.csv`)은 세션 임시 폴더에 두었고 저장소에는 넣지 않았다.
