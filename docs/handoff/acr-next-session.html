1. 이번 세션에서 끝낸 것 (2dfb8ef)

일내용
P1 회차 간 비교 막기 처음 결정은 "업스트림 답이 올 때까지 Δ·추이·기간 누적을 모두 막는다"였다. 이후 사용자는 측정 방식이 바뀌어 값이 급변하는 것은 당연하니 무시하라고 했다. 대신 추이 분석(3절)을 보고, 비교할 수 있는 이력이 아직 없어서 숨김을 유지하기로 다시 정했다. 기존 화면에도 같은 결정을 적용했다.
  • BFF: screens/acr.py의 COMPARE_ROUNDS = False 하나로 막는다. 날짜를 박지 않고, 경계를 추정하지 않는다.
    • 뷰는 compareRounds false로, 추이(dates [], 추이 null)와 Δ를 보내지 않는다. 그래서 "변동" 발견과 "격차 벌어짐"도 빠진다.
    • 회차가 둘 이상인 기간은 held {rounds, from, to}를 보내고 뷰를 만들지 않는다. 회차가 하나뿐인 기간은 그 회차를 그대로 보인다.
  • 화면:
    • 페이지 위에 안내 한 줄을 두고, 이유는 ⓘ에 적었다.
    • 히어로의 추이 자리에는 안내 문구를 넣었다.
    • 경쟁 표에서 추이·증감 열과 증감 정렬을 뺐다.
    • 여러 회차 기간이면 안내 카드와 "최신 회차 보기"를 보인다(useRnFilterClear("time")).
  • 기존 화면(acr/standard·acr/gold, live_vm)
    • 추이를 보내지 않고, 차트 자리에 안내 한 줄을 둔다.
    • 여러 회차 기간은 held를 보내고, 안내 카드와 "최신 회차 보기" 링크(time만 지움)를 보인다.
  • 안내 문구는 "회차마다 측정한 국가·질문이 달라 비교할 이력이 아직 없음"이다(renewal.acr.held.*, 두 화면이 같이 씀).
  • 되돌리기: 스위치를 켜면 예전 계산 그대로다. 리뉴얼 41건과 기존 86건 골든이 켠 상태에서 기록과 같음을 확인했다.

4. 다시 재는 법

  • Gold 접속: .env.gold.local의 HGH_GOLD_DB_URL(읽기 전용).
    • 리더를 그대로 부르려면 back/에서 bff.gold_reader.db.open_pool()과 bff.gold_reader.readers.read("funnel/acr", QueryParams("surface=global&…"))를 쓴다.
    • SQL을 직접 쓸 때는 Context.create와 acr.cell_where·CELL_JOINS를 쓰면 화면과 같은 셀 집합이 나온다. 전체 회차는 ctx.selected_dates = sorted(ctx.dates)로 잡는다.
  • 리더를 고칠 때는 "고치기 전 답을 저장 → 고친 뒤 같은 쿼리 묶음과 JSON 비교" 순서로 한다. 쿼리 묶음은 1절의 12개 읽기다. 같은 코드로 두 번 읽어 결정성을 먼저 확인한다.
  • build 메타: gold.build(metric_version, input_snapshot의 silver_run_key, started_at)와 gold.release_item.
  • 답 원문: gold.acr_cell_job(build_id, acr_cell_key → answer_key) → gold.answer_body.answer_text, model_slug.
  • 페이지 측정과 화면 확인: front/node_modules/playwright를 시스템 Chrome(channel: "chrome")으로 띄운다. 로그인 정보는 .local/hub-test-admin.txt를 스크립트 안에서만 읽는다(메모리 browser-e2e-mac). 이번 세션의 스크립트도 세션 스크래치패드에 있어 남지 않는다.
  • API(5555)는 자동으로 다시 읽지 않는다. BFF를 고친 뒤에는 scripts/start-local.sh를 다시 실행한다(API만 재시작). 같은 서버를 다른 세션도 쓴다.
