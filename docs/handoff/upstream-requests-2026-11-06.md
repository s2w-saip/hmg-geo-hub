# 업스트림 요청 (초안, 2026-11-06)

대공사 T2.1 · T2.2의 요청서다. **초안이며 아직 보내지 않았다. 사용자가 보낸다.**

- OBT 컬럼과 의미는 우리가 정하지 않고 파이프라인의 OBT DB를 읽어 확인한다(사용자 2026-11-05). 그래서 파이프라인에는 접근만 요청하고, 분석에는 표에서 알 수 없는 것만 묻는다.
- 아직 정하지 않은 것(`architecture-rebuild.md` D-13)은 담지 않았다.
- 수치는 지금 서비스가 받는 데이터의 Global 2026-10-05 회차이고, 2026-11-06에 확인했다.
- 기존 질문 묶음 `upstream-questions-2026-10-30.md`의 29건은 현행 데이터 이전 · 단절 범위(D-19)가 정해진 뒤 다시 나눈다. T2.3 · 2.4 · 2.5 · 2.6은 이 문서에 없다.

## 1. 파이프라인에 보낼 메시지 (이시형, 김혜민)

```text
[HMG GEO HUB 서비스] Silver OBT 읽기 접근 요청

서비스(BFF)가 지표를 계산하려면 OBT 운영 스냅샷을 읽어야 합니다. OBT 컬럼과 의미는 DB를 직접 읽어 확인하겠습니다. 아래 세 가지를 알려 주세요.

1. OBT가 있는 DB의 접속 위치(호스트 · 포트 · DB · 스키마)와, 지금 운영 스냅샷이 있는 회차
2. BFF용 읽기 전용 계정. 운영 스냅샷(public)만 보이면 됩니다. 비밀번호는 문서나 채널에 적지 말고 따로 전달해 주세요.
3. 운영 스냅샷 포인터와 매니페스트를 읽는 위치

아직 준비 전이라면 볼 수 있는 시점을 알려 주세요.
```

## 2. 분석에 보낼 메시지 (신민철, 박보규)

```text
[HMG GEO HUB 서비스] 추출 항목 확인 6건

BFF가 SSOT 지표 정의(service/metric-definitions.md)대로 계산하려면 추출 결과의 뜻을 알아야 합니다. OBT 컬럼은 DB를 직접 읽어 확인하므로, 표만 봐서는 알 수 없는 것을 여쭙니다. 수치는 지금 서비스가 받는 데이터의 Global 2026-10-05 회차입니다.

1. 언급 순위의 기준 (가장 급합니다)
 - SSOT 용어집의 언급 순위는 '먼저 언급된 경쟁 브랜드 수 + 1'이고 화면 이름은 '경쟁 순위'입니다. 지금 데이터에는 '경쟁 순위'와 '텍스트 첫 등장 순서' 두 값이 따로 있습니다.
 - 경쟁 브랜드 언급 행 208,464건에서 문구와 맞는 것은 텍스트 첫 등장 순서입니다(전부 일치). 경쟁 순위가 이 순서와 같은 행은 115,696건(55.5%)이고, 언급 횟수 순서와 같은 행은 52,551건(25.2%)입니다. 4,262개 답변에 동순위가 있습니다.
 - 물을 것: (a) 경쟁 순위는 무엇을 기준으로 매기나요? 동순위 규칙은요? (b) OBT의 언급 순위는 둘 중 어느 쪽인가요?

2. 첫 언급 위치의 회차 범위
 - 텍스트 첫 등장 순서는 Global 2026-09-07, Website 2026-09-11 이전 회차에 값이 없고, 경쟁 순위는 전 회차에 있습니다. 서비스는 AI 우선 노출도 · Top 3를 SSOT 문구대로 텍스트 첫 등장 순서로 세기로 해서, 추이 14회차 중 9회차가 비게 됩니다.
 - 물을 것: 이전 회차를 다시 추출해 채울 계획이 있나요?

3. 집계 자격 규칙
 - SSOT의 모니터링 답변은 '집계 자격이 있고 분석이 빠지지 않은 답변'입니다. 자격이 없는 답변은 47,135건 중 1,610건이고, 그중 1,598건은 인도네시아(ID) 답변 전량입니다. 나머지는 AE 10건, KR 2건입니다.
 - 물을 것: (a) 자격은 어느 팀이 어떤 규칙으로 정하나요? (b) ID 전량 제외는 의도한 것인가요?

4. 비경쟁 · 노이즈 브랜드 구분
 - SSOT의 AI 우선 노출도는 비경쟁 · 노이즈 브랜드를 뺍니다.
 - 물을 것: (a) 이 구분을 OBT에서 어떻게 알 수 있나요? (b) 기준정보 entity_role의 '제외'와 같은 것인가요, 명단이 따로 있나요?

5. ACR 반복의 단위
 - 셀 3,761개의 유효 반복 합은 35,927회인데, 반복별 결과는 3,763행(10.5%)만 있습니다. SSOT 맞대결의 분모는 '함께 후보에 오른 반복'이라 반복마다 후보 목록이 필요합니다.
 - SSOT는 '셀마다 최신 반복 1회'를 모니터링 답변에 넣는데, 같은 회차에 같은 셀의 답변이 2건 이상 들어온 셀이 203개 있습니다(같은 cycle의 다른 run).
 - 203셀의 답변은 모두 최신 반복으로 표시되어 있습니다. 서비스는 셀당 대표 답변 1건만 넣으려 합니다.
 - 물을 것: (a) 유효 반복은 독립된 답변들인가요, 한 답변을 여러 번 판정한 것인가요? (b) 반복마다의 후보군 · 최종 선택 · 차종을 OBT에서 볼 수 있나요? (c) 같은 셀을 다시 측정하는 이유는 무엇이고, 203셀처럼 run이 여러 개인 것이 정상인가요? (d) 셀당 1건을 고를 때 대표 답변을 쓰는 것이 맞나요?

6. 추출에 쓴 입력 버전
 - 서비스는 입력이 운영 스냅샷에 반영됐는지 비교해 화면에 '반영됨 / 반영 대기'로 보입니다(SSOT shared/input-contract.md). 입력의 변경은 change_seq로 알립니다.
 - 물을 것: OBT 행이나 매니페스트에서 어떤 입력 버전으로 추출했는지 볼 수 있나요? 프로젝트 · 기준정보 종류마다 다르면 그 단위도 알려 주세요.
```
