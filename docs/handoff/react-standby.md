# React 전환 준비

2026-11-06 사용자 요청에 따라 Next 대체용 `front-react/`를 별도 프로젝트로 준비했다. 서버 안정화와 병행하는 사전 준비이며, 운영 프런트 교체는 아니다. 현재 Next `front/`와 백엔드 구현·DB·VM은 변경하지 않았다.

React 전환 구조의 기준은 [React 버전 아키텍처](../architecture/service-architecture-react.html)다. 사용자가 제공한 `service-architecture-gold-node.html`과 저장소의 최신 [허브 서버 분리안](../architecture/hmg-geo-hub-architecture.html)을 바탕으로 React(브라우저) → Hub → 내부 데이터 서버의 논리 구조를 그렸다. 호스팅·프록시 배치는 인프라 단계에서 정한다. 검증에서 확인한 7건은 1차 구현으로 보완했고, 문서의 검증 표에 확인 범위와 남은 실서버 검증을 적었다. 이 문서는 실행·연결 설정의 기준으로 유지한다.

## 준비한 범위

| 항목 | 상태 |
|---|---|
| 독립 실행 | React 19 · Vite · React Router · TanStack Query · use-intl, 전용 포트 3334. `front/node_modules` 없이 `npm ci`·빌드 가능 |
| 경로 | 기존 리뉴얼 `page.tsx` 37개에 대응: 명시 경로 35개와 미구현 안내 경로 2개. `src/app/source-routes.json`이 원본 대응표 |
| 기본 화면 | 공통 대기 화면 대신 기존 리뉴얼 컴포넌트를 미연결 상태에서도 표시. 사이드바·메뉴 트리·흰 패널·KPI·분석 탭·프롬프트·관리 목록·Project 측정 설정 폼을 확인. 목록은 비어 있고 측정값은 null 또는 로딩 자리이며 계정·프로젝트 기록은 생성하지 않음 |
| 이식한 UI | 리뉴얼 공용 UI·표·차트·편집 폼과 그 브라우저 의존 소스. `src/legacy/`는 수정 가능한 독립 사본이며 원본을 실행 시 import하지 않음 |
| 서버 의존 제거 | Next navigation/link → React Router 연결, next-intl → use-intl, 비동기 Project 설정 → React 훅, 지도 → React.lazy. 타입만 필요한 서버 모듈은 구현 없이 `.d.ts`로 분리 |
| 화면 연결 준비 | Global·Website·Project 분석/프롬프트/설정, Admin 계정·프롬프트·출처·고객 관심·엔티티·GA4 등록부의 브라우저 로더. UI의 기존 읽기·편집 경로는 허브 서버가 인수해야 함 |
| 인증 | HttpOnly 쿠키 기반 HUB 세션 계약, 미로그인·역할·초기 비밀번호 변경 분기. 서버 검증이 권한의 정본이며 프런트 체크는 화면 접근 안내 |
| 캐시·오류 | 계정 ID·역할·범위별 조회 키, 필터 변경 시 취소 신호, 쓰기 자동 재시도 없음. 최초 로딩과 재조회를 구분해 편집 폼 유지. 필수 조회의 503은 오류 화면으로, 저장 필터·기준 주·헤더 메타 오류는 본문과 분리 |
| 섹션별 읽기 | Global Overview의 추이·브랜드 비교·시장, Global 언급 분석의 카드 묶음은 독립 로딩·오류 표시. 실패한 읽기만 재조회하며 401·403은 페이지 접근 차단. query 캐시의 실패 상태를 빈 성공으로 바꾸지 않음 |
| Project 측정 설정 | 초안과 편집 시작 버전을 함께 보관. 미편집 상태만 새 서버 응답을 자동 반영하고, 편집 중에는 원래 `expectedVersion`으로 저장. 충돌·실패 시 초안 보존, 최신 설정을 명시적으로 다시 읽고 저장 가능 |
| 기준 주·헤더 | Global·Website 프롬프트의 기준 주 변경 시 현재 검색 조건으로 목록 재조회. 분석 공통 헤더에 서버가 답한 유효 기간·측정일과 별도 기준 주 칩, 설명·베타·링크 복사 표시 |
| URL 상태 | 탭·검색의 브라우저 내 URL 변경은 React Router의 history 상태를 보존하고 화면 전체를 재조회하지 않음 |
| 지연 항목 | 외부 계정·데이터 대기 화면은 기존 프레임·계정 안내 막을 사용하고 그 아래 차트 자리를 표시. GA4 데이터 연결 인터페이스와 샘플 지표는 만들지 않음 |

원본의 전체 기능·숫자·부분 오류 처리를 검증한 전환 완료본은 아니다. 연결 전에도 이식한 차트·표·폼을 사용하지만, 값과 목록이 비어 있어 배치와 상호작용을 확인하는 용도다. 채워진 차트·표와 저장 결과의 동등성은 서버 연결 뒤 대조한다.

2026-11-06 사용자 'react app 구현 시작하자'에 따라 1차 구현을 진행했다. 공통 로더의 응답 값으로 폼 전체를 다시 마운트하던 키를 요청·계정 기준으로 바꾸고, 계정 등 목록에는 새 서버 응답을 반영하면서 편집 상태를 유지한다. 저장 필터는 기존 클라이언트 훅이 독립 조회·재시도한다. 잘못된 로그인 복귀 URL은 기본 경로로 처리하고, 원본 변경 검사는 신규 리뉴얼 페이지도 탐색한다. 경로 시험은 예상 제목·화면 유형과 명시적 미등록 경로를 구분한다. 기본값은 계속 미연결이며 실제 Hub 연결은 서버 안정화 뒤다.

같은 날 사용자 '2차 구현 시작'으로 Global Overview·언급 분석의 섹션별 읽기와 Project 측정 설정 저장을 보완했다. `ReadSection`이 섹션의 조회 상태를 확인한 뒤 이식 UI를 렌더링한다. 화면 전체를 기다리게 하거나 `undefined`를 응답으로 소비하지 않으며, 다른 섹션이 도착해도 이미 소비한 Promise를 유지한다. 측정 설정은 편집 시작 시점의 원본과 버전을 유지하고, 저장 성공 응답을 받은 뒤에만 초안을 새 기준으로 바꾼다. 새로 불러오기나 저장이 실패해도 현재 입력을 지우지 않는다. 저장 중 세션이 만료되면 중앙 HTTP 클라이언트가 로그인으로 복귀시킨다.

사용자 'UI까지 기존과 같도록' 요청으로 미연결 표시를 기존 UI에 맞췄다. 기존 `RnSidebar`·`RnNavMain`·운영 안내를 옮기고 원본 메뉴 정의를 사용한다. 사이드바는 232px, 흰 패널은 위·오른쪽·아래 10px, 필터는 296px이며 본문과 따로 스크롤한다. 기존 페이지 로더는 미연결일 때 빈 표시 모델을 사용하고, 조회되지 않은 분석은 같은 컴포넌트의 로딩 자리를 사용한다. 이 표시 범위는 인증 세션이 아니며 서버에 전달하지 않는다. 설정 폼은 읽기 전용이다. 이식 UI의 직접 `fetch`도 `browserFetch`를 통해 미연결 상태에서 네트워크 읽기·쓰기를 하지 않는다. 연결 모드의 권한·오류·저장 동작은 기존 계약을 유지한다. 외부 계정 대기 페이지의 차트 자리는 실제 측정 화면과 별도로 남아 있다.

Project 사이드바는 기존 `projects/list` 응답을 받아 프로젝트 정보와 전환 목록을 표시한다. 화면을 이동해도 같은 메뉴로 프로젝트를 바꾸며, 권한이 없는 경로는 이 명부도 요청하지 않는다. 카드의 공유 상태는 언마운트할 때 지워 세션 사이에 남기지 않는다. 비밀번호 아이콘은 React의 `/change-password`로 연결하고, 로그아웃 실패는 세션을 유지한 채 안내한다.

## 실행

Node.js 22.12 이상(검증 환경 24.22), 저장소에서:

```sh
cd front-react
npm ci
npm run dev
```

`http://127.0.0.1:3334/ko/renewal/dashboard`에서 확인한다. 기본값은 미연결이며 API를 호출하지 않는다. `/en/renewal/...`도 유지한다. 프로젝트 상세의 `/projects/preview`는 미연결 상태의 화면 탐색 주소이며 프로젝트 데이터가 아니다. 연결 모드에서는 실제 UUID 경로만 허용한다.

## 현재 개발 환경의 데이터 연결

2026-11-06 사용자 '데이터 공급까지 해볼까' 요청으로 기존 API를 연결했다. 화면 API는 이미 `back/data_server`의 `/v1/screens/*`에 있다. 브라우저에 없던 두 경로만 기존 Next에 추가했다.

- `GET /api/hub/session`: 기존 HttpOnly 쿠키로 실제 계정을 재확인해 `{user}`만 반환한다. 토큰은 응답에 넣지 않는다.
- `GET /api/screens/{name}`: React가 사용하는 화면만 허용하고 메뉴 권한을 확인한다. `ctx.role`·`ctx.admin`은 로그인한 계정에서 정하며, 반복 필터는 보존한다. 완성된 뷰모델은 기존 데이터 서버가 계산한다.

현재 맥의 연결은 **React :3334 → Vite의 같은 origin `/api/*` 프록시 → 기존 Next :3333 → 허브 서버 :5556 → 데이터 서버 :5555**다(2026-11-07, T13 1c 프록시). Next의 기존 로그인·입력·드릴다운·다운로드 API를 재사용한다. T13의 독립 허브 서버가 구현됐다는 뜻은 아니며, 그 서버가 준비되면 프록시 대상만 바꿔 같은 브라우저 계약을 검증한다. 새 경로는 기존 로컬 모드에서만 열리고, 운영 전환·배포는 하지 않는다.

`front-react/.env.local`(git 제외):

```dotenv
VITE_HUB_CONNECTED=true
HUB_PROXY_TARGET=http://127.0.0.1:3333
```

개발 서버를 다시 시작하고 `http://127.0.0.1:3334/ko/login`에서 기존 HUB 계정으로 로그인한다. 쿠키는 호스트를 따르므로 Next에서 쓰던 것과 같은 `127.0.0.1` 또는 `localhost`를 사용한다. 로그인 정보는 브라우저에 입력하며 코드·설정에 넣지 않는다. 미연결 화면으로 돌아가려면 `VITE_HUB_CONNECTED=false`로 바꾸고 다시 시작한다. 저장소의 기본 예시는 계속 미연결이다.

검증: Next 신규 계약 12건과 기존 Hub 라우트 23건(총 35건), Next 타입 검사, React 타입 검사·빌드, 실제 프록시의 미로그인 리다이렉트와 세션 200·화면 401을 확인했다. 데이터 서버 `/healthz`도 정상이다. 사용자가 기존 계정으로 로그인한 뒤 실제 세션·Global 프롬프트·Overview의 필터·카드·추이·브랜드 비교·시장 조회에서 200 응답을 확인했다. 기준 주는 2026-10-05~10-11이다.

| 실제 조회 조건 | 노출률 | 점유율 | 우호도 | 우선 노출도 | 인용 점유율 |
|---|---:|---:|---:|---:|---:|
| 필터 없음 | 76.6% | 38.9% | 53.9% | 2.2 | 25.0% |
| Kia · KR | 82.9% | 32.6% | 57.4% | 2.3 | 29.5% |

이는 연결 확인 시 받은 기존 서버 응답값이다. 지표 계산이나 정의를 바꾸지 않았으며, 원본 컬럼·집계 단위 대조와 모든 화면의 동작 검증은 별도 범위다. 테스트 응답을 실행 중인 앱에 공급하지 않는다.

같은 날 필터 변경 시 페이지 전체가 로딩 화면으로 교체되는 문제를 재현하고 수정했다. URL의 검색 조건이 바뀌어도 페이지 경계와 필터 프레임을 유지한다. 새 조건의 필수 조회가 완료될 때까지 마지막 완성된 응답 묶음을 표시하고 카드의 진행선으로 갱신 중임을 알린다. 새 묶음을 반영한 뒤 지연 섹션은 각자의 상태를 표시한다. 계정·역할·범위·읽는 화면 종류가 달라지면 이전 묶음을 유지하지 않으며, 오류는 기존 오류 처리로 전달한다. 기존 목록 컴포넌트의 초기 응답 키는 유지해 새 조건의 목록 반영도 보존한다.

## 서버 안정화 후 허브로 전환

1. 허브 서버가 아래의 브라우저 계약을 제공하는지 확인한다. 현재 개발용 Next 중계를 대체하는 단계다. `back/data_server`는 Bearer 인증을 받으므로 여기에 주소만 지정해서는 연결되지 않는다. T13의 내부 토큰·DB 권한 분리는 별도 작업이다.
2. `front-react/.env.example`을 `.env.local`로 복사하고 `HUB_PROXY_TARGET`을 **허브 서버** 주소로 지정한다. 데이터 서버 주소를 지정하지 않는다.
3. `VITE_HUB_CONNECTED=true`로 바꾸고 개발 서버를 다시 시작한다. 정적 빌드는 이 값을 빌드할 때 반영한다.
4. 먼저 로그인·로그아웃·비밀번호 변경과 Admin 계정 읽기/편집, Global Mention을 실서버로 확인한다. 테스트 응답을 가로채는 e2e와 구분한다.
5. 아래 남은 검증을 끝낸 뒤에만 실제 프런트 전환을 검토한다. VM 반영과 기존 Next 종료는 사용자 지시 뒤에 한다.

### 허브가 제공할 브라우저 계약

| 경로 | 동작·응답 |
|---|---|
| `GET /api/hub/session` | `{user: ...}` 또는 401. 사용자 = `id, login, email, displayName, role, scope, mustChangePassword`. 로그인 토큰을 응답 JSON에 주지 않음 |
| `POST /api/hub/session` | `{login,password}` → `{user}` + HttpOnly 쿠키. Origin 확인 |
| `DELETE /api/hub/session` | 쿠키를 지운 뒤 204. 실패하면 프런트도 로그아웃 성공으로 처리하지 않음 |
| `POST /api/hub/password` | `{current,new}` → `{user}` + 갱신 쿠키. Origin 확인 |
| `GET /api/screens/{name}` | 기존 `/v1/screens/{name}`의 화면 응답을 허브를 통해 전달. 반복 쿼리 키와 `ctx.*` 유지 |
| 기존 `/api/hub/*` | 계정·입력 편집·저장 필터. 기존 응답 봉투 `{data,meta}`, 충돌 상태와 `expectedVersion` 유지 |
| 기존 읽기·다운로드 `/api/*` | 현재 Next가 맡는 지연 조회와 CSV/XLSX 다운로드 경로를 허브가 인수. 콘텐츠 형식·파일 헤더 유지 |

나머지 `/api/*` 경로는 이식한 클라이언트에 남아 있다. 확인 명령은 `rg -n '/api/' front-react/src/legacy`다. 초기 화면별 조립은 `src/pages/analytics.tsx`·`catalog.tsx`·`projects.tsx`·`admin.tsx`, 공통 HTTP는 `src/api/client.ts`다. 응답 스키마가 달라지면 해당 로더에서 맞추고 UI·지표 정의는 분리해 둔다.

브라우저 → 같은 origin의 `/api/*` → 허브 → 내부 데이터 서버 순서다. 세션 쿠키 발급/삭제·쓰기 Origin 확인·매 요청 계정 재확인·내부 토큰은 허브 책임이다. 프런트는 토큰을 저장하지 않는다. 개발 프록시는 Host/Origin을 바꾸지 않는다.

정적 배포도 `/api/*`를 허브로 보내고, 나머지 화면 경로만 `index.html`로 돌려야 한다. API 오류를 HTML 200으로 바꾸면 안 된다. `HUB_PROXY_TARGET`은 Vite 개발 서버 설정이며 프로덕션 프록시를 설정하지 않는다. 이 작업에서는 배포하지 않았다.

## 원본 변경 추적

`source-manifest.json`에는 이식 시점의 원본 UI·타입·페이지·번역·스타일·정적 자산 해시가 있다. 서버 안정화 동안 Next를 바꾸면 다음 명령으로 차이를 확인한다.

```sh
cd front-react
npm run check:source
```

추적 중인 파일의 변경·삭제와 신규 리뉴얼 `page.tsx`·`page.jsx` 등을 확인한다. 차이가 있으면 자동 덮어쓰기하지 않고 React 사본과 로더에 필요한 변경을 반영한다. 신규 페이지 탐색은 리뉴얼 경로 트리를 대상으로 하며 저장소 전체 신규 파일을 검증하는 것은 아니다. `src/legacy/`의 `(dash)` 이름은 재사용 컴포넌트의 출처를 유지한 것이며 레거시 전체 화면을 이식했다는 뜻이 아니다. 최초 가져오기 스크립트는 기존 사본 위 실행을 거부한다. 일반 실행·빌드는 원본 Next를 필요로 하지 않는다.
