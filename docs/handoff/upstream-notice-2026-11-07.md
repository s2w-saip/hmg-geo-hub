# 업스트림 통보 초안 (2026-11-07)

대공사 T2.1 · T2.2 · T2.3 · T2.5와 T2.4 중 기준정보 9종의 통보문이다. 서비스가 정한 것을 알리고 답을 기다리지 않는다. **초안이다. 보내는 것은 사용자가 정한다.**

보내기 전에 확인할 것:

| 확인 | 지금 |
|---|---|
| 지표 정의 버전 | `2026-11-07.3`. 바뀌었으면 아래 수치를 다시 뽑는다 |
| 수치의 출처 | 맥의 가상 OBT 기준, Global 2026-10-05 · Website 2026-10-09 · Project 2026-10-06 회차 |
| SSOT 링크 | 통보문의 `service/metric-definitions.md` · `prompt-reference-api.md`는 SSOT 본이 낡았다. 최신본은 `docs/ssot-staging/`에 있고 SSOT 업로드 전이다 |
| API 키 | 발급 전이다(T8.3). 통보를 보낼 때 함께 발급한다 |

이번에 서비스가 새로 정한 것은 분석 · 앤써 통보의 '읽는 시점'이다(결정 기록 2026-11-07). 담지 않은 것: 키워드 · 소셜 · GA4의 자리(T2.4의 나머지), 사용자 보유 계정(T2.6).

## 1. 파이프라인 (이시형, 김혜민)

```text
[HMG GEO HUB 서비스] Silver OBT를 읽는 방식 안내

서비스 데이터 서버(SSOT의 BFF)는 Silver OBT를 아래처럼 읽습니다. 이 안내에 회신은 필요 없습니다.

1. 읽기 전용 계정 하나로 운영 스냅샷(public)만 읽습니다. loading · ready · retired 스냅샷은 읽지 않고, Silver에 쓰지 않습니다.
2. 컬럼과 의미는 서비스가 DB를 직접 읽어 확인합니다. 서비스가 OBT 컬럼을 정하거나 요청하지 않습니다.
3. 데이터 서버의 적재 잡이 매니페스트에서 새 운영 스냅샷을 찾아 서비스 DB의 조회용 테이블로 가공하고, 그 뒤 사전 집계와 캐시를 갱신합니다. 재분석 결과도 운영 반영된 뒤에만 화면에 나옵니다.
4. 회차의 스냅샷이 loading · ready인 동안은 그 회차를 완료로 보지 않고, 서비스 기준 주도 넘어가지 않습니다.

받아야 하는 것은 접속 정보뿐입니다: 호스트, 포트, DB, 스키마, 운영 스냅샷과 매니페스트 위치, 읽기 계정. 전달처는 서비스 담당 김태호이고, 비밀번호는 문서나 채널에 적지 말아 주세요. 받으면 연결을 바꾸고 값을 대조합니다.

참고로 지금 서비스가 쓰는 값 중 답변 원문(answer_text)은 OBT에서 읽습니다. 아래 값은 지금 쓰는 데이터 구조에 값이 없어 있는 행만 유지합니다. 실제 Silver에도 없으면 새 회차부터 해당 화면이 비거나 줄어들고, 서비스는 추정해 채우지 않습니다.
- ACR 반복별 승자 · 후보: ACR 맞대결
- 제품 표시 이름: ACR 모델 표, 답변 상세
- 출처의 자사 브랜드 · 경쟁사 매핑: 경쟁사 공식 출처 인용 점유율
```

## 2. 분석 (신민철, 박보규)

```text
[HMG GEO HUB 서비스] 지표 계산 기준 안내 (지표 정의 버전 2026-11-07.3)

서비스가 정한 계산 기준입니다. 추출 결과는 고치지 않고 아래 기준으로 세기만 합니다. 정의는 SSOT service/metric-definitions.md에 있고, 리뷰 의견은 언제든 받되 적용은 기다리지 않습니다. 수치는 Global 2026-10-05 회차입니다.

1. 언급 순위
- AI 우선 노출도와 Top 3 · 1위 비율의 순위는 '먼저 언급된 경쟁 브랜드 수 + 1'이고, 텍스트 첫 등장 순서로 셉니다.
- 경쟁 순위 값은 지표에 쓰지 않습니다. 두 값이 있는 행 206,620건 중 114,920건(55.6%)만 텍스트 순서와 같고, 4,226개 답변에 동순위가 있습니다.

2. 첫 언급 위치가 없는 회차
- Global 2026-09-07, Website 2026-09-11 이전 회차에는 값이 없습니다. 그 회차의 우선 노출도 · Top 3 · 1위 비율은 빈칸이고 다른 값으로 채우지 않습니다(추이 14회차 중 9회차).
- 추출 결과에 값이 들어오면 운영 반영 뒤 화면에 나옵니다.

3. 집계 자격은 서비스가 판정합니다
- 완료된 답변이고, Global은 표준 카탈로그 프롬프트 · 숨기지 않은 시장 · 프롬프트의 대상 지역인 답변입니다. 47,135건 중 1,610건이 빠집니다. 1,598건은 인도네시아(ID) 시장 숨김, 12건은 카탈로그 밖입니다.

4. ACR
- 셀 = 프롬프트 × 엔진 × 국가이고, 셀마다 대표 답변 1건만 모니터링 답변에 넣습니다. 같은 회차에 답변이 2건 이상인 조합이 3,710개 중 226개 있습니다.
- 대표 답변 = 회차(cycle) · 프롬프트 · 엔진 · 국가 · 언어마다 측정 시각이 가장 늦은 1건입니다. 그 결과 모니터링 답변은 44,759건, 대표 답변은 44,740건입니다.
- 같은 회차 날짜에 cycle이 둘 이상이면 cycle마다 1건입니다. SSOT 문구 '회차마다 1건'보다 많고, 해당 회차는 Global 07-13 · 08-10 · 08-17 · 08-24입니다. 회차 날짜로 묶으면 노출률이 76.70 · 78.86 · 76.54 · 74.91로 달라집니다(지금 75.98 · 80.38 · 76.96 · 75.36). 2026-10-05는 차이가 없습니다.
- ACR 화면은 셀 3,573개, 유효 반복 34,462회입니다. 맞대결은 반복별 결과가 있는 3,575회(10.4%)만 세고, 없는 반복은 추정하지 않습니다.

5. 브랜드 이름
- 답변 행의 brand가 아니라 brand_rollup_entity_id가 가리키는 롤업 자기 행의 이름으로 셉니다. 이 값은 회차 전체에서 찾습니다.
- 행의 brand와 롤업 이름이 갈리는 행이 있습니다. 서비스는 고치지 않고 롤업 기준으로 셉니다. 추출 쪽에서 볼 값으로 알려 드립니다.

   표면 · 회차               갈리는 행 / 전체       많은 조합 (brand → 롤업 이름, 행 수)
   Global 2026-10-05        1,233 / 662,561     Volkswagen → Škoda 230, Mercedes-AMG → Mercedes-Benz 98, BMW → Mazda 79, Alpine → Renault 68, Mahindra → Honda 52
   Website 2026-10-09       128 / 195,545       Kia → Genesis 24, Mercedes-AMG → Mercedes-Benz 24, Gran Turismo → Genesis 17
   Project 2026-10-06       112 / 52,786        Mitsubishi → Škoda 53, Citroën → Nissan 12

6. Website 시장
- Website는 사이트의 국가를 시장으로 씁니다. 사우디는 도시 3개 구분이 계약에 없어 사이트 국가 하나로 합칩니다.

7. 자사 · 타겟 URL
- 자사 URL은 측정 설정에 등록한 소유 URL과 대표 주소의 오리진에 속한 모든 URL입니다. 하위 도메인은 따로 등록해야 합니다. 등록하지 않은 Project는 추출 표시를 씁니다.
- 타겟 URL은 Website는 프롬프트에 지정한 URL, Project는 등록한 추적 URL과 그 하위입니다. 등록하지 않은 Project와 Global은 추출 표시를 씁니다.

기준정보 읽기는 아래 '프롬프트·기준정보 API 안내'를 봐 주세요.
```

## 3. 앤써 (수집 · 답변 원문)

```text
[HMG GEO HUB 서비스] 답변 원문을 읽는 방식 안내

서비스는 답변 원문을 Silver OBT의 answer_text로 읽어 답변 상세 화면에 보여 줍니다. 지표 계산에는 쓰지 않습니다. 지금 Bronze는 읽지 않고, 나중에 직접 읽을 계획은 있습니다. 답변 데이터는 Silver OBT 하나로만 받으므로 수집 쪽이 서비스에 따로 넘길 것은 없습니다.

실제 Silver에 answer_text가 없으면 새 회차부터 답변 상세의 본문이 비어 보입니다. 그때 Bronze를 읽는 경로를 서비스가 정해 알려 드립니다.

프롬프트와 측정 설정은 아래 '프롬프트·기준정보 API 안내'로 읽어 주세요.
```

## 4. 앤써 · 분석 공통: 프롬프트·기준정보 API

```text
[HMG GEO HUB 서비스] 프롬프트·기준정보 API 안내

프롬프트, 측정 설정, 수집 · 분석 기준정보의 원본은 서비스가 관리하고, 이 API로 읽습니다. 주소와 명세는 SSOT shared/urls.md, service/prompt-reference-api.md에 있습니다. 내부망(10.x)에서 GET만 되고, 키는 호출자마다 하나를 전달합니다.

누가 무엇을 읽는지
- 수집(앤써): 프롬프트, 측정 설정, 수집 기준정보(engine, country, language, interest_keyword, interest_source)
- 분석: 분석 기준정보(taxon, brand, source_override, source_seed, source_social, source_code, entity_role, surface, brand_bit, mention_type)

읽는 시점
- 키를 받은 때부터 읽을 수 있습니다.
- 수집은 회차를 시작하기 전에, 분석은 추출을 시작하기 전에 읽어 주세요. 그 사이 주기는 각 파트가 정합니다.
- 바뀐 것만 읽으면 됩니다: 프로젝트는 change_seq(after_seq로 이어 읽기), 기준정보는 etag로 확인합니다. meta.contract_version이 바뀌면 전부 다시 읽습니다.
- 서비스는 입력이 어느 스냅샷에 반영됐는지 확인하거나 화면에 표시하지 않습니다.

나가는 기준정보는 SSOT input-contract.md의 15종뿐입니다
- 아래 9종은 서비스 저장소에만 있고 API로 나가지 않습니다: region, entity, source_category, source, owned_base, crawl_bot, keyword, perspective, population.
- 쓰는 곳이 생기면 SSOT 계약에 올라간 뒤 내보냅니다.
```
